### The article's outline

  PART 1: Distributed Representations: Composition & Superposition
    Distributed representations combine two distinct notions, composition and superposition, which trade off in generalization and linear computability, illustrated via Thorpe's shape-color codes.
  PART 2: "Local" Codes
    A pure local code assigns one neuron per (shape, color) pair, giving flexible linear selectivity for arbitrary stimulus sets despite seeming wasteful and lacking any true single-feature meaning.
  PART 3: "Semi-Local" / Compositional Codes
    Compositional codes represent independent features like color and shape that combine to encode objects, yielding fewer neurons, non-local generalization, and extensibility, while remaining interpretable component-wise.
  PART 4: "Dense" / Maximal Superposition Codes
    Dense superposition codes represent exponentially many unrelated objects with few neurons, at the cost of losing linear probeability and requiring non-composing features rather than independent ones.
  PART 5: Composition vs Superposition
    Composition and superposition are not points on one distributedness spectrum but orthogonal strategies competing for the same limited exponential representational volume.
  PART 6: Mixing Composition and Superposition
    Sparse, limited composition leaves unused regions of representational space, allowing composition and superposition to coexist within a single code as Thorpe's semi-distributed example shows.
  PART 7: Conclusion
    Because composition and superposition have different properties yet get conflated as one idea, distinguishing them is essential for mechanistically understanding neural network representations.

  8. In Thorpe's 'semi-distributed' code, individual neurons respond to several features at once. What perspective does the author suggest is more natural for understanding this kind of code?

     — Because, as the author argues, maximal superposition is only possible when there is no composition; packing exponentially many items into few neurons requires giving up on features that freely compose, so the code has to use a non-composing set of features instead.  [spya-kq5p9m]
  10. Using the idea of a fixed 'volume' of representational space, why do composition and superposition fundamentally compete rather than combine freely?
     — With m bits of representational volume you get exp(m) possible states; storing n fully composable features that combine arbitrarily already uses up exp(n) of that volume, so composable features can only be stored within the limited exp(m) space. Superposition instead spends that same volume storing exp(m) unrelated items directly, at the cost of needing a non-linearity to retrieve them, so the two strategies are competing for the same limited volume.   11. How can composition and superposition coexist in the same representation, according to the article?
     — If composition is limited, meaning many feature combinations are rare or never occur, this leaves unused 'holes' or low-probability regions in the space of possible combinations, and those empty regions can be used to store other features in superposition.  [spya-ajbh7f]
