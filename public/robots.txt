# Spideryarn's own pages may be listed by a search engine. Nothing a reader
# put here may: no article, shelf, profile, admin page or API path.
#
# Greg, 2026-10-05, on our own pages: "yes definitely we want those to be
# visible". On a shared article ever being listed: "no".
#
# The list of our own pages is src/site-pages.ts, and tests/site-pages.test.ts
# holds this file to it, line by line. scripts/check-public-shell.ts fails a
# deploy that serves anything else.
#
# Why this file exists at all: Vercel puts `x-robots-tag: noindex` on the
# generated *.vercel.app addresses automatically and does NOT put it on a custom
# domain. See docs/project/deployment.md.
#
# Two different things keep a page out of search, and they do not reinforce
# each other:
#
#   Disallow, here        stops a crawler FETCHING a page. It does not stop the
#                         address being LISTED: a search engine lists a linked
#                         address it may not fetch, as a bare URL.
#   noindex, on the page  stops it being listed. It is the `X-Robots-Tag` header
#                         (vercel.json, on every path that is not one of our own
#                         pages) and the matching <meta name="robots">. A
#                         crawler has to be let in to read it.
#
# That is why `/read/` is allowed below. Our own pages link to shared articles,
# so a crawler finds those addresses; it is let in so that it reads the noindex
# on every one. What it is sent there is a title, a one-sentence description
# and a link to the original. The article's text comes from /api/public/, which
# stays shut. Taking the `Allow: /read/` line out again is the way back, and it
# trades this for the bare listing.
#
# `/read/` covers the list of shared articles at /read/public too. It carries
# the same noindex. `/login` is let in for the same reason: every one of our
# pages links to it, and it carries the noindex. So is `/help/`: /help is the
# contents of Help and links to every page under it, and each of those carries
# the noindex too. (`/help/` does not match /help itself, which is one of our
# own pages and has its two lines.) Nothing a crawler can reach links to
# /profile, the admin pages or the API, and those stay shut.
#
# Each of our own pages has two lines. `$` ends the match, so `/pricing$` is
# that page and nothing under it; `/pricing?` is the same page with a query
# string on it, which is how a link from a newsletter arrives. `/assets/` is
# the script and the stylesheet, which a crawler needs to draw a page at all,
# and the five files after it are our own icons and card picture, which a
# search result shows beside a page.

# The link-preview fetchers, which draw the card when a link is pasted.
#
# Pasting a link into a chat should show a title, a description and a picture.
# The services that draw those cards fetch the page like any other crawler.
# Slack unfurls anyway (its fetchers ignore robots.txt:
# https://api.slack.com/robots); Meta's obeys this file.
#
# A bot obeys exactly one group, the most specific one naming it, and inherits
# nothing from the `*` group above. So this group repeats what it needs and
# carries its own Disallow. It is let in to:
#   our own pages           the same lines as above
#   /read/                  a shared article's page, for its title and description
#   /og-card.png            our picture, on any card that has no other
#   /api/public/asset/      a shared article's own first picture, from the copy
#                           we host, when its card shows one. The route answers
#                           only for an article that is shared at that moment.
#
# The list of names is also `PREVIEW_BOTS` in scripts/check-public-shell.ts, and
# the platforms are named to authors on /features/public-readable-sharing.
#
# **This is not permission to index.** These fetch a page to draw a card, and
# none puts it in a search result.
