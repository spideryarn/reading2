## Why there is a file for it at all

**So the directory accounts for every report there has ever been.** Sixteen feedback issues exist and
fifteen had notes; the next run of the loop would have had to work out which one was missing and
whether it mattered. One file is cheaper than that question being asked again.

## The wrinkle it exposes

`ignored` now carries two meanings.
[feedback-reports.md § Three ways a report ends](../project/feedback-reports.md#three-ways-a-report-ends)
assigns it to **Awaiting Greg** — written up, not built, and listed in
[`awaiting-approval.md`](awaiting-approval.md) because `ignored` is otherwise invisible. This issue
is `ignored` in the older, plainer sense: noise. It predates the process, so nothing is wrong, but a
future reader finding an `ignored` issue that is not on `awaiting-approval.md` should know that the
file, not the status, is the register — and that this one is the only exception.
