# The Add page, and its sharing part, made clearer

SPIDERYARN-READING2-F9 · report `spya-nsrkju` (#498) · Greg (admin; `feedback-reporter.ts` exit 0) ·
filed 2026-10-09 00:53 UTC from `/changelog` · kind suggestion · queue item `qi-xxdgyn9c`.

> I think the Add page is going to be a little bit confusing to users, especially the sharing bit.
> Can we do a better job? I think this is partly about the graphic design and partly about the
> text. We could also include more tooltips, links to help pages. I don't know. Try kicking off
> different agents, each with a different persona to critique it.

**Shipped.** Five critics read screenshots of the page in character (a first-week reader, a postdoc
sharing with her lab, an interaction designer, a privacy-anxious journalist, and GPT Sol as a
content designer), and the changes are the ones they agreed on: the Sharing row is the page's body
size and reads *Sharing options*; the open section starts with *Every article starts private…* and
a *How sharing works* link to Help; the private link comes first; *Make it public…* is a button like
the link's, so nothing looks shared while the question is still asking; the descriptions lose the
sentences about the buttons and gain *can pass it on* and where the public listing is; the import
card's copy button has a copy icon and a tooltip that no longer suggests a private link opens that
address. Also folded in: `qi-9x3akt5n`, a refused paste no longer says its text *has been sent*.
[261009i](../plans/261009i-add-page-sharing-clearer.md) has the critiques, the reasoning and both
GPT Sol reviews.

**Queued, not built** (`qi-krppt8r9`): the confirmation panel, which is shared with the Metadata
card; a private link whose create reply was lost cannot be turned off from the add page; two privacy
sentences whose meaning would change (naming the provider, and when *has been sent* is true); and
the rest of the page (the auto-modes box, the slug as the card's title, the purpose box's text).
