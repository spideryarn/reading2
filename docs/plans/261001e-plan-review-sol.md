1. **Root cause and fix:** Yes. React emits adjacent direct-child spans with no text node between them ([Masthead.tsx:269](/home/greg/code/spideryarn2/.claude/worktrees/figure-overflow-390/src/web/Masthead.tsx:269)); the separator is generated inside the following span ([shell.css:361](/home/greg/code/spideryarn2/.claude/worktrees/figure-overflow-390/src/web/styles/shell.css:361)); and b8e8a9dd added `nowrap` to every later span ([shell.css:366](/home/greg/code/spideryarn2/.claude/worktrees/figure-overflow-390/src/web/styles/shell.css:366)). More precisely, they do not “become one nowrap item”: ordinary inline boundaries introduce no wrap opportunity, producing one unbreakable suffix.

`inline-block` is the correct fix. CSS explicitly requires soft-wrap opportunities before and after atomic inlines, so there is no conforming-browser exception here ([CSS Text §5.5](https://drafts.csswg.org/css-text-3/#line-breaking)). It should not alter desktop vertical geometry: the inline-block’s baseline is its last line-box baseline, and the inherited line-height remains unchanged ([CSS 2.2 §10.8](https://www.w3.org/TR/CSS22/visudet.html#leading)).

2. **Other instances:** None. The two apparent sibling cases from the `nowrap` grep are already flex items: `.origin-host`/`.origin-path` sit in `.origin-link { display:inline-flex }` ([shell.css:294](/home/greg/code/spideryarn2/.claude/worktrees/figure-overflow-390/src/web/styles/shell.css:294), [Masthead.tsx:477](/home/greg/code/spideryarn2/.claude/worktrees/figure-overflow-390/src/web/Masthead.tsx:477)); the chat metadata spans sit in `.chat-thread-meta { display:flex }` ([mode-band.css:377](/home/greg/code/spideryarn2/.claude/worktrees/figure-overflow-390/src/web/styles/mode-band.css:377), [ChatPanel.tsx:830](/home/greg/code/spideryarn2/.claude/worktrees/figure-overflow-390/src/web/ChatPanel.tsx:830)).
