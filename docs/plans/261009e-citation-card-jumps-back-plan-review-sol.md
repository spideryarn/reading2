## Findings

1. **High — `citedAt` is ordered, but not complete for every citation.** The plan says it contains “every body block” uncapped ([plan:16](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/docs/plans/261009e-citation-card-jumps-back-to-every-passage-that-cites-the-work.md:16)). In fact, extraction requests at most three prose mentions ([citations.ts:1948](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/bibliography.ts:1948)) and verification enforces that limit ([citations.ts:829](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/bibliography.ts:829)). `placesOf` expands note citations to all matching note markers and sorts the result into document order ([citations.ts:946](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/bibliography.ts:946), [citations.ts:961](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/bibliography.ts:961)), but direct author-year mentions after the first three can be absent. Implement this as “every known citing passage,” or expand the pipeline before claiming completeness. The `CitedWork.citedAt` comment is correspondingly too strong ([types.ts:4822](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/types.ts:4822)).

2. **High — the cap does not define how the current passage is handled.** The plan requires the current paragraph to be shown unlinked ([plan:47](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/docs/plans/261009e-citation-card-jumps-back-to-every-passage-that-cites-the-work.md:47)) while also limiting the list to 20 ([plan:50](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/docs/plans/261009e-citation-card-jumps-back-to-every-passage-that-cites-the-work.md:50)). It needs rules for a current passage beyond position 20 and for a work cited only in the current passage. Concurrent implementation work exposed the latter: the targeted test run failed because the card rendered “cited in 1 paragraph and 1 more” ([ProseHoverCard.tsx:2219](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/ProseHoverCard.tsx:2219), [citation-hover-card.test.tsx:361](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/tests/citation-hover-card.test.tsx:361)). Require tests for sole-current and current-after-cap.

3. **Medium — pointer and touch nesting work, but keyboard focus can close the parent card.** `BlockRef`’s delegated `BlockLinkCard` survives the portal because context crosses portals ([BlockLinkCard.tsx:127](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/BlockLinkCard.tsx:127)); the outer hover card explicitly stays open while the pointer is in any `.hover-card` ([useHoverCard.ts:450](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/useHoverCard.ts:450)); and touch events inside the card are allowed through ([useHoverCard.ts:660](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/useHoverCard.ts:660)). However, `focusIn` lacks the equivalent inside-card exception ([useHoverCard.ts:969](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/useHoverCard.ts:969)). Focusing a numbered `BlockRef` can therefore schedule the containing dialog to close and unmount the focused link. Add focus-retention behavior and a keyboard test.

4. **Medium — numbered links need explicit touch sizing and accessible names.** `BlockRef` supplies its generic enlarged touch target only when it has no children ([BlockRef.tsx:182](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/BlockRef.tsx:182)), and child content supplies its own accessible name ([BlockRef.tsx:204](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/BlockRef.tsx:204)). A bare “1” is both small and poorly named. The plan should require a coarse-pointer target consistent with the project’s 40×40 guidance ([touch.md:470](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/docs/project/touch.md:470)) and a label such as “Go to citing paragraph 1 of 4,” plus `aria-current` on the unlinked current number. Test the two-tap path explicitly: first tap opens CiteCard; second tap on a number jumps exactly once.

5. **Medium — “the reference entry already opens CiteCard” is conditional.** It is true for a uniquely located, rendered HTML reference entry: Reader includes `reference` among citation places ([Reader.tsx:1462](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/reader/Reader.tsx:1462)). But `reference` is optional ([types.ts:4809](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/types.ts:4809)); repeated or unrefindable text receives no mark ([annotate.ts:1105](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/annotate.ts:1105)); and PDF reference entries may not correspond to rendered blocks ([types.ts:4811](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/types.ts:4811)). Phrase this as the supported HTML path, not a universal invariant.

## What checks out

- `jumpTo(id, citePassageKey(work.id))` is the right call. The key targets marks for that specific work ([rows.ts:98](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/rows.ts:98)); when none exists, scrolling retains the block rect ([scroll.ts:1085](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/scroll.ts:1085)) and flashing falls back to the whole cell ([flash.ts:268](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/flash.ts:268)).
- `shown.el.closest("tr[data-block]")` is a sound current-block lookup because `shown.el` remains the original prose trigger while the pointer moves into the portaled card.
- Reusing `BlockRef` is the simplest implementation; no new data shape is needed.
- Visitor exclusion is correct because Reader only constructs `works` for owners ([Reader.tsx:1410](/var/tmp/spideryarn-worktrees/fbtsd470-citations-jump-back/src/web/reader/Reader.tsx:1410)).
