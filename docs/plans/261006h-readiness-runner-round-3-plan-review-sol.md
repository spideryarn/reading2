- **P3R-01 — P1 — An existing stamp does not establish build provenance.** `buildStamp()` uses `readStartRevision()`, which ignores untracked files. A manual build at SHA A can consume an untracked imported file and stamp itself `{sha:A, dirty:false}`. Remove that file afterwards: the runner now stamps clean, and the proposed validator returns null for the surviving bundle. The runner’s before/after checks never observed that build. Require a fresh build on initial preparation, or strengthen and verify producer provenance before reusing existing output.

- **P3R-02 — P1 — “Whole” and “usable” exceed the proposed integrity check.** A correct stamp plus non-empty, truncated JavaScript satisfies all three conditions while producing a broken page. HTML-only validation also misses transitive assets: the current CSS references eleven fonts. A producer-generated output manifest with sizes/hashes would bind the stamp to the complete output; `generateBundle` currently emits diagnostic metadata, not a verified completion record.

- **P3R-03 — P1 — Another inherited npm setting can hollow lifecycle execution.** With `npm_config_script_shell=/bin/true`, the proposed `npm ci` flags exit 0 while the root `postinstall` effect is absent. I reproduced this offline. A cached bundle accepted by P3R-01 bypasses the rebuild backstop. Pin the intended script shell, or narrow the environmental-independence claim and cover this case explicitly.

- **P3R-04 — P1 — Stage 2 is not a safe relaunch proof as written.** `--once` acquires the same lifetime lock; there is no dry invocation. Calling `prepareRunner()` directly bypasses the lock and can run `npm ci` while the old loop’s check uses those dependencies. Tests do not exercise live preparation. Prove preparation in a separate worktree, then wait for the old check to finish, stop the loop, confirm its descendants exited and lock released, and launch the replacement. Preserve an executable old-code checkout for rollback.

- **P3R-05 — P2 — The proposed mutation coverage still has wiring gaps.** Testing `advanceRunner()` catches its internal guard losing `expectedRepository`, but does not catch `tick()` supplying the wrong repository. Likewise, classifier `it.each` tests do not detect removal from the production Git diff pathspec. Exercise those callers. Invalid-bundle fixtures must otherwise contain a valid stamp and assets, so each rejection cannot pass through another guard.
