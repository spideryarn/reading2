1. **P1 — The pause does not cover every persistence path, so rough Chromium guesses can still become stored text.** The plan explicitly allows hidden-tab commits while dictating (`docs/plans/261020r-dictation-on-the-add-page-boxes-and-a-microphone-by-default.md:52-67`), while `AddPage.tsx:1368-1377` commits on visibility change and retires on unmount, and `useAutosavedText.ts:269-301` commits or sends About-you text on hidden/pagehide/unmount. The proposed held-seed implementation also adopts the seed and flushes the current—potentially rough—text from `leaveNow` and `retire` (`src/web/add-purpose.ts:273-278`, `src/web/add-purpose.ts:336-365`). Closing the page can therefore leave rough text as the final value; merely hiding it can let publication consume rough purpose text before the transcript corrects it. Replace `heldSeed` with one transactional pause boundary: capture the pre-dictation draft, suppress idle, shortcut, visibility, pagehide and retirement writes of the live draft, record a returned seed without changing the box, and only expose/commit the final draft when `onEnd` releases the pause. A retired session must flush at most its pre-dictation snapshot, never its live guesses. Test hidden, pagehide, unmount, first-slug arrival, source change and Retry-to-another-slug while busy.

2. **P1 — A public-copy answer still silently discards a completed purpose dictation.** The plan deliberately unmounts the boxes after the words land (`docs/plans/261020r-dictation-on-the-add-page-boxes-and-a-microphone-by-default.md:91-96`, `:106-109`), but a public answer never supplies the purpose session with a slug, because the public slug must not enter `Completion` (`docs/plans/261009j-a-public-copy-offered-at-import.md:187-190`). Consequently `AddPurposeSession.commit` cannot save (`src/web/add-purpose.ts:228-230`), yet *Read the public copy* becomes navigable once `busy` clears (`src/web/AddPage.tsx:2047-2074`). Keep the purpose draft visible and require an explicit “Read without saving this reason” choice, or provide another durable carry path; do not treat “transcript reached the textarea” as safely finished. Add the public-answer/no-slug case to the lifecycle tests.

3. **P1 — “Every exit” omits several real navigation paths.** Stage 3 guards the Ready and public-copy actions (`docs/plans/261020r-dictation-on-the-add-page-boxes-and-a-microphone-by-default.md:77-95`), but the page also has an always-live *Back to the shelf* link (`src/web/AddPage.tsx:2031-2035`), the failed/cancelled job’s dismiss action navigates through `onHide` (`src/web/AddArticle.tsx:738-748`), quota failures link away (`src/web/QuotaNotice.tsx:124-134`), and the sharing disclosure links to Help (`src/web/AddSharing.tsx:144-152`). Each can unmount `useDictation`, whose cleanup aborts the recording/transcription (`src/web/useDictation.ts:2094-2136`). Add one page-level busy navigation gate and visibly disable or replace every in-page navigation affordance while busy; test Back, job dismiss, quota and Help navigation during opening, listening and transcribing. The author-gift exit itself is otherwise sound because it cannot begin while busy and disables new dictation while waiting.

4. **P2 — The ratchet’s file-level test is neither sound nor robust enough to support its claim.** The plan accepts any textarea file containing a `DictationButton` or `ProfileBox` (`docs/plans/261020r-dictation-on-the-add-page-boxes-and-a-microphone-by-default.md:122-130`), so a new unmic’d textarea in an already-covered file passes. This already happens: `ChatPanel.tsx:3176-3195` has a prose rewrite textarea without dictation, while another component’s buttons at `ChatPanel.tsx:3900-3907` make the whole file look compliant. Keep the ratchet—it is worthwhile—but make it an exact recursive inventory of textarea occurrences/components, with an expected count and reason per exempt occurrence rather than per file. Parse JSX or scan recursively without relying on a shell `**` glob, and add `EditQuestion` to the sweep/exemption list.

5. **P3 — The busy-to-purpose plumbing can be simpler.** The plan already has authoritative per-box refs plus one rendered OR state (`docs/plans/261020r-dictation-on-the-add-page-boxes-and-a-microphone-by-default.md:71-75`); it does not need another purpose-busy state solely to pause replacement sessions. Have the purpose callback update `purposeBusyRef` and pause the current session immediately, then have the session-replacement layout effect call `purpose.setPaused(purposeBusyRef.current)`. Retain only the combined state used to render disabled controls.
