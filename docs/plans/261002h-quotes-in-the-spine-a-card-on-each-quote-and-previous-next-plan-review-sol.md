## P1

1. **Skim breaks both Stage 1 derivations.** The plan empties `hitBlocks` only in Quotes mode, but Skim publishes its current quote as a normal passage via `QUOTES_RUN`; it would therefore retain the old green lane alongside the new strip. More subtly, when the current stop is hidden from the band, Skim resolves that quote afresh and prepends it only to `proseFound`, so a strip derived from `quotes.found` can omit a quote visibly outlined in the prose. Derive the strip from `proseMarked`, and remove quote-stroked Found objects from the rail projection in every mode—not only Quotes. 2. **“Hover and keyboard” is not supplied by adding the selector.** Quote marks are not focusable; `focusable: true` merely listens for focus events. Worse, if a card opens from an enclosing focusable link, moving focus into its new buttons makes `focusIn` find no matching prose anchor and schedules the card to close. The keyboard doc explicitly records portalled prose-card controls as a known bad exception. Simplest v1: describe this as a pointer-hover card and leave keyboard operation to Quotes mode. Otherwise the plan needs a genuine focus trigger and portalled-card focus-retention work; making every quote fragment tabbable would be worse. 3. **Quote lookup must handle split and merged marks, not just one `data-hit`.** A quote may produce several sibling marks, and `data-hit` is a space-separated mixture of quote and search IDs. Existing term/citation lookup also searches descendants when the hover anchor is an enclosing link. The plan should require: inspect the nearest mark plus descendant marks, split every `data-hit`, filter through the quote-key map, and deduplicate. Otherwise quote-inside-link keyboard cases disappear and split marks can duplicate the quote section. Evidence: [annotate.ts:478](/home/greg/code/spideryarn2/.claude/worktrees/fbyd2c47-quotes-spine-tooltip-nav/src/web/annotate.ts:478), [annotate.ts:624](/home/greg/code/spideryarn2/.claude/worktrees/fbyd2c47-quotes-spine-tooltip-nav/src/web/annotate.ts:624), [ProseHoverCard.tsx:311](/home/greg/code/spideryarn2/.claude/worktrees/fbyd2c47-quotes-spine-tooltip-nav/src/web/ProseHoverCard.tsx:311).

4. **`stepQuote` can select a dead quote.** `markedQuotes` intentionally retains saved quotes whose blocks no longer resolve, while `resolveQuotes` omits their marks. `jumpTo` does not validate the destination, so stepping can set a stale selection, push a dead `?at=`, consume the arrow key, close the card, and move nowhere. Step over navigable quotes, or have navigation return failure and preserve the current state/card. The `hiddenSelection` effect does not fight valid stepping; stale targets are the real issue.
