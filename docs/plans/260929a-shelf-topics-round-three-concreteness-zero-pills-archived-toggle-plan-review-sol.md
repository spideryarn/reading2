R1 — P1, established. The extractor cache version is missing from the plan. Any concreteness filtering or ranking change in `extract.ts` changes cached output, but `EXTRACTOR_VERSION` remains 1 and existing shelves will keep their old candidates (`extract.ts:7-8,38`). Recommendation: require a version bump, update its invariant test, and measure the resulting refill.

R2 — P1, established. Moving Archived into `ShelfControls` can strand a reader whose every article is archived. Controls currently render only when the active `total > 0` (`Library.tsx:604-615`); the bottom disclosure escapes that guard. The existing “Nothing on the shelf yet” message would also contradict a visible archived-only list (`Library.tsx:651-654`). Recommendation: render the Archived toggle whenever the active request has settled, independently of active count, and derive empty states from the combined scope.

R3 — P1, established. Removing the bottom `Archived` component also removes the only `loadArchived()` trigger (`Library.tsx:1127-1135`). Without relocating it, `?archived=1` never loads archived rows, and `shelfKeyOf` deliberately withholds topics while that list is null (`useShelfTerms.ts:57-69`). Keep active cached rows painted while the archive loads or fails; do not make the combined list itself null. The archive’s cached offline response may be used if previously fetched, but `/api/library/terms` is not cached, so offline topic filtering remains unavailable—state that as the accepted limit.

R4 — P1, established. A merged row needs archived identity, but `LibraryEntry` has none, `ShelfEntry` always calls `shelf.archive` (`ShelfEntry.tsx:529`), rename updates only the active array (`useShelf.ts:411`), and the Archive tooltip promises the card leaves the shelf. With Archived on, it should instead remain and change state. Recommendation: define an explicit archived row/flag, replace Archive with Restore for those rows, reconcile mutations in both arrays, and update the conditional copy. Combine rows before TanStack sorting; then the fixture sink and one row cap continue to work. The public shelf is unaffected.

R5 — P1, reasoned. Zero-pill hiding is right in both views, and keeping selected zero-count topics handles a URL-selected topic correctly. But filtering after today’s collapsed selection would leave holes: `shown` currently takes the first 12 before considering counts (`ShelfTerms.tsx:103-108`). Recommendation: first derive rank-preserving `available = count > 0 || selected`, then take the first 12 available plus selected outliers; use that same array for detail and “All N”. A key absent from a settled server response should continue to be removed from the URL by `useChosenTopics`.

R6 — P1, established/reasoned. There is no route for an exact single-word `entered` topic in this code: `nounishShape("entered")` rejects it, and labels preserve token count; the only plausible route is a longer phrase with `entered` before a passing final word, possibly visually truncated. A red test for single-word `entered` will therefore start green. Capture the reported response/DOM label first. The concreteness design also is not ready: no dataset or licence is selected despite “research below,” unknown words pass—including unknown vague forms—and phrase lookup/unknown semantics are unspecified. A threshold near 3.0 is a reasonable measurement seed, not yet a rule; `following year` is not a valid fixture because `year` is already a stopword.

R7 — P2, reasoned. The global 0.5 shared-stem penalty is more intervention than the report requires and overlaps existing shared-word Jaccard, containment, and replacement rules (`choose.ts:328-349,424-440`). Start with the adjacency rule alone; it directly fixes near-neighbours while preserving immediate fresh coverage. If 0.5 remains, replace “must not fall materially” with a gate such as no loss beyond one physical article at @5/@8/@12, and measure adjacency on the final list after `admit` replacements.

Verdict: Revise before build—the display direction is right, but cache versioning and the archive-only/lazy-load contracts are P1s, and Stage 1 has not yet explained the reported `entered` topic.
