P1 — High: The glob is incorrect as written. `query: "?url"` makes the URL the module’s default export, but an eager glob without `import: "default"` emits `import * as …`; the manifest receives module namespace objects rather than URL strings ([plan](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/docs/plans/261007l-help-screenshots-and-gifs.md:55), [Vite transformer](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/node_modules/vite/dist/node/chunks/node.js:29754)). TypeScript may not expose this because Vite’s known-query overload infers a string. Use:

```ts
import.meta.glob("./pages/images/*.{png,gif}", {
  query: "?url",
  import: "default",
  eager: true,
})
```

The simpler option is preferable: import each file explicitly in `help-images.ts`, keyed by filename, exactly as `shots.ts` does ([shots.ts](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/src/web/shots.ts:65)). The filesystem/manifest test then supplies the missing-file and extra-file guarantees without a second asset map. No Vite or Vitest configuration change is needed.

P2 — High: The planned test can pass while the feature does nothing. All listed set comparisons are vacuously green with zero entries; a declared 1×1 placeholder also passes exact dimensions and the upper size limit; and a one-frame or visually unchanged GIF passes the same checks. This is especially risky because stage 1 explicitly introduces a placeholder ([plan](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/docs/plans/261007l-help-screenshots-and-gifs.md:124)). The existing screenshot test deliberately asserts non-emptiness, minimum dimensions and minimum bytes because placeholders previously survived every ordinary check ([landing-assets.test.ts](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/tests/landing-assets.test.ts:129), [minimum checks](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/tests/landing-assets.test.ts:144)). Add equivalent, crop-appropriate lower bounds. For GIFs, also require multiple frames and more than one distinct frame; test the converter’s frame ordering and equal-dimension validation.

P3 — Medium: The 2× sizing contract is underspecified. The manifest dimensions are said to match the file header, while the same plan says files remain twice their drawn size ([plan](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/docs/plans/261007l-help-screenshots-and-gifs.md:60), [capture rule](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/docs/plans/261007l-help-screenshots-and-gifs.md:82)). Passing file-pixel dimensions directly as HTML attributes makes a 600px crop naturally draw 600 CSS pixels, not 300; the global rule only caps it at its column and preserves aspect ratio ([tailwind.css](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/src/web/tailwind.css:404)). State explicitly that `w`/`h` are file pixels and the renderer uses `w / 2`, `h / 2`, shrinking further at narrow widths.

P4 — Medium: Infinite-loop GIFs bypass the repository’s reduced-motion protection. That protection only shortens CSS animation and transition durations ([tailwind.css](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/src/web/tailwind.css:120)); it cannot pause raster animation. The proposed 2–5-second loop therefore moves indefinitely ([plan](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/docs/plans/261007l-help-screenshots-and-gifs.md:91)). Either stop each GIF after enough repetitions to remain within five seconds and offer a replay, provide a static reduced-motion fallback, or prefer a controlled `<video>` with poster and pause controls. W3C specifically recommends GIFs stop within five seconds. [W3C technique G152](https://www.w3.org/WAI/WCAG22/Techniques/general/G152)

P5 — Medium: `pngjs` needs a declaration package. `scripts/frames-to-gif.ts` is covered by the strict root TypeScript project ([tsconfig.json](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/tsconfig.json:15)), but `pngjs` publishes JavaScript without bundled types, whereas `gifenc` declares its own `types.d.ts`. Add `@types/pngjs`, provide a local declaration, or reuse an already typed decoder. Otherwise `npm run typecheck` should fail. [pngjs package metadata](https://github.com/pngjs/pngjs/blob/main/package.json), [gifenc package metadata](https://github.com/mattdesl/gifenc/blob/main/package.json)

P6 — Medium: The ongoing-maintenance instructions need to run the new asset test. The current documented recipe names only `tests/help-page.test.tsx` and typechecking ([help-page.md](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/docs/project/help-page.md:119)); following it would miss stale dimensions, orphan files, size limits and broken GIFs. Add `tests/help-images.test.ts` to step 4, alongside the planned “retake or delete” question.

P7 — Low: The Markdown representation is sound, but specify AST-based checks rather than “image lines.” `mdast-util-from-markdown` produces a paragraph containing one `image` for the intended form; a list nests that paragraph, a linked image nests it under `link`, and an image followed by a soft break has an additional text child. An exact one-child paragraph test therefore rejects all three reliably, matching the renderer’s strict design ([help-markdown.tsx](/var/tmp/spideryarn-worktrees/fbmq05ww-help-screenshots/src/web/help/help-markdown.tsx:262)). A literal ASCII quote inside a double-quoted caption must be written as `\"`; smart quotes are harmless. Add explicit escaped-quote and soft-break tests so a future regex cannot narrow the guarantee.

The server and corpus integration are otherwise sound. The branch’s generator preserves raw Markdown after token expansion (`worktree-fbucftjt-help-chatbot:tests/help-corpus.test.ts:40`) and compares it with the checked-in JSON (`:92`), so image additions force regeneration. The server imports that generated JSON, not `src/web/` (`worktree-fbucftjt-help-chatbot:src/help-chat-call.ts:38`), so assets and the glob do not enter the API bundle.
