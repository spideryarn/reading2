1. **P1 — Stage B duplicates the existing figure classifier and reintroduces cases it already excludes.** The proposed `kind === "media"` test includes every `<hr>`, while raw tag matching admits presentation tables, LaTeXML equation tables, pull-quote figures, and small lettering/icons (`docs/plans/261024w-figures-and-tables-open-in-the-original-and-a-titled-arxiv-box-keeps-its-words.md:56-59`; `src/blocks.ts:330-339`). `figureKindOf`/`figuresOf` already answer this exact question and explicitly reject those cases (`src/figures.ts:1-16`, `src/figures.ts:45-95`, `src/figures.ts:109-123`). Stage B should consume that existing classification instead of defining a second, broader one.

2. **P1 — The exact-fragment strategy assumes original IDs survive when the common root ID does not.** Stage 3 temporarily stamps author IDs, scrubs those stamps before serialization, and overwrites every block element’s non-Spideryarn ID with its own ID (`src/blocks.ts:1184-1188`, `src/blocks.ts:1237-1256`, `src/blocks.ts:1492-1516`). DOM-clobbering IDs can also be deleted by the sanitiser (`src/blocks.ts:1216-1229`). Therefore a publisher `<figure id="figure-1"><img …></figure>` with no descendant ID has no recoverable original ID in `block.html`, contrary to the plan’s claim (`docs/plans/261024w-figures-and-tables-open-in-the-original-and-a-titled-arxiv-box-keeps-its-words.md:60-63`). The original root target must be carried through stage 3, or the plan must explicitly accept that these figures only receive a text/page fallback.

3. **P1 — “Two foreignObjects, first short” can turn a two-label diagram into prose and discard the drawing.** The existing safety rule says diagrams use one `foreignObject` per label; it does not establish that diagrams always have three or more (`src/latexml.ts:703-708`; `tests/latexml.test.ts:600-610`). A diagram made from paths/rectangles with two short HTML labels satisfies the proposed rule (`docs/plans/261024w-figures-and-tables-open-in-the-original-and-a-titled-arxiv-box-keeps-its-words.md:35-41`). The plan itself notes that a real title carries `ltx_font_bold`, but does not require that evidence. Require a measured title-specific marker or geometry, and add a two-label-diagram negative test.

4. **P1 — The text-fragment fallback lacks the encoding and browsing-context rules that make it work.** Text-fragment terms must percent-encode `-`, `&`, and `,`; plain `encodeURIComponent` is insufficient because it leaves hyphens unchanged. Cross-origin text fragments also require a `noopener` browsing context ([WICG specification](https://wicg.github.io/scroll-to-text-fragment/)). The plan only says `#:~:text=` and “new tab” (`docs/plans/261024w-figures-and-tables-open-in-the-original-and-a-titled-arxiv-box-keeps-its-words.md:48-63`), while existing external-source anchors explicitly use `rel="noreferrer noopener"` (`src/web/Masthead.tsx:186-188`). Specify a dedicated text-directive encoder, construct the address through `URL` while replacing any existing hash, and test hyphens, commas, ampersands, `%`, `#`, and non-ASCII text.

5. **P1 — Links for figures on later pages of a multi-page article will open the wrong page.** Each later page is extracted using its own URL, then only its content is joined into page 1’s article; its address is not retained, and its anchors are rewritten to `p2-…`, `p3-…` (`src/read-parts.ts:10-27`, `src/read-parts.ts:57-61`, `src/read-parts.ts:99-117`, `src/read-parts.ts:171-179`; `docs/project/content-extraction.md:430-445`). `webSource(meta)` supplies page 1’s address, so the proposed article-only helper will open page 1 with a fragment or text that belongs to another page (`docs/plans/261024w-figures-and-tables-open-in-the-original-and-a-titled-arxiv-box-keeps-its-words.md:52-65`). Per-block source-page provenance is needed, or later-page blocks must be explicitly excluded.

6. **P2 — A singular `Map<BlockId, OriginalLink>` cannot provide a link for every visual in a block.** The existing PDF implementation documents that one block can contain multiple figures and consequently stores and renders an array of notes (`src/web/PdfFigureNote.tsx:193-205`). Stage B proposes one link based on the first ID and one control per block (`docs/plans/261024w-figures-and-tables-open-in-the-original-and-a-titled-arxiv-box-keeps-its-words.md:60-66`), leaving subsequent figures without their own destination. Use `Map<BlockId, OriginalLink[]>` or narrow the product claim to one link per figure block.
