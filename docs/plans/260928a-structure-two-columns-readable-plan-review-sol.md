1. **P1 — The covering band creates a non-monotonic face switch.** The plan keeps measuring the full-width covering band against the new 585px threshold ([plan:51](</docs/plans/260928a-structure-two-columns-readable.md:51>)). Below 700px, however, `fitMode` returns `modeW: 0` ([layout.ts:838](</src/web/layout.ts:838>)) and CSS paints the band at the viewport minus the rail, with no border ([narrow-window.css:326](</src/web/styles/narrow-window.css:326>)). At a 16px root, the covering threshold is 584px because the border is absent. Consequently:

   - Spine on: windows 596–699px show columns; 700px suddenly switches to a 288px list beside the prose.
   - `?spine=0`: 584–687px show columns; 688px switches back to the list.

   This contradicts “phones lose the columns,” “≤400 below the switch,” and the dead-zone premise ([plan:45](</docs/plans/260928a-structure-two-columns-readable.md:45>), [plan:112](</docs/plans/260928a-structure-two-columns-readable.md:112>)). **Fix:** force the list face whenever the band covers the prose, passing that fact into the face decision. Sweep the actual painted width—not `fit.modeW`, which is zero—across both 699/700 and 687/688, both spine states, and multiple root sizes.

2. **P1 — The 585px arithmetic does not give both columns 272px of readable content.** The plan subtracts only band padding, border, and gutter ([plan:58](</docs/plans/260928a-structure-two-columns-readable.md:58>)). But column B additionally spends `0.6rem + 2px` on `.struct-inner`’s inset and border ([structure-mode.css:112](</src/web/styles/structure-mode.css:112>)); global `border-box` makes that come out of its equal grid track. At 585px the tracks are 272px, but column B’s content is only **260.4px**. At the 681px ideal it is **308.4px**, not 320px. **Fix:** either move the bracket/inset into the gutter, explicitly use asymmetric tracks, or include this cost. Keeping equal tracks requires about a 609px minimum band and 705px ideal at a 16px root; then recalculate every switch width.

3. **P1 — The current-state arithmetic for the 390px phone is wrong.** A covering band excludes the default 12px spine ([narrow-window.css:327](</src/web/styles/narrow-window.css:327>)). At a 390px window it is therefore 378px wide, and `structureFace` subtracts 24px padding before comparing with 364px ([StructureMode.tsx:79](</src/web/modes/structure/StructureMode.tsx:79>)): the current face is already the list. The claimed 177px columns occur only with `?spine=0`. The current covering switch is 400px with the rail, 388px without it—not “any phone 389px or wider” ([plan:29](</docs/plans/260928a-structure-two-columns-readable.md:29>), [plan:76](</docs/plans/260928a-structure-two-columns-readable.md:76>)). **Fix:** correct the baseline table and list rail-on and rail-off cases separately.

4. **P1 — Washing both marked rows is less consistent with the reference face, not more.** The list distinguishes the ancestor chain (`.here`) from one deepest current row (`.now`); only `.now` receives the orange wash and weight 650 ([outline-mode.css:252](</src/web/styles/outline-mode.css:252>), [OutlinePanel.tsx:497](</src/web/OutlinePanel.tsx:497>)). Structure deliberately emits two `aria-current` rows, one per column ([structure-panel test:219](</tests/structure-panel-draws-both-columns.test.tsx:219>)); styling both with the strongest wash produces two competing “now” marks, while column A already has the connector edge. **Fix:** wash only the deepest current row—normally the section in B, falling back to the part when no section exists—and keep the parent part at strong ink plus its connector. If two washes are desired, describe it as a deliberate departure rather than visual consistency.

5. **P2 — Root-relative fit/face agreement needs an explicit acceptance test.** The new minimum and ideal are in rem, but `fitMode` currently receives no root size ([layout.ts:548](</src/web/layout.ts:548>)), and `FitInput` currently documents `rootFontPx` as relevant only to the lone-prose cap ([layout.ts:517](</src/web/layout.ts:517>)). At a 20px root, even before accounting for the bracket, the proposed minimum band is 731px rather than 585px. **Fix:** explicitly pass `rootFontPx` through `fitMode`, update that contract, and test the exact boundary/dead-zone sweep at 12, 16, and 20px with both spine states.

I found no other runtime assumption that `modeW <= MODE_IDEAL`: the band, herald, bars, table pin, return chip, and viewport probe all consume `--mode-w` directly. The fisheye panels are not mounted in Structure, Floating UI positions the cards from actual rectangles, and StructurePanel’s hidden copies measure the same widened/font-enlarged rows, so its rung ladders remain structurally sound. The visual-consistency table is otherwise faithful to `outline-mode.css`.
