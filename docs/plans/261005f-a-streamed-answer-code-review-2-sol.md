- **D1 — P2 — fixed: clamp detection could override a reader.** From a held bottom, a 0.6px upward wheel/trackpad movement satisfied both original tolerances: it was more than 0.5px above `h.top`, yet less than 1px from the maximum. `settle()` therefore snapped the reader back. - **D2 — P2 — fixed: global `overflow-anchor: none` removed useful transcript anchoring.** Without native anchoring, a reader in history would jump when an earlier editor or Remember hint changes height; those local state changes do not invoke `Conversation`’s compensator. The same protection matters during Live, when typed streaming is not holding the transcript. The rule is now limited to `.chat-scroll.streaming`, and normal anchoring returns when the typed answer finishes. The exact Chrome anchor remains inferred. `.chat-room` is the strongest DOM explanation: it survives the replacement of “thinking…” by the zero-height prose anchor and blocks, and its top moves by the answer’s growth while its height shrinks. Chrome preserving that node would increase `scrollTop` by precisely the observed growth. That matches the specified anchoring model, which adjusts by the selected node’s movement and emits a scroll event. [CSS Scroll Anchoring specification](https://www.w3.org/TR/css-scroll-anchoring/). The fix prevents the competing positioner during streaming; it does not prove or structurally remove Chrome’s chosen anchor.

`settle()` does not normally loop: it records `h.top` and `h.max` before writing `scrollTop`, so the resulting event sees the recorded position and does not call `settle()` again. The room calculation also rounds upward, making the requested position reachable.
