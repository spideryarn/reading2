Verdict: **rethink**. The step-order move is safe, and waiting for Ideas is defensible, but the central Idea-to-Quote mapping is not yet specified in a form the model can use, the section-stop identity conflicts with the block-ID/URL contract, and newly generated Ideas would not reach the stop card.

## Findings

### F60 — P1 — Block IDs alone do not tell the model which Quotes carry an Idea

The plan supplies Ideas with occurrence block IDs and expects the model to recognize a Quote “in or next to” them ([plan:655](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/plans/260928a-trajectory-mode-skim-a-paper-at-increasing-depth.md:655>)). But current Quote records expose only `Q1`, section path, priority, and words—not their block IDs ([trajectory.ts:547](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/trajectory.ts:547>)). Even if Quote block IDs were added, random IDs deliberately encode neither position nor adjacency ([block-ids.md:44](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/project/block-ids.md:44>)).

Concrete fix: compute the relationship deterministically before the prompt. Label Ideas `I1…`, and annotate each Quote with the Idea labels it shares a block with or is adjacent to, preferably distinguishing exact from adjacent. Do not ask the model to infer document geometry from opaque IDs. This also makes the added prompt much smaller.

### F61 — P1 — Ideas generated by the route job will not appear in the stop card

Trajectory’s card mounts a standalone `useIdeasRead` ([TrajectoryMode.tsx:124](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/web/modes/trajectory/TrajectoryMode.tsx:124>)), whose initial GET will normally see no Ideas before the job runs. When the combined job finishes, `useTrajectory` refreshes only Trajectory and Quotes ([useTrajectory.ts:142](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/web/useTrajectory.ts:142>)). The Ideas read has no job subscription and therefore remains `none` until remount/reload.

This is the same failure class as the earlier F31 that 5g avoided. The “5g is not built” paragraph overlooks that Ideas have now become a generated card source.

Concrete fix: create `useIdeasRead` before `useTrajectory`, pass it in, and call `ideas.refresh()` from the trajectory job’s completion callback. Test a fresh article from no Ideas through completed route to an Ideas-bearing card.

### F62 — P1 — `{ kind: "section", nodeId }` cannot be the stored/navigation identity

The plan stores a section stop by `nodeId` ([plan:763](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/plans/260928a-trajectory-mode-skim-a-paper-at-increasing-depth.md:763>)). Tree IDs are regenerated sequentially as `n0001`, `n0002`, etc. ([hierarchy.ts:1688](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/hierarchy.ts:1688>)), while `?stop=` accepts only stable `spya-…` IDs ([params.ts:61](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/web/params.ts:61>)). A recut tree can also make the same node ID refer to another section.

Almost every route helper assumes `quoteId`: current selection, stepping, depth changes, door targets, row keys, deep links, passage resolution, cards, and flashes ([trajectory-route.ts:78](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/web/trajectory-route.ts:78>)).

Concrete fix:

- Use a discriminated union, but anchor section stops to a stable `blockId`, not solely a node ID.
- Define the passage as the first `isBodyEvidence` block inside the top-level section, excluding headings and supplements; store that resolved block ID at generation time.
- Centralize `stopKey(stop)` and `stopBlockId(stop)`.
- Treat missing `kind` as legacy Quote at the read boundary.
- Validate section labels against server-built candidates: top-level, body-bearing, and with no usable offered Quote.
- Update `visibleRoute`, `currentStop`, `stepStop`, `doorAfter`, panel rows, passage resolution, cards, flash, URL/last-view tests, store freshness, and export documentation.

The discriminated union is the right shape only after those identity and compatibility rules are explicit.

### F63 — P2 — The coverage tool will silently undercount section stops

The promised post-6b measurement uses the new script ([plan:772](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/plans/260928a-trajectory-mode-skim-a-paper-at-increasing-depth.md:772>)), but `stopBlocksAtDepth` resolves every stop through `stop.quoteId` and counts anything else as unresolved ([trajectory-coverage.ts:115](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/scripts/trajectory-coverage.ts:115>)). `loadTrajectory` similarly constructs the current-Quote set from every stop’s `quoteId` ([pg.ts:3391](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/store/pg.ts:3391>)).

Concrete fix: make the script and store use the same union-aware `stopBlockId`; report Quote stops and section stops separately. Update the export description, which currently promises only “a route through the quotes” ([export-bundle.ts:591](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/store/export-bundle.ts:591>)).

### F64 — P1 — Waiting adds a substantial undisclosed call while the empty-state copy still promises seconds

The plan’s own baseline prices Ideas at roughly $0.065–$0.183 per article, against approximately $0.02 for the route ([baseline:31](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/plans/260928a-trajectory-mode-stage6-coverage-baseline.md:31>)). Ideas are documented as taking tens of seconds ([useIdeas.ts:1](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/web/useIdeas.ts:1>)). Yet the current pre-press copy says the route is a short call taking “a few seconds” whenever Quotes already exist ([TrajectoryPanel.tsx:262](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/web/TrajectoryPanel.tsx:262>)).

The running band will correctly say “Finding the ideas,” because the pipeline label is already present. That is too late to explain the longer paid prerequisite.

Concrete fix: derive explicit `needsIdeas`/`needsQuotes` state and describe the prerequisites before the press, including that finding Ideas is the long part. If Stage 6 always names Quotes too, disclose when an outdated Quote list will be replaced.

Waiting is still preferable to planning twice: it gives the first visible route the intended semantics and avoids replacing it while it is being walked.

### F65 — P2 — The before/after gate changes its measuring stick

The normal paper’s baseline deliberately uses outdated `ideas/2` ([baseline:45](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/plans/260928a-trajectory-mode-stage6-coverage-baseline.md:45>)). In the new job, `stepIsDone` will compare Ideas’ current prompt version and regenerate them ([pipeline.ts:3415](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/pipeline.ts:3415>)). The “before” and “after” Idea-coverage denominators can therefore contain different Ideas and occurrences.

The adjacency metric also credits any occurrence and crosses headings, supplements, and top-level section boundaries using raw array distance ([trajectory-coverage.ts:144](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/scripts/trajectory-coverage.ts:144>)). Three single model samples cannot distinguish a prompt effect from ordinary model variation; the prompting guide explicitly requires an old-vs-old control ([prompting-guide.md:112](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/project/prompting-guide.md:112>)).

Concrete fix:

- Regenerate all Ideas to the same current version first, snapshot them, and score both route arms against that identical snapshot.
- Run the old route prompt at least twice.
- Keep same-block coverage primary; constrain “adjacent” to body blocks in the same top-level section.
- Add blind human judgments of Gist completeness/coherence and Quote worthiness.
- Record input tokens, latency, Quote count, duplicates, and per-section quality.
- Treat three articles as a smoke set, not sufficient evidence to ship 6b/6c.

### F66 — P2 — 6a largely repeats the current Quotes instruction, while its version bump has wider consequences

Quotes already says “Take them from across the whole piece” and warns against leaving the second half empty ([quotes.ts:1372](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/quotes.ts:1372>)); it also already receives the outline with gists ([quotes.ts:1473](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/quotes.ts:1473>)). The proposed nudge may help, but it is a refinement rather than a missing instruction.

A version bump makes every owner’s list outdated and offers replacement. Public visitors receive neither `outdated` nor `stale`, so “out of date everywhere” is false: they silently keep seeing the stored old list ([public-types.ts:267](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/public-types.ts:267>)). Other modes likewise continue using the old Quotes until replacement. Once replaced, changed Quote content makes Trajectory stale via its Quotes hash.

Concrete fix: run the proposed prompt as an isolated evaluation arm over snapshot articles before landing the version bump. Use production’s generator with `previous: null`, old-vs-old controls, and judge section spread alongside quote quality. Bump `PROMPT_VERSION` only after it wins; the bump is then correct provenance, not the experiment itself.

### F67 — P2 — 6c reverses an existing product finding without measuring the relevant risk

The scrapbook experiment already removed section gists because they gave away the finding ([trajectory.md:83](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/project/trajectory.md:83>)); `stop-card.ts` records the same exclusion ([stop-card.ts:24](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/web/stop-card.ts:24>)). Reintroducing the gist at precisely the sections with no Quote makes generated summary text the section stop’s main content.

A single current-only line does not automatically violate augment-not-replace, but “section coverage, words and cost” cannot detect whether readers consume the gist instead of the passage.

Concrete fix: ship/test 6b without 6c first. If an orientation line is still needed, prefer the section title or a non-answering question/cue. Test the gist separately with blind judgments of whether it gives away the passage.

### F68 — P2 — Freshness needs one canonical rendered-input fingerprint

The plan says Ideas and outline hashes join the stamp ([plan:683](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/docs/plans/260928a-trajectory-mode-skim-a-paper-at-increasing-depth.md:683>)), but current write and read paths each understand only the Quotes hash ([pipeline.ts:3325](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/pipeline.ts:3325>), [pg.ts:3391](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/store/pg.ts:3391>)).

Concrete fix: add one shared `trajectoryInputHash` over exactly the fields rendered into the prompt:

- usable Quote identity/text/priority/block relationship;
- Idea name, statement, and deterministic Quote association;
- the selected outline titles/gists;
- explicit `null` for missing Ideas.

Exclude timestamps, elapsed time, and fields not sent. Keep the route’s profile hash separate. Because Ideas’ own stamp includes the current profile, the combined job will produce Ideas and route for the same profile; the route’s stricter none→some rule should remain unchanged.

### F69 — P3 — “Summaries and outline … always exist” is too strong

A provisional headings tree explicitly has no gists ([types.ts:221](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/src/types.ts:221>)). The earlier plan wording correctly says “where the summaries have one”; the later freshness sentence contradicts it.

Concrete fix: say the outline exists, while gists are optional, and hash/render their absence explicitly.

## Other conclusions

The pipeline move is safe:

- `StepBefore` is derived from `STEP_ORDER`, so moving Trajectory after the Ideas–Sketch group makes `ideas` legal automatically.
- `cacheArticleForStep` compares all job members, not adjacent entries, so the move does not damage cache matching.
- Only named steps run; placing Trajectory after Sketch does not cause Timeline, Quiz, FAQ, or Sketch to run.
- `FORCE_ONLY_WHEN_NAMED` keeps both Ideas and Trajectory out of positional force cascades.
- One existing test deliberately asserts that Trajectory directly follows Quotes and must be rewritten ([trajectory.test.ts:610](</home/greg/code/spideryarn2/.claude/worktrees/trajectory-flash-position-0928/tests/trajectory.test.ts:610>)). I found no other load-bearing direct-follow assumption.

Section stops are best described as a second set of **navigation anchors**, though not necessarily a second visible highlight set. Keeping them current-only, with no quote stroke and only the ordinary ring/bar, is compatible with Greg’s later suggestion of plain block links. The project doc must explicitly revise its earlier “stops are Quotes” decision rather than pretending both rules remain true.

Prompt size is probably not the limiting factor on the three baseline articles: the long paper has only 8 Ideas and 16 Quotes. The full worst case is less clear because Trajectory permits up to 120 quotes at 1,200 characters each, and the plan does not bound which tree nodes enter the outline. Use only top-level sections initially, precompute Idea associations, fence Ideas and gists as untrusted data just like Quote records, and record per-component characters plus actual input tokens.

The simplest worthwhile Stage 6 is:

1. Give the route current Ideas through deterministic Quote↔Idea associations.
2. Wait for Ideas, refresh them into the card, disclose the wait, and hash the exact input.
3. Measure that alone.
4. Evaluate the Quotes nudge offline and ship it only if it wins.
5. Defer the section-stop union and gist line until remaining failures demonstrate they are needed.
