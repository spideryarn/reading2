The stop arithmetic is basically sound, but the browser/input contract needs tightening before implementation.

P1 — high — Blanket `onChange` snapping can mishandle assistive and non-pointer input.  
Evidence: [plan:44](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/docs/plans/261017f-threshold-sliders-jump-between-the-values-that-change-the-count.md:44>) claims screen-reader behaviour is unchanged, while [plan:79](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/docs/plans/261017f-threshold-sliders-jump-between-the-values-that-change-the-count.md:79>) snaps every change event. `preventDefault` itself should not break iOS VoiceOver: Safari synthesizes arrow-key events, so the proposed handler can replace the default correctly ([Apple WWDC22](https://developer.apple.com/videos/play/wwdc2022/10153/?time=564)). But W3C warns that touch assistive technologies do not uniformly synthesize those keys ([WAI slider pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)). If TalkBack or another path changes the native value directly by one ordinary step, nearest-stop snapping may return it to the same stop, making the gesture do nothing. Firefox can also fire `input` when the thumb is merely clicked without changing value; an off-stop default would then jump before the user moved it ([Mozilla bug 863633](https://bugzilla.mozilla.org/show_bug.cgi?id=863633)).  
Fix: distinguish pointer-active changes from other native changes. Snap pointer changes to nearest; for a non-pointer change, use its direction to move one stop; ignore `raw === controlledValue`. Add real iOS VoiceOver and Android TalkBack checks. If that cannot be verified, ship ticks without pointer snapping.

P2 — medium — Quotes’ raw stops are incompatible with an ordinary numeric `step`.  
Evidence: Quotes accept any finite 0–1 score, without hundredth rounding, at [src/quotes.ts:304](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/src/quotes.ts:304>); `barStops` preserves those raw values at [src/web/QuotesPanel.tsx:265](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/src/web/QuotesPanel.tsx:265>), while `?bar=` rounds to hundredths at [src/web/params.ts:591](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/src/web/params.ts:591>). The plan says Quotes keeps `barStops` but does not specify its new linear track’s `step` ([plan:85](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/docs/plans/261017f-threshold-sliders-jump-between-the-values-that-change-the-count.md:85>)). A score such as `0.625` is a step mismatch on `min=0, step=.01`; user agents may round mismatched range values, producing browser-dependent thumb/value behaviour ([HTML range specification](https://html.spec.whatwg.org/multipage/input.html#range-state-(type=range))).  
Fix: explicitly choose either:

- floor Quotes’ stops onto the same hundredth grid as its URL, accepting that close scores collapse; or
- use `step="any"` with exact `max` and test keyboard, VoiceOver, and TalkBack behaviour.

The first is simpler and makes reloads reproduce the exact same state.

P3 — medium — “No stop at 0” confuses a synthetic zero with a genuine zero score.  
Evidence: [plan:60](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/docs/plans/261017f-threshold-sliders-jump-between-the-values-that-change-the-count.md:60>) says there is no stop at zero, but valid model scores include zero, and Quotes currently preserves it at [src/web/QuotesPanel.tsx:265](</var/tmp/spideryarn-worktrees/fbt80rep-slider-snaps/src/web/QuotesPanel.tsx:265>). Fix: state “no synthetic zero”; retain zero when an item actually scores zero. Test `[0, .4, .8]`, including Home, left-edge pointer input, and the visible count.
