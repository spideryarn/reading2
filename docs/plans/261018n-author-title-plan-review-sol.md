1. **P1 — Not bumping `SANITIZER_VERSION` can silently remint stable block IDs.** The plan says old blocks may retain `title` ([plan:49](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/docs/plans/261018n-an-article-s-own-title-attributes-shown-in-our-card-marked-as-the-author-s.md:49)), while newly extracted HTML is sanitized before ID carry-over ([blocks.ts:1392](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/src/blocks.ts:1392)). For textless blocks, identity includes every attribute name and value ([blocks.ts:818](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/src/blocks.ts:818)); there is already an explicit `<hr title="…">` identity test ([empty-blocks-keep-their-ids.test.ts:296](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/tests/empty-blocks-keep-their-ids.test.ts:296)). Thus legacy `<hr title="thin">` and new `<hr data-author-title="thin">` no longer match, and that block silently gets a new ID. PostgreSQL’s stage baseline is read as stored, without sanitizer normalization ([artifacts-pg.ts:435](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/src/store/artifacts-pg.ts:435)), so bumping alone is insufficient there. **Fix:** bump to version 9, and canonicalize legacy `title` to `data-author-title` when preparing the previous baseline—or make `emptyKey` treat those spellings identically. Add a regression using a legacy titled `<hr>` baseline and assert `minted === 0`.

2. **P2 — The change knowingly removes meaningful accessibility semantics.** The plan explicitly accepts losing `abbr[title]` to screen readers ([plan:71](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/docs/plans/261018n-an-article-s-own-title-attributes-shown-in-our-card-marked-as-the-author-s.md:71)), contrary to the tooltip contract that replacements need a separate assistive path ([tooltips.md:96](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/docs/project/tooltips.md:96)). Images without `alt` can likewise lose a fallback accessible name. Restoring only empty anchors does not cover either case. **Fix:** preserve the title as an accessible description where one is absent; give `<abbr>` an explicit accessible expansion, and give `<img>` an `aria-label` when `alt` is absent—not when `alt=""` deliberately marks it decorative. Test these cases alongside the empty-link case.

3. **P2 — A titled ancestor can race `BlockLinkCard` on a cross-reference.** The widened selector ([plan:57](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/docs/plans/261018n-an-article-s-own-title-attributes-shown-in-our-card-marked-as-the-author-s.md:57)) can match a titled `<span>` containing `mark.xref`. Cross-references deliberately exclude only author hyperlinks, not titled spans ([annotate.ts:1131](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/src/web/annotate.ts:1131)), while `BlockLinkCard` independently listens for that mark ([BlockLinkCard.tsx:388](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/src/web/BlockLinkCard.tsx:388)). Hover or keyboard focus can therefore open two delegated cards. **Fix:** make the prose selector treat `XREF_SELECTOR` as a shadowing target and have `read` decline it before walking to a titled ancestor. Add hover and focus tests proving only the block-preview card opens.

4. **P2 — The proposed filter can hide meaningful punctuation despite claiming to err toward showing.** The draft comparator removes all punctuation and symbols ([author-title.ts:38](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/src/web/author-title.ts:38)); consequently `title="C++"` over text `C`, or `C#` over `C`, is classified as redundant and discarded. **Fix:** use conservative normalization for visible-text equality—case, whitespace, Unicode normalization, and surrounding quotation marks—while retaining semantic internal punctuation. Keep the more aggressive path normalization separate. Add `C++` and `C#` cases.

5. **P3 — The new transformation is not included in the binding-parity corpus.** `tests/author-title.test.ts` exercises the server binding, while the server/client equality corpus contains no title-renaming cases ([sanitize-client.test.ts:29](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/tests/sanitize-client.test.ts:29)). That suite also acknowledges its “browser” is still jsdom ([sanitize-client.test.ts:15](/var/tmp/spideryarn-worktrees/qi-ra2qwnfk-author-title-in-card/tests/sanitize-client.test.ts:15)). **Fix:** add ordinary, pre-forged, iframe, SVG, and MathML title cases to the shared parity/idempotence corpus; include at least one real-Chromium smoke case for the namespace paths.

No XSS or clobbering issue otherwise: `setAttribute` introduces no parser re-entry, `data-author-title` cannot clobber DOM properties, and forging it only produces explicitly author-labelled text. The iframe exception and second-pass attribute ordering are sound; SVG/MathML attributes are safe, with `<svg><title>` elements unaffected. Grep found no other direct stored-HTML reader beyond `anchorsOf`; the important missed indirect reader is `emptyKey` in finding 1.

There is no materially simpler design that still supports links, spans, abbreviations, and the maths re-sanitization path. The policy-backed attribute remains the smallest coherent approach once these fixes are included.
