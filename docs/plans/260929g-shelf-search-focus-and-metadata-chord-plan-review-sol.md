Revise before implementation: two user-visible edge cases need resolving.

- **F1 — P1: Back can leave focus on an off-screen search box.** The plan deliberately combines remount-time focus with `preventScroll` ([plan:39](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/plans/260929g-shelf-search-focus-and-metadata-chord.md:39)). `Library` does remount after returning from an article, but native scroll restoration is disabled ([main.tsx:29](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/main.tsx:29)); only app-initiated `navigate()` scrolls to the top ([router.ts:1247](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/router.ts:1247)), while Back merely emits `popstate` ([router.ts:1251](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/router.ts:1251)). Returning from far down an article can therefore preserve a large `scrollY`, focus the newly mounted search field, and refuse to reveal it. Typing then changes an invisible field. **Fix:** decide the Back policy explicitly: either skip autofocus when the field is outside the viewport, or allow/perform a scroll that reveals it. Add a real-browser test that scrolls an article, presses Back, and asserts both focus and visibility.

- **F2 — P1: the proposed chord helper can regress ⌘/Ctrl-K under Caps Lock.** The current handler explicitly accepts both `"k"` and `"K"` ([Dock.tsx:1315](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/Dock.tsx:1315)); the proposed `isModChord(e, key)` does not specify case handling ([plan:95](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/plans/260929g-shelf-search-focus-and-metadata-chord.md:95)). A straightforward equality check would break existing behavior. **Fix:** define letter matching as case-insensitive while keeping named keys such as `Enter` exact, and test `key: "K"` through the command-bar integration.

- **F3 — P2: the coarse-pointer check and browser verification are underspecified.** An unguarded `matchMedia` has previously broken multiple tests and can blank a page where the API is unavailable ([media.ts:4](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/media.ts:4)). Also, the planned “phone width” browser check ([plan:123](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/plans/260929g-shelf-search-focus-and-metadata-chord.md:123)) does not exercise `(pointer: coarse)`; Playwright needs `hasTouch: true` ([browser-testing-playwright.md:155](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/project/browser-testing-playwright.md:155)). **Fix:** specify a guarded media query and its unknown fallback, and run the phone check in a touch-enabled context while asserting the query actually matches. `(pointer: coarse)` is otherwise the better choice than `any-pointer`: it does not suppress autofocus on touchscreen laptops whose primary input is a mouse. Its accepted false negative is an iPad with a hardware keyboard.

- **F4 — P2: the research’s consolidation recommendation does not match either the code or the plan.** It claims every listener has the same eight guards ([research:14](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/research/260929a-keyboard-shortcut-libraries.md:14)) and recommends a general wrapper plus migration of arrows, G, ⌘-K, and the new chord ([research:89](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/research/260929a-keyboard-shortcut-libraries.md:89)). In reality, `keynav` lacks dialog/composition guards ([keynav.ts:455](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/keynav.ts:455)), ⌘-K lacks `defaultPrevented`/composition guards ([Dock.tsx:1314](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/Dock.tsx:1314)), and TermJump has the fullest set ([TermJump.tsx:133](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/src/web/TermJump.tsx:133)). The plan instead shares only `isTyping` and chord recognition ([plan:88](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/plans/260929g-shelf-search-focus-and-metadata-chord.md:88)). **Fix:** correct the inventory and explicitly recommend the plan’s narrower consolidation; it is the right-sized design because these handlers intentionally have different claiming policies. The no-library conclusion remains justified.

- **F5 — P2: allowing focused buttons is reasonable, but the stated browser justification is not established.** The research measured button activation only in headless Chrome ([research:53](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/research/260929a-keyboard-shortcut-libraries.md:53)) and explicitly says page behavior was not verified in Firefox, Safari, or Edge ([research:74](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/research/260929a-keyboard-shortcut-libraries.md:74)); the plan nevertheless states categorically that a focused button has no claim ([plan:72](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/plans/260929g-shelf-search-focus-and-metadata-chord.md:72)). **Fix:** frame this as an app policy—no current button binds modified Enter, so the global Metadata chord deliberately wins—or verify supported browsers before making a browser-default claim. Keeping focused links excluded is correct.

- **F6 — P2: the named red-first cases omit several promised contracts.** The plan promises `defaultPrevented`, IME composition, existing-focus preservation, and `preventScroll` behavior ([plan:69](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/plans/260929g-shelf-search-focus-and-metadata-chord.md:69)), but the explicit test list covers none of those ([plan:117](/home/greg/code/spideryarn2/.claude/worktrees/shelf-focus-and-metadata-chord/docs/plans/260929g-shelf-search-focus-and-metadata-chord.md:117)). **Fix:** add tests for a pre-cancelled event, `isComposing` and legacy `keyCode === 229`, an already-focused control on shelf mount, and the Back/off-screen case from F1.

The canonical signed-in shelf is `/`, not `/library`, and the article-to-shelf transition genuinely remounts `Library`; those parts of the plan are correct.
