## Other conclusions

After the fixes:

- A non-admin gets Opus without a new charge only when that article already has its permanent upgrade row. Switching off never removes or refunds it; switching back on never charges twice.
- The transaction is `read committed`, locks billing account then article, and performs only database queries and pure calculations while locked. Stripe resync happens after it returns.
- The unlocked ownership probe is owner-scoped and cannot create a billing anchor for another reader’s slug.
- Visibility changes and deletion use the same billing→article lock order. Settlement takes the article lock but never the billing lock, so there is no reverse edge.
- `high_power` rows cannot become in-flight or be released: the database requires them to be born succeeded, unreleased, with equal timestamps. The existing release and settlement predicates require `succeeded_at IS NULL`.
- Enforcement, admin reporting, sharing offers, deletion freezing, settlement, and release handle the two ledger kinds consistently.
- Route ownership, admin exemption, switch-off behavior, and 200/400/402/404/503 status selection are otherwise correct.
- No AI-cost amount currently reaches a reader response, stream, copy, email, export, changelog, or error. The cost endpoint remains admin-gated.
