# Stage 2 code review

1. **P1 — fixed: DOI containment could identify the wrong page.** `pageIsTheWork` searched the whole URL, including its query, and treated some DOI punctuation as a boundary. Consequently `https://citing.example/?doi=10.1038%2Fnature05357`, `10.1038/nature05357.2`, and even a wanted DOI appearing as the suffix of `10.9999/prefix/10.1038/nature05357` could pass when the page title matched. I first added failing cases at `tests/citation-web-note.test.ts:175-197`. The code now excludes query strings and compares the wanted DOI with each complete maximal DOI-shaped token at `src/citation-web-note.ts:274-323`; encoded paths and case differences remain accepted. Because that changes an identity check applied to stored notes, I also added the red old-version detachment assertion at `tests/citation-web-note.test.ts:351-354` and moved the read-guard version to `citation-web-note-checks/2` at `src/citation-web-note-shown.ts:27-33`.

2. **P1 — wider recommendation: the “own page, never a page about it” promise is still not enforceable by this evidence.** On every non-arXiv/non-resolver host, the final rule is only “a DOI token occurs in the path or search extract” plus `titleNamesWork(...) === "whole"` (`src/citation-web-note.ts:318-323`). Indeed, the positive test deliberately accepts an arbitrary `x.example` host when those two strings agree (`tests/citation-web-note.test.ts:187-188`). A citation-detail, review, index, or malicious page can satisfy both without being the work’s own page. The host checks themselves correctly reject subdomains and lookalikes, and arXiv ids/versions are constrained to arXiv’s `abs|pdf|html` routes (`src/citation-web-note.ts:284-316`), but the generic DOI branch cannot establish page ownership. Before shipping the absolute copy in `docs/project/bibliography.md:325-334` and the help page, either restrict this branch to provenance code can verify (resolver/arXiv plus registry-derived publisher/repository hosts), or explicitly weaken the product promise. I did not choose that wider product trade-off.

3. **P1 — fixed: the post-allowance reread did not reread all facts that make a press free or make the selected page the article itself.** It reread only the note-table row while continuing to use the pre-wait owner-visible bibliography row and article. An abstract note or changed source URL landing during the wait could therefore still permit a paid call or store the article itself as a completed result. The failing reproductions are now at `tests/citation-web-note.test.ts:567-581`. After taking the lease, the press rereads the owner-visible bibliography, article, and note row, repeats all stored refusals, and re-resolves an identity if the row changed (`src/citation-web-note.ts:563-592`). Both regressions now pass and every refusal frees the lease.

4. **P2 — fixed: malformed prompt JSON could be cached as a completed negative.** `readWebNote` treated a missing `sentences` field like an empty list when `url` was null, accepted extra fields and unchecked sentence members, and could therefore turn an unreadable provider answer into a week-long `none`. The red cases are at `tests/citation-web-note.test.ts:257-265`. The reader now requires exactly `{url, sentences}`, exactly `{text, quote}` for each sentence, string members, and an empty array with a null URL (`src/citation-web-note.ts:379-402`); all malformed forms are transient and are not stored.

5. **P2 — recommendation: two simultaneous presses do not implement R4’s wait-then-reread behavior.** The PostgreSQL allowance returns `concurrency` immediately when one lease is live (`src/store/pg-rate-limit.ts:175-190`), and the feature immediately turns that into a 429 (`src/citation-web-note.ts:491-498,550-554`). The route integration test explicitly pins the second press to 429 (`tests/citation-web-note-route.test.ts:261-277`), while the comment claims that it waited and then found the first result (`src/citation-web-note.ts:563-565`). This prevents duplicate spend, but it does not give the second press the first press’s stored answer as amended R4 says. A correct fix needs a disconnect-aware wait/claim contract around the shared database allowance (not an in-process mutex or blind request sleep), so I report it rather than widening this stage’s change.

6. **P2 — fixed: every 429/503/SSE failure was silently swallowed by the client.** The server already emits reader-safe copy, but `findWebNote` discarded it, leaving a press that visibly started with no outcome. I changed the existing test first; it failed until the hook retained `{id, message}` (`tests/citation-web-note-client.test.tsx:246-254`, `src/web/useBibliography.ts:654-721`). `WebNoteProgress` now renders that safe sentence as text with `role="alert"` (`src/web/BibliographyPanel.tsx:1577-1605`), and the feature doc now describes the actual transient behavior (`docs/project/bibliography.md:330-334`). Aborts remain silent.

7. **P3 — fixed: the band’s (i) could omit the required web-note sentence.** It was incorrectly gated by `showListReadNote`, so a visible web note on a list whose rows each supplied their own read-status line had no web-note explanation. The red regression is `tests/bibliography-panel.test.tsx:2385-2390`; the sentence is now controlled only by the presence of a visible web note (`src/web/BibliographyPanel.tsx:1020-1028`). I also replaced the sentence array’s index key with a stable content key at `src/web/BibliographyPanel.tsx:1520-1523`, clearing the touched-file lint error.

8. **P3 — recommendation: three requested failure/lifecycle claims are not directly protected by the stage tests.** The route suite has no registry-transient/503 case, despite the mapping at `src/citation-web-note.ts:540-544`; it does not assert that the writer and checker create cost-ledger rows, despite both jobs being routed through the tracked seam at `src/citation-web-note.ts:520,635-662`; and its response fake has an inert `on()` (`tests/citation-web-note-route.test.ts:151-180`), so it cannot reproduce a real socket close before or after streaming starts. The pure generator test covers the last paid-work behavior, and the generic AI-call/registration tests cover the ledger infrastructure, but a route could regress while those stay green. Add one route-level test for each case with a response fake that can fire `close`.
