1. **P1 — A failed reading-time GET is treated as “read nothing.”** The plan defines `ready` as settled “success or failure,” then uses an empty map as a genuine empty result ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/docs/plans/260930e-quiz-only-asks-about-what-you-have-read.md:61)). After a network failure, previously stored reading disappears from the filter and the UI falsely says none has been read. Smallest fix: replace `ready` with `status: "loading" | "loaded" | "failed"`; filter and calculate the percentage only after `"loaded"`, and fall back to the ordinary unfiltered quiz with an unavailable message after `"failed"`.

2. **P1 — The derived opening index can silently change the question under an answer or mark.** The plan leaves `at` pointing to excluded question 0 while deriving the first included question for display ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/docs/plans/260930e-quiz-only-asks-about-what-you-have-read.md:86)). If an earlier question subsequently becomes read, the derived question jumps back to it while `typed`, dictation state, and any in-flight attempt still belong to the former question. Smallest fix: commit the first included full-array index into `at` before making the question interactive. Every transition that excludes the current question must go through `move`; if the included set is empty, explicitly abort/clear the attempt and draft before showing the empty state.

3. **P1 — “Levels only rise while the page is open” is not a safe invariant.** It is true during one continuously enabled effect: the opening GET is merged with local credit ([useReadingTime.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/src/web/useReadingTime.ts:307)). A metadata re-mount or slug change also remounts Quiz, so no draft crosses that reset. But changing the experimental switch reruns the effect and clears levels without unmounting Quiz ([useReadingTime.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/src/web/useReadingTime.ts:175)); re-enabling can also expose the previous `ready`/levels for one render before the effect resets them. Smallest fix: scope the invariant to one `{slug, enabled}` run and specify the enabled/off/on transition as a filter transition, with loading state keyed synchronously to that run and current-question preservation handled explicitly.

4. **P1 — Removed evidence blocks can incorrectly qualify as read.** Reading-time GET returns totals for every historical block identity, including blocks absent from the current revision ([pg-reading-time.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/src/store/pg-reading-time.ts:27)). `useReadingTime` assigns missing blocks a zero-word reading time, so old IDs readily become level 4 ([useReadingTime.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/src/web/useReadingTime.ts:195)). A stale quiz can therefore include a question whose evidence no longer exists and describe it as about a passage already read. Smallest fix: `questionIsRead` must also require every evidence ID to exist in the current `words`/block map; alternatively, disable this filtering entirely for `owner.stale`. Outdated-but-not-stale quizzes remain safe.

5. **P2 — “All words in the piece” makes the percentage disagree with the project’s article-reading policy and with Quiz’s source.** It includes footnotes and bibliographies, while the established reading total is body words only ([block-policy.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/src/block-policy.ts:184)), and Quiz is generated only from body evidence ([quiz.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/src/quiz.ts:904)). A reader can read the whole argument and every quizzable passage yet remain well below 100% because they skipped a long bibliography. Smallest fix: use `countsTowardReadingTime` for both numerator and denominator, and define the zero-body-word case.

6. **P2 — “No change to published wording” leaves the stated purpose incomplete.** Nothing new is stored or sent, but the stored totals gain two new uses: estimating progress and deciding which quiz questions appear. `/privacy` currently says they are kept so the outline and margin can show where the reader has been ([PrivacyPage.tsx](/home/greg/code/spideryarn2/.claude/worktrees/fb61-what-you-have-read/src/web/PrivacyPage.tsx:213)). Smallest fix: update that bullet and the privacy project doc to mention the percentage and quiz filtering; the “nothing new stored or sent” claim can remain.

Verdict: revise before build; `level >= 3`, requiring every current evidence block, the filtered premise rule, verdict map, included-only numbering, and included-only list are otherwise sensible.
