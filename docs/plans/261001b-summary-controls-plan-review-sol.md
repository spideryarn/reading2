1. **P1 — The proposed profile handling contradicts Simple’s fingerprint contract.**  
   Evidence: Simple currently hashes the “exact article bytes and user message” ([simple-summary.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/simple-summary.ts:211)), and the fingerprint includes `renderPrompt()` ([simple-summary.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/simple-summary.ts:237)). The plan changes that message by appending the profile while keeping the profile outside the stamp ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/docs/plans/261001b-summary-controls-in-one-row-and-two-plain-words-levels-shaped-by-profile-and-goal.md:141)). If the fingerprint hashes the actual profiled message, the pipeline’s profile-free expected stamp ([pipeline.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/pipeline.ts:3878)) will consider a newly written artefact stale. If it does not, “exact request” becomes false.  
   Concrete fix: redefine the fingerprint explicitly as the article plus profile-free base prompt, with profile variance recorded only in `profileHash`. Build the actual message separately. Add a test proving two profiles produce different request bytes and hashes but the same `sourceHash`, and that a profiled generated artefact matches `STEPS.simple.stamp`.

2. **P1 — Metadata can report a malformed `simple/2` artefact as current.**  
   Evidence: the owner loader validates the stored paragraphs today ([pg.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/store/pg.ts:3700)), but Metadata’s `isCurrent` branch only checks that JSON exists and that its stamp matches ([pg.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/store/pg.ts:3197)). A `simple/2` row with one missing or invalid level could therefore show as done while `/api/simple` returns 404 and the public DTO omits it.  
   Concrete fix: make the metadata branch require `isSimpleLevels(simple.levels)` before comparing stamps. Use that same guard in `store/artifacts.ts`, `loadSimpleSummary`, sharing inventory, and the public projection. Test a malformed current-version row across all four paths, including Metadata reporting it not done.

3. **P1 — Fuller is missing from the activation boundary design.**  
   Evidence: `ModeBoundary` relies on `bandTarget` to retire an armed run when rendering fails ([ModeBoundary.tsx](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/web/reader/ModeBoundary.tsx:136)), but `bandTarget` currently recognises only `summary === "simple"` ([activation.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/web/activation.ts:594)). The plan’s client-stage file list does not name `activation.ts`. If Fuller arms `simple` and its render fails before `useAutoRun` claims the token, the pending token can survive and be spent later.  
   Concrete fix: map both `simple` and `fuller` to the `"simple"` target and update the activation comments. Test both pills for: click arms; URL/Back/last-view arrival does not arm; a boundary failure retires the token; clicking an already selected pill re-arms. `ModeBoundary`’s reset key already includes the parsed Summary value, and last-view already retains `summary`; add Fuller cases rather than new machinery.

4. **P1 — The one-call decision rests on incorrect token evidence and does not measure its new atomic failure mode.**  
   Evidence: the plan estimates roughly 350→800 output tokens and only a few extra seconds ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/docs/plans/261001b-summary-controls-in-one-row-and-two-plain-words-levels-shaped-by-profile-and-goal.md:117)), but the existing one-level valid runs already report roughly 845–920 output tokens for high-15-v2 ([results-260930.md](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/evals/simple/results-260930.md:62)). An earlier run also lost the entire answer because it exceeded the word cap by 19 words ([results-260930.md](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/evals/simple/results-260930.md:184)); with two independently validated levels, either level can discard both.  
   Concrete fix: retain one call as the initial simpler design, but make a combined-output pilot a go/no-go gate. Record billed output tokens, visible words, latency, cost, and valid-both rate over repeated runs. Predeclare an acceptable failure threshold. Split calls, or add a narrowly specified repair strategy, only if the combined call fails that gate.

5. **P1 — The proposed evaluation does not isolate the reading goal or adequately test no-profile compatibility.**  
   Evidence: the claim says the goal changes what the summary leads with ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/docs/plans/261001b-summary-controls-in-one-row-and-two-plain-words-levels-shaped-by-profile-and-goal.md:133)), but the experiment uses one combined synthetic profile and goal ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/docs/plans/261001b-summary-controls-in-one-row-and-two-plain-words-levels-shaped-by-profile-and-goal.md:208)). The judge question about “what they already know” tests background adaptation, not goal-led emphasis. The no-profile arm is generated, but no stated comparison tests whether it remains as plain as the current prompt. Repetition is also unbalanced: “before twice” while the after count is unspecified.  
   Concrete fix: hold About fixed and compare no goal, goal A, and a meaningfully different goal B; predeclare the concepts each About says are known and the claims relevant to each goal. Run equal repeats for every arm. Judge background omission, goal-led emphasis, faithfulness, and before-vs-after no-profile plainness separately. Score Simple and Fuller separately for claim coverage and complexity, alongside the operational measurements in finding 4.

8. **P2 — The literal prompt concatenation omits a separator.**  
   Evidence: `renderPrompt()` ends in a period ([simple-summary.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/simple-summary.ts:206)), while `profileSection()` begins immediately with `=== WHO IS READING THIS ===` and deliberately supplies no leading newline ([profile.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/profile.ts:212)). The plan’s `renderPrompt() + profileSection(profile)` would produce `article.=== WHO...`.  
   Concrete fix: append `\n\n${section}` only when the section is non-empty. Test the exact profiled delimiter and retain the planned byte-for-byte equality test for no profile.

9. **P2 — The two identically shaped segmented controls use conflicting selection semantics; the current scalar depth model supports a simpler design.**  
   Evidence: the plan says the joined shape communicates “one choice,” then makes Parts/Sections cumulative while Simple/Fuller is exclusive ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/docs/plans/261001b-summary-controls-in-one-row-and-two-plain-words-levels-shaped-by-profile-and-goal.md:77)). The underlying `deep` state is one scalar value ([params.ts](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/web/params.ts:1131)), and the current controls expose exactly one pressed depth ([SummaryPanel.tsx](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/web/SummaryPanel.tsx:213)). Lighting two buttons does not add state; it only introduces a second selection grammar. The compact badge also explicitly documents itself as Glossary-only today ([WrittenForYou.tsx](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/web/WrittenForYou.tsx:45)).  
   Concrete fix: keep Parts/Sections exclusive—Sections still renders parts because it is the selected depth—and keep Simple/Fuller exclusive. This yields one row and one interaction model with less CSS and simpler `aria-pressed` semantics. If cumulative lighting is a firm product requirement, visually distinguish it as a ladder rather than making both groups look identical. Use the existing `.sr-only` class for legends, not `hidden` or `display:none` ([chat-actions.css](/home/greg/code/spideryarn2/.claude/worktrees/fb7a-summary-controls-and-levels/src/web/styles/chat-actions.css:187)), and add accessible-name and keyboard tests. If compact provenance expands beyond Glossary, update its invariant and ensure the changed-profile state is also stated visibly in the panel.

Verdict: revise before build. The shared `PROFILE_RULES`/`profileSection` choice, profile-change policy, public projection, and owner-shaped visitor output are consistent with the existing profiled artefacts and privacy copy; the public DTO must continue stripping `profileHash`. The one-call/two-level artefact is still the simplest viable server design, but it needs an operational gate rather than the current estimates. The blocking plan defects are the fingerprint/stamp contradiction, the malformed-artefact Metadata success path, the missing Fuller activation-boundary mapping, and an evaluation that does not isolate the goal it claims to test.
