## P1

- **The active bar must explicitly opt out of the container-count system.** With `container-type: normal`, `.blk-gutter` stops being eligible for the height queries at [gutter.css:201](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:201). The browser does not query the viewport; it searches for the nearest eligible size-container ancestor. There is none in the current reading-table ancestry, so both the positive queries at [gutter.css:501](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:501) and the negated one at [gutter.css:550](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:550) fail to apply. The base rules then leave most controls `display:none`, generally showing only “…” ([gutter.css:465](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:465)). The existing `(hover:none)` reveal changes only opacity and pointer events, deliberately not display ([gutter.css:803](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:803)). It also means the one-slot rule that hides `.blk-cmt` behind “…” on an active row no longer runs. The phone-active rule must therefore explicitly:

  - show each real control;
  - hide `.blk-more`;
  - restore active marks’ pointer events and count spans;
  - avoid relying on the absence of an outer size container.

  The planned test currently promises only to pin orientation and parent pointer events ([plan:126](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/docs/plans/261018g-phone-portrait-gutter-icons-above-the-paragraph.md:126)); it should also assert those child-level outcomes.

- **Turning the existing gutter box into the bar displaces the reading-time strip and requires several special-case resets.** `span.blk-read` is absolutely positioned against `.blk-gutter`, with `right:100%` and `top:0; bottom:0` ([gutter.css:995](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:995)). Once that parent becomes a wide, short bar, the hairline moves to the bar’s left edge and becomes bar-height—not the promised vertical trace beside the paragraph. Headings also impose `top:0`, bottom alignment and `align-content:end` ([gutter.css:363](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:363)); the existing open-panel code already documents why headings need an explicit override ([gutter.css:898](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:898)). Footnotes have their own higher-specificity `right` calculation ([footnotes.css:105](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/footnotes.css:105)).

  The cleanest implementation is a small `.blk-actions` wrapper around the controls, leaving `.blk-gutter` as the narrow, row-height strip and size container, with `.blk-read` as its sibling. Only `.blk-actions` becomes the horizontal floating bar. This avoids changing container ownership and preserves the hairline. It does require adjusting the focus query currently written as `:scope > *` in [BlockGutter.tsx:421](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/BlockGutter.tsx:421).

  Give the active bar an explicit `z-index:3`, matching the existing open panel ([gutter.css:861](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:861)). The active row is later than the previous row and therefore usually paints later, but coarse-pointer controls in that previous row already carry `z-index:1` ([gutter.css:1074](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/gutter.css:1074)); leaving the bar at `auto` makes the overlap depend on stacking details. It should remain below the sticky table head (`25`) and controls (`40`), so the acknowledged top-of-screen occlusion remains unchanged.

- **Making visible state marks inert is a noticeable regression, and it is unnecessary.** The bookmark mark currently opens its comment directly ([BlockGutter.tsx:566](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/BlockGutter.tsx:566)); a blue chat mark directly opens its conversation ([BlockGutter.tsx:646](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/BlockGutter.tsx:646)). The accepted two-tap cost in the touch policy applies to hidden *affordances*, while bookmark/chat marks are explicitly *state* ([touch.md:520](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/docs/project/touch.md:520), [touch.md:562](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/docs/project/touch.md:562)). Turning a visible “you have something here” mark into a first-tap-only selector is likely to feel broken.

  Cheap better option: leave the marks interactive while keeping the empty strip `pointer-events:none`. Retain a 24×24 invisible target, allowed to overhang the 17.6px strip by 6.4px into the prose, while drawing the glyph centred in the strip. Hide counts at rest and restore them in the active bar. This preserves the familiar one-tap path and the existing target floor.

## P2

- **The media condition is sensible for the current interaction model, but it does not literally mean “phone portrait.”** `(max-width:731px) and (hover:none)` means “a narrow viewport whose primary input cannot hover.” A full-width portrait iPad is excluded, but an iPad in a narrow split view is included; an attached Magic Keyboard does not change iPad’s primary `hover` value ([touch.md:568](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/docs/project/touch.md:568)). A touchscreen laptop is excluded because its primary pointer normally hovers, which is correct while mouse-hover and touch-selection share one `row-active` state ([touch.md:575](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/docs/project/touch.md:575)). Keep the condition, but describe the scope as “narrow non-hover viewport,” not as a reliable phone/iPad distinction. `any-pointer:coarse` would be semantically broader but is unsafe without separating hover state from touch selection.

- **No ordinary phone-width JS change is required, but `proseAloneMaxPx` and its tests cease to describe every layout.** The cap explicitly includes one full gutter slot ([layout.ts:188](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/layout.ts:188), [layout.ts:214](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/layout.ts:214)). At the normal 16px root, a phone’s available width is below the 808px cap, so changing the pads affects the actual prose exactly as intended and the cap is irrelevant. At a small root and a viewport near 731px, the cap can bind and will be roughly the reclaimed width looser than necessary. That does not clip prose, but it leaves extra cell width and makes the “cap is loose by less than one rem” test’s claim phone-inaccurate ([gutter-target-size.test.ts:761](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/tests/gutter-target-size.test.ts:761)). I would keep JS unchanged, document that this is the desktop/base cap, and add a small-root phone check.

  The other consumers already use the live tokens rather than fixed totals: phone controls and masthead follow `--text-pad-l` ([narrow-window.css:175](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/narrow-window.css:175), [narrow-window.css:233](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/narrow-window.css:233)), while text-alone and mode masthead centring carry both pad values algebraically ([narrow-window.css:1312](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/narrow-window.css:1312), [narrow-window.css:1407](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/styles/narrow-window.css:1407)). Those remain sound when the pads shrink or differ.

One simplifying correction: there are at most four real controls, not five—the mark and bookmark affordance are mutually exclusive ([BlockGutter.tsx:519](/var/tmp/spideryarn-worktrees/fbk49y3q-phone-gutter-icons/src/web/BlockGutter.tsx:519)).
