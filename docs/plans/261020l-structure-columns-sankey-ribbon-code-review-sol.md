# Code review: Structure columns Sankey ribbon

1. **Medium — The capacity effect watches the fixed grid-item wrappers, not the measuring lists, and does not remeasure on font completion.** The comment says each measured list is observed, but `measureRef.current.children` are the two `.struct-side` wrappers; as stretched grid items inside an absolutely inset grid, their border boxes can stay fixed while their lists and row heights change. The effect also omits `onFontsChanged`, although the revised plan says the measuring lists already make that unnecessary. A late font swap can therefore leave `cap` based on the old row heights, particularly when there is no ribbon or its rounded visible endpoints do not change enough to cause a render. Evidence: `src/web/StructurePanel.tsx:713-719`; `docs/plans/261020l-structure-columns-sankey-ribbon.md:99-101`. Change: observe the two `[data-struct-measure]` lists themselves, subscribe the capacity measurement to `onFontsChanged`, and clean up both subscriptions.

2. **Low — `ribbonFrom` accepts vertically out-of-grid boxes despite its stated geometry contract.** It validates finite, positive boxes and some horizontal relationships, but never checks that the marked row, header, and list are vertically inside the grid. A stale or mismatched rect can therefore produce negative `aTop`/`bTop` or an edge below the grid, while the function and plan claim that out-of-grid geometry returns `null`. Evidence: `src/web/structure-ribbon.ts:75-90`; `docs/plans/261020l-structure-columns-sankey-ribbon.md:46-48`. Change: reject any contributing box outside the grid (with the existing one-pixel layout tolerance) and add tests for every vertical boundary.

3. **Medium — The marked source row has no visible hover-background response.** The new source-row selector has much higher specificity than `.struct-row:hover`, so its grey background wins in both source order and specificity; the current row already has the hover rule's ink colours, leaving pointer hover without the established background response in either theme. Keyboard focus still has its outline, but mouse and tap-reveal users lose the row's normal interaction feedback. Evidence: `src/web/styles/structure-mode.css:166-171`, `src/web/styles/structure-mode.css:270-282`. Change: add an equally scoped `:hover` rule that restores `--surface-raised`; keep the focus outline and all dimensions unchanged.

4. **Low — The tests prove the visible-row selector and one observed endpoint, but not several required cases.** They do not assert that A's list, B's header, B's list, and the grid are all observed; do not cover the capacity measuring lists or font subscriptions; do not check observer/listener cleanup; and do not reject out-of-grid geometry. The plan review required a capacity/window change, but the implementation accounting omits it and no test changes capacity. Evidence: `tests/structure-ribbon.test.tsx:148-169`, `tests/structure-ribbon.test.tsx:172-219`; `docs/plans/261020l-structure-columns-sankey-ribbon-plan-review-sol.md:17-19`; `docs/plans/261020l-structure-columns-sankey-ribbon.md:107-109`. Change: extend the scoped test with geometry-boundary, complete observer-set, capacity-window, font-redraw, and cleanup assertions, and update the plan's evidence sentence.
