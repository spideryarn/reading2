1. **P2 — The sub-mode is the best option, but one argument for it is false.** The plan says folding links into Bibliography would require a model call or migration (`docs/plans/261011d-sources-links-sub-mode-the-articles-own-hyperlinks.md:74`). A derived “Other links” section could be appended in the browser without either. It would still be worse: mixed row semantics, an awkward empty Bibliography, and hidden links when no bibliography exists. **Fix:** retain the sub-mode, but base the decision on those product costs; remove the model/migration claim. There is no better third option.

2. **P1 — `sameTarget` is insufficient for the advertised Bibliography join.** It compares exact HTTP request targets apart from fragments (`src/urls.ts:625-647`). Bibliography deliberately canonicalises DOI-bearing publisher links to `doi.org` and arXiv links to `/abs/…` (`src/bibliography.ts:1287-1293`, `src/bibliography.ts:1344-1358`). Thus common pairs such as `science.org/doi/10.…` versus `doi.org/10.…`, or `arxiv.org/pdf/…` versus `arxiv.org/abs/…`, will miss “In Bibliography.” **Fix:** match by `sameTarget` first, then by DOI/arXiv identity when `linkFrom` is `doi` or `arxiv`, using the existing browser-safe identifier readers. Add publisher-DOI and arXiv PDF/HTML tests. Also correct the nonexistent `linkFrom: "anchor"` in the plan to `"article"` (`src/types.ts:4935-4946`).

3. **P2 — The current second-parser approach is security-safe, but its claimed parity is inaccurate and underspecified.** Parsing into an inert browser `<template>`, reading raw `getAttribute("href")`, and resolving with `new URL`, `isWebUrl`, and `sameTarget` is sound; it neither executes the article nor reaches the server. A shared parser-injected core would also work in jsdom and browsers, but leaving the fetch allowlist untouched is a reasonable scope choice. However, the new parser deliberately rejects credential-bearing URLs and does not preserve `articleLinks`’ 80-character label bound (`src/web/outbound-links.ts:55-69`, `src/web/outbound-links.ts:93-107`; `src/chat-tools.ts:1126-1148`). **Fix:** document the exact divergence, preferably reject all `carriesCredential` URLs, bound displayed phrases, and test browser/jsdom parity only for the rules intended to match. Add a public-network trace proving opening Links issues no request.

4. **P2 — Visitors do not actually get the same feature as owners.** The plan promises that at `docs/plans/261011d-sources-links-sub-mode-the-articles-own-hyperlinks.md:47-50`, but explicitly leaves Sources gated on stored artefacts at lines 158-161. `POLICY.sources` requires Bibliography, Reception, or Claims (`src/web/visitor.ts:320-346`), and `Reader` mounts `VisitorSourcesBand` only when one exists (`src/web/reader/Reader.tsx:3752-3767`). **Fix:** make Sources visitor-available and always mount `VisitorSourcesBand`; its visitor arm mounts no fetching/job hooks. Then a public article with only prose links can open Links. Update visitor-gap, shared-inventory, and no-network tests.

5. **P1 — The proposed PDF empty state makes a claim the public type explicitly forbids.** The plan equates absent `meta.url` with a PDF (`docs/plans/261011d-sources-links-sub-mode-the-articles-own-hyperlinks.md:165-169`). For visitors, absent URL may instead mean the source address failed publication policy (`src/public-types.ts:149-164`). The reliable owner-side PDF signal is `Meta.source === "pdf"` (`src/types.ts:1827-1830`), and it does not cross publicly. **Fix:** owners may get the PDF-specific sentence only from `meta.source`; visitors need neutral copy such as “This piece has no web links in its text.”

6. **P2 — The wiring inventory misses visible copy and several non-compiler-checked enumerations.** `MODE_CATALOG.sources.how` still describes only Bibliography, Reception, and Claims (`src/mode-catalog.ts:486-522`), and the shared-link explanation does too (`src/messages.ts:4435-4440`). Tests explicitly enumerate Sources views in the command bar (`tests/command-bar-sub-modes.test.tsx:566-629`), URL parsing (`tests/url-state.test.ts:289-305`), last-view restoration (`tests/last-view.test.ts:113-130`), band containment witnesses (`tests/a-broken-mode-leaves-the-article-readable.test.tsx:1487-1495`), paid-work checks and rendered surfaces (`tests/every-mode-draws-its-surface.test.tsx:1256-1268`, `1572-1586`), and visitor network traces (`tests/public-network-trace.test.tsx:2195-2213`). **Fix:** name these in the plan and update them explicitly. No logic change is needed in `item-focus`, `thread-source`, reruns, `Dock`, auto-modes, `ModeBoundary`’s table, or `Reader.subModeViews`; their generic/default behavior already handles Links.

7. **P2 — The row count wording is inaccurate, and hostile/accidental long labels need bounds.** Rows deduplicate block IDs (`src/web/outbound-links.ts:97-101`), so “linked 3 times” in the mock-up (`docs/plans/261011d-sources-links-sub-mode-the-articles-own-hyperlinks.md:23-24`) really means “linked in 3 paragraphs”; two links in one paragraph count once. Phrase text and the number of alternative phrases are currently unbounded, unlike chat’s deliberate cap (`src/chat-tools.ts:145-151`). **Fix:** say “in 3 paragraphs,” cap each displayed phrase, show only a small number of alternatives followed by “+N more,” and use “destinations” in the chip’s accessible count to avoid “Links, 61 links.”

VERDICT: build with the fixes above
