1. **High — D2 resolves the starter before `createVoucher`, breaking replay-first semantics.** The plan says to resolve or create the link before calling `createVoucher` ([plan:71](/var/tmp/spideryarn-worktrees/fbcwb56b-mcp-admin/docs/plans/261010r-mcp-gift-any-article-and-send-makes-the-link.md:71)), but `createVoucher` deliberately checks for an existing voucher before examining the live article ([pg-vouchers.ts:490](/var/tmp/spideryarn-worktrees/fbcwb56b-mcp-admin/src/store/pg-vouchers.ts:490)). A replay of a frozen gift whose voucher already committed must succeed even if the article was subsequently deleted or its link turned off. Under D2’s ordering, such a replay can instead return 409, fail to reschedule a still-queued email, or—with an earlier `rightsConfirmed: true` body—turn a deliberately disabled link back on. Proposed change: call `createVoucher` first inside `runAsOwner`; only when that returns `starter-refused/link-off` and this request carries `rightsConfirmed: true` should Send create the link and retry `createVoucher`. Handle all final structured starter refusals through the existing attempt-token-and-no-voucher unfreeze ([pg-author-gifts.ts:1088](/var/tmp/spideryarn-worktrees/fbcwb56b-mcp-admin/src/store/pg-author-gifts.ts:1088)). Add tests for a frozen gift with an existing voucher, link off/absent article, both values of `rightsConfirmed`, and a queued delivery requiring replay scheduling.

2. **High — D1 loses the article-identity check when accepting `link-off`.** Today `ensureAuthorGift` compares the ready starter’s `articleId` with the article found by its first read, preventing a freed slug from silently becoming a gift for another article ([pg-author-gifts.ts:189](/var/tmp/spideryarn-worktrees/fbcwb56b-mcp-admin/src/store/pg-author-gifts.ts:189), [pg-author-gifts.ts:201](/var/tmp/spideryarn-worktrees/fbcwb56b-mcp-admin/src/store/pg-author-gifts.ts:201)). `StarterResolution`’s `link-off` case carries no article id ([voucher-starter.ts:55](/var/tmp/spideryarn-worktrees/fbcwb56b-mcp-admin/src/store/voucher-starter.ts:55)), so simply accepting it as D1 proposes removes that check. The gift then retains the first article’s id but the contested slug ([schema.ts:7035](/var/tmp/spideryarn-worktrees/fbcwb56b-mcp-admin/src/db/schema.ts:7035)); Send could make a link and email the replacement article. Proposed change: make a link-off resolution carry `articleId`, preserve the comparison in `ensureAuthorGift`, and make the author-gift call to `createVoucher` use an identity-checking resolver that maps any different article id to `absent`. Test both a slug swap during ensure and a reused slug between draft and Send.
