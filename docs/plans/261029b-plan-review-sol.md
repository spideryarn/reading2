2. **Medium — starting from a valid citation reduces false positives but does not prevent them.**  
   **Evidence:** The drafted parser reads both names in `(Smith 2020, Kenya 2021)`, `(Smith 2020, Paris 2021)`, and `(Smith 2020, Release 2021)`. In prose such as “The rollout followed Smith’s protocol (Smith 2020, Kenya 2021),” `Kenya 2021` can be a place and date rather than a work. The proposed negative test `(founded in 2019, Kenya 2021…)` proves only that a bare year cannot start the chain; it does not test ambiguity after a real citation. Because continuations are marked `parenthetical`, the narrative/lone article threshold does not filter them. A false hit therefore becomes a visible `rowsFromText` row, mention, `citedAt` jump, Scholar search, and potentially an inherited `authorYearAlias`.  
   **Suggested change:** State this unavoidable grammatical ambiguity and add a negative corpus/test beginning with a genuine citation. Either explicitly accept it based on measured precision, or require independent corroboration—such as a matching reference-list entry, another occurrence, or a model row. Expanding `NOT_A_NAME` is not a general solution.

3. **Low — the other named interactions are mostly sound, but one integration seam deserves a test.**  
   **Evidence:** `ENTRY_LINE` is not newly defeated: a matching entry already supplies a narrative hit, while continuation requires a separate parenthetical hit, so `found.size` was already above one.    **Suggested change:** Add a `rowsFromText` or `buildBibliography` test with a model row whose only identity is a whole-list mention, asserting the intended duplicate/coverage behavior and exact `mentions`/`citedAt`.
