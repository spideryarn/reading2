Revise before implementation. Findings, highest severity first:

1. **P1 — Bare commits need content checks, not path membership.** A source can be staged and also have unstaged edits (`MM`). The guard admits its pathname, but the generator reads the unstaged version. Reproduced in `/tmp`: committed source was `ready`; generated output was `unfinished`. Require working-tree bytes and file presence to match what the commit will carry, including deletions.

2. **P1 — “Already included” is wrong for bare commits.** [Step 3](/var/tmp/spideryarn-worktrees/generated-files-fresh/docs/plans/261007q-generated-files-regenerate-on-commit.md:44) skips an output already staged, even when regeneration changed its working-tree bytes. Comparing against `HEAD` also misses an incorrect staged output when regeneration restores the HEAD version. For bare commits, compare against the **index** and stage the verified generated bytes whenever they differ, regardless of path membership.

3. **P1 — The PNG parser is insufficient for granting `allow`.** Its whitelist accepts both `git add -A && git commit …` and `git commit … && git add -A`. Returning `allow` approves that whole Bash invocation, including staging peers’ files. Restrict approval to a validated house recipe: literal leading `cd`, optional check, optional `git add -- <explicit files>`, then one commit, with no trailing commands. Preserve every unchanged input field. Correct precedence to `deny > defer > ask > allow`; `updatedInput` also works with `ask`. [Claude hook contract](https://code.claude.com/docs/en/hooks#pretooluse-decision-control).

4. **P2 — The source sets omit actual inputs.** Help output also depends on `src/title-text.ts`, `src/messages.ts`, `src/modes.ts`, and `src/web/router.ts`. Generator changes themselves must trigger regeneration: `tests/help-corpus.test.ts`, `scripts/feedback-endings.ts`, and relevant imported helpers. Otherwise an excluded dirty dependency can enter the generated output despite the guard. Maintain one explicit dependency manifest for triggering **and** guarding.

5. **P2 — Failure and concurrency guarantees exceed the implementation.** Help writes directly during a test run; another assertion can fail while its write test still executes. Feedback writes its two outputs sequentially. Neither provides rollback or atomic replacement, and the source guard can become stale during generation. Specify temporary output, success-only atomic installation, source/output fingerprint rechecks, and index-entry checks before staging. Add tests for partial staging, concurrent edits, deletion/rename, subdirectory invocation, and failure after the first output. The current stub tests alone won’t prove these guarantees.

6. **P2 — The build rejection reaches a reasonable conclusion using incomplete reasoning.**
   - **Feedback endings:** keeping it committed is justified by the git-based shipped-email reader.
   - **Feedback questions:** it has no corresponding git-reader requirement; build generation is technically possible.
   - **Help:** a prebuild Vitest invocation could reuse the existing generator; a second Vite generator is unnecessary. Keeping JSON committed also avoids the fresh-worktree problem.
   
   The actual obstacle is `.vercelignore`: it excludes **both `tests/` and `docs/`**, and Vitest’s configuration imports further test files. Running these generators during Vercel builds unchanged therefore fails. Build generation also leaves the original stale-commit/test-gate problem unresolved.

On Git’s own hooks: **a pre-commit hook can add an omitted generated path** through Git’s temporary index. I verified that it enters the path-limited commit, but the real index retains the old blob, leaving a **staged revert** afterward. Avoiding that needs careful index reconciliation; it is not a simpler safe alternative. [Git’s partial-commit implementation](https://raw.githubusercontent.com/git/git/master/builtin/commit.c).

On parser sharing: **worth doing once the parser is tightened**. Share parsing only; keep PNG selection and staging behavior separate. Its existing tests are a regression baseline, not proof that the parser safely grants permission.

Finally, call this **best-effort freshness**, not “impossible to be stale”: errors, timeouts, dirty peers, and ordinary `git commit … && git push` commands all remain uncovered.
