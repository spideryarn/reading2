## Findings

1. **Medium — The intended fact order is contradictory and the tests would not catch it.** The plan says journal and date go “after the site” while also matching the existing Metadata pages ([plan](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/docs/plans/261015c-why-you-are-reading-higher-in-metadata-and-the-publication-date-in-the-masthead.md:53)). Those pages currently use `byline → journal → site → date`, not `site → journal → date` ([PublicPages.tsx](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/src/web/PublicPages.tsx:137)). The example omits the site, and the proposed test merely checks that strings occur ([masthead-published-and-counts.test.tsx](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/tests/masthead-published-and-counts.test.tsx:90)). Choose one canonical order and test the sequence. The test should also cover a visitor’s journal and `journalBesideSite` suppressing a duplicate journal/site.

2. **Medium — The rejected simpler option is dismissed on faulty grounds.** Greg said “maybe hide”, not that a disclosure was required. The plan says deleting parts and sections is insufficient because the word count is occasionally useful ([plan](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/docs/plans/261015c-why-you-are-reading-higher-in-metadata-and-the-publication-date-in-the-masthead.md:72)), but that alternative leaves the word count intact. The simpler version is: add journal/date, retain words and read time, and remove parts/sections from the masthead; those counts remain under Metadata › At a glance. This avoids another stateful control among two existing controls. If masthead access to all counts is an explicit requirement, the proposed disclosure is reasonable.

3. **Low — The keyword move lacks its relevant regression test.** The plan promises that `purpose reason goal why intent` move to the new section, but its test list only checks section order. Add real-page cases such as `purpose → Why you're reading` and retain `resume → Your reading` in [metadata-contents-reveal.test.tsx](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/tests/metadata-contents-reveal.test.tsx:471); update the copied section inventory in [page-search.test.ts](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/tests/page-search.test.ts:29).

4. **Low — The disclosure is visually consistent, but its controlled content should be explicit.** A native text button, `type="button"`, changing label, `aria-expanded`, `ControlTip`, and the existing facts-line styling match `FrontMatterButton`. If retained, add a stable controlled-region ID and `aria-controls`. Prefer putting the revealed region after the button in DOM order; as drawn, the counts appear before the focused button, so a screen-reader user expanding it may pass over the newly inserted content.

The visitor path is correctly understood: `resolveAccess` preserves the public payload’s `PublicMeta` while adapting the article to `Article` ([access.ts](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/src/web/article/access.ts:429)), and that article reaches the same `Masthead` ([Reader.tsx](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/src/web/reader/Reader.tsx:4304)). Therefore the masthead must read `published`, not just `publishedAt`; the plan does.

Moving the purpose box is otherwise safe. Its autosave hook remains above the layout, `article-purpose` can stay unchanged, the contents list derives entries from `<Section>`, and `?section=` only accepts `ai-processing` and `access-sharing` ([params.ts](/var/tmp/spideryarn-worktrees/fbejzr4b-metadata-order-and-date/src/web/params.ts:1937)). No CommandBar or production code targets `Your reading` or `article-purpose` for navigation.

**VERDICT: APPROVE WITH CHANGES**
