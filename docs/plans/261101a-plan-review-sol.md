1. **High — Wikipedia truth counts citation numbers, not distinct works.** The existing hand count admits that references 24=66 and 48=49 are the same sources, yet counts them separately; the new prompt requires one row per work. A correct deduplicated answer therefore cannot reach 100% under one-to-one scoring. Evidence: [261027a-hand-count.md:4](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/evals/results/citations-recall/261027a-hand-count.md:4), [plan:90](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:90). **Fix:** canonicalize footnotes by DOI/URL/normalized entry/title, store all citation-number aliases on one truth work, and score recall by canonical work.

2. **High — the truth set mixes body citations with reference-list membership.** The plan says truth is “every distinct work the body cites” but reconciles Butlin against all 243 reference entries. The prior measurement found 22 real body citations not matching that list and 29 list entries not found in the body; production also deliberately accepts reference-only works. This can both miss true citations and label legitimate rows false. Evidence: [plan:50](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:50), [261029b:81](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261029b-citations-in-a-comma-separated-list-are-all-read.md:81), [bibliography.ts:2174](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/bibliography.ts:2174). **Fix:** adjudicate body citations independently, then classify outputs as body-cited, legitimate reference-only, or false. Store citation block/span plus canonical identity so truth remains auditable.

3. **High — pre-fold scoring can reward duplicates and misassign collisions.** `toDrafts` deliberately returns raw rows; production folds by entry, metadata, and identifier afterwards. Thus two duplicate rows can cover two same-surname/year truth works. A shared reference block can likewise credit the wrong work, and greedy one-to-one assignment would be order-dependent. The known Layfield exceptions also required manual title/metadata matching because seven rows lacked entries. Evidence: [plan:59](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:59), [bibliography.ts:729](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/bibliography.ts:729), [bibliography.ts:1882](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/bibliography.ts:1882), [261027a-hand-count.md:5](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/evals/results/citations-recall/261027a-hand-count.md:5). **Fix:** factor/reuse production’s pre-cap folds, reject surname/year fallback where that key is ambiguous, allow reference-block matching only when the block uniquely identifies one work, and use maximum-cardinality matching with exact matches preferred. Keep raw-row diagnostics separately.

4. **High — the proposed token budget throws before calling the model.** `105,400 + 40,000 = 145,400`, above 128,000. `budgetFor` throws; it does not cap. High-effort adaptive thinking has previously consumed about 64K tokens, so merely shrinking headroom is risky. The 360-second job admission budget is also justified by the old 80-row/28.4K answer. Evidence: [plan:92](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:92), [token-budget.ts:13](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/token-budget.ts:13), [token-budget.ts:198](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/token-budget.ts:198), [jobs.ts:1076](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/jobs.ts:1076). **Fix:** choose and test an answer/headroom pair totaling ≤128K, record visible versus reasoning tokens, and gate shipping on production-duration headroom. If long/high runs truncate or approach the 740-second claim deadline, splitting returns as a requirement.

5. **High — the new meaning of `capped` would make the UI lie.** The plan sets `capped: true` whenever the model “stopped before the end.” Today the field specifically means the article exceeds `MAX_CITATIONS` and the kept rows were selected by relevance; the UI would consequently say, for example, “more than 300 works” even if Haiku merely under-returned 150. Evidence: [plan:83](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:83), [types.ts:6153](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/types.ts:6153), [BibliographyPanel.tsx:617](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/web/BibliographyPanel.tsx:617). **Fix:** retain an explicit hard cap and reserve `capped` for exceeding it, or introduce a separate incomplete/under-return diagnostic with truthful copy. Gate shipping on recall after production folding and the proposed final cap, not only pre-cap recall.

6. **High — pinning the wire model alone leaves false model stamps and broken freshness.** `buildBibliography` and `BibliographyRun.model` still use `generatorFor(power)`, while both freshness seams expect `CAPABLE_MODEL`. A pinned Haiku run would be stored/logged as Sonnet or Opus; correcting only the stored stamp would then make it perpetually outdated. Evidence: [plan:103](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:103), [bibliography.ts:2051](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/bibliography.ts:2051), [bibliography.ts:2469](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/bibliography.ts:2469), [pipeline.ts:6261](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/pipeline.ts:6261), [pg.ts:3792](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/store/pg.ts:3792). **Fix:** add a Bibliography-specific model/generator constant and use it in generation, logs, pipeline stamps, and store freshness. Test standard and High-powered articles explicitly.

7. **Medium — raising the row cap expands an automatic downstream job that the cost comparison omits.** Every published Bibliography queues `citation-blurbs`; it processes every row in batches of 20 and may make one checker call per work. Moving 80→300 rows can roughly quadruple that work and exceed its deadline, producing partial results. Registry enrichment still takes only the first 80 rows. Evidence: [pg-revisions.ts:2795](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/store/pg-revisions.ts:2795), [citation-blurbs.ts:555](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/citation-blurbs.ts:555), [citation-blurbs.ts:605](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/citation-blurbs.ts:605), [citation-registry.ts:206](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/citation-registry.ts:206). **Fix:** run one full 240-row Bibliography→blurbs pipeline and report total spend, duration, and partial rows; then deliberately retain, raise, or separately prioritize each downstream cap.

8. **Medium — the ship rule is underspecified and permits regressions.** There are four ≤70-work articles, not five. A universal 95% threshold permits 35/36 and 39/40 where S0 is currently perfect, and the plan does not say whether both Haiku repetitions must pass or whether a best/mean run suffices. Absolute false-row count is also unfair between an 80-row baseline and a 240-row candidate. Evidence: [plan:38](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:38), [plan:72](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:72), [plan:100](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:100). **Fix:** require every repetition to pass; require no per-article recall regression on the four short articles; use precision/false-row rate plus zero dangerous fabrications; and blind a fixed, stratified `why` sample. Refusal, truncation, or invalid JSON must count as zero recall, not disappear from averages.

9. **Medium — cost collection and the >100K assumption need tightening.** `finalMessage()` drops OpenRouter’s cost; the established eval pattern obtains spend through `collectSpend`, which also includes retries and failed calls. Cache state/order is unspecified and can make later same-model arms look cheaper. Also, the current OpenRouter model page lists flat $0.10/$0.50 inference pricing and a 128K completion limit, rather than documenting the plan’s asserted 5× inference step above 100K. Evidence: [plan:29](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/docs/plans/261101a-citations-every-work-cheaply-with-haiku.md:29), [messages-stream.ts:40](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/src/messages-stream.ts:40), [quiz-models.ts:96](/var/tmp/spideryarn-worktrees/fbd5e2jk-citations-eval-haiku/evals/quiz-models.ts:96), [OpenRouter model listing](https://openrouter.ai/anthropic/claude-haiku-5.5). **Fix:** isolate every run with `collectSpend`, fail closed on unpriced calls, include retries/refusals, disable caching or report cold and warm costs separately, and record total prompt/cache/reasoning tokens plus the provider-reported bill rather than applying a hard-coded rate table.
