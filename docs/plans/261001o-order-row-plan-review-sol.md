## Findings

1. **High — Quotes would still wrap.** The plan puts `.quotes-rank { flex-wrap: nowrap }` in `narrow-window.css` ([plan:21](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/docs/plans/261001o-order-buttons-one-sideways-scrolling-line-on-touch-screens.md:21)), but that stylesheet loads before `quotes.css` ([styles.css:55](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/src/web/styles.css:55), [styles.css:59](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/src/web/styles.css:59)). The later, equal-specificity `.quotes-rank { flex-wrap: wrap }` wins ([quotes.css:26](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/src/web/styles/quotes.css:26)). When Quotes has its trailing badge, flex line-breaking can therefore put the trail on a second line before the group shrinks. The proposed text-scanning test would still pass because it checks that `nowrap` exists, not which declaration wins ([touch-controls.test.ts:427](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/tests/touch-controls.test.ts:427)). Move the base Quotes row rule before `narrow-window.css`, put its touch override in `quotes.css`, or give the touch selector higher specificity—and add a cascade-aware assertion.

2. **Medium — mount/selection effects do not preserve visibility after later reflow.** The component only repositions on opening and selection changes ([plan:36](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/docs/plans/261001o-order-buttons-one-sideways-scrolling-line-on-touch-screens.md:36)). Geist uses `font-display: swap`, and the project explicitly documents fonts starting after a mode mounts ([fonts.ts:22](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/src/web/fonts.ts:22)). A font swap, orientation change, changing option set, or trail appearing can move the selected button out of view without changing selection. Re-run on font completion and container/content resizing; test a reflow after initial placement. Directly changing the group’s `scrollLeft` is otherwise the right approach because it cannot scroll the band or page.

3. **Low — the planned tests miss two branches of the contract.** `coarseBlocks()` accepts both `pointer: coarse` and `any-pointer: coarse` ([touch-controls.test.ts:56](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/tests/touch-controls.test.ts:56)), so the new test would not enforce the chosen query. The component test also covers only a target to the right and one already visible ([plan:67](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/docs/plans/261001o-order-buttons-one-sideways-scrolling-line-on-touch-screens.md:67)); add the symmetric “selected button left of the viewport” case.

The remaining design is sound: `pointer: coarse` matches the query that introduces the 40px floor ([narrow-window.css:706](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/src/web/styles/narrow-window.css:706)); extending the shared wrapper to Debate and FAQ prevents drift; and `min-width: 0` plus a shrinking group and non-shrinking, auto-margined trail will pin the trail once parent wrapping is genuinely disabled. `min-width: 0` is already present ([glossary.css:52](/home/greg/code/spideryarn2/.claude/worktrees/order-row-sideways-touch/src/web/styles/glossary.css:52)), and `flex: 0 1 auto` is the default, so those proposed additions can be omitted.

**Verdict: revise before build—the overall design is good, but the Quotes cascade bug defeats the central behaviour and the visibility correction needs late-reflow handling.**
