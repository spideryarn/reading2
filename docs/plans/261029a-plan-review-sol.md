Stage 1’s client-first ordering is right, but the plan is not ready as written. “A section is the frontier” is appropriate for Structure’s display, not as a universal replacement for every existing meaning of “section.” No P0 findings.

## Findings

- **PR-1 — P1: the proposed frontier is not total and is not identical on all uniform trees.**  
  The plan excludes the root ([plan:125](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/docs/plans/261029a-structure-one-level-deeper.md:125)). A flat root→leaves tree currently gets one entry per block because `sectionDepth` clamps to 1 ([position.ts:73](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/position.ts:73)); the new rule produces no entries. In a mixed tree, a part with direct leaves currently produces nameless per-block “sections”; deepest-internal instead produces one part entry. That is probably a bug fix, but contradicts bit-for-bit identity.  
  **Fix:** define Structure’s frontier separately and explicitly cover five shapes: ordinary, root-only, part-with-direct-leaves, supplement, provisional. Call the shallow-part change intentional. Do not claim universal identity.

- **PR-2 — P1: replacing the shared section list changes persisted-position semantics and misses several consumers.**  
  `useColumnContext` publishes only when its supplied section start changes ([useColumnContext.ts:121](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/useColumnContext.ts:121)). Supplying sub-sections therefore makes the one-second hold and Structure redraw sub-section-granular. More importantly, `?at=` will canonicalise on sub-section boundaries instead of today’s section boundaries. Existing saved URLs still open their exact block—the restore path uses the block ID directly ([useReadingPosition.ts:67](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/reader/useReadingPosition.ts:67))—so there is no data loss, but later scrolling churns and rewrites differently.  
  Missed consumers include reading-position/Quiz ([Reader.tsx:866](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/reader/Reader.tsx:866)), block-link cards ([Reader.tsx:2703](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/reader/Reader.tsx:2703)), breadcrumbs ([Reader.tsx:701](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/reader/Reader.tsx:701)), ReturnChip ([Reader.tsx:5495](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/reader/Reader.tsx:5495)), and Quiz’s evidence grouping ([quiz-sections.ts:55](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/quiz-sections.ts:55)). Arrow navigation currently accepts one numeric depth, not a per-branch frontier ([keynav.ts:650](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/keynav.ts:650)).  
  **Fix:** keep `readingSections` for URL, Quiz, ReturnChip and block cards; add `structureFrontier` for Structure focus and ←/→, passing explicit start rows rather than a depth number.

- **PR-3 — P1: `buildGeometry` is not already fine.**  
  On an undeepened branch in a globally deeper tree, the leaf occupies an intermediate column with `continuation: false` because `depth === chain.length - 1` ([tree.ts:155](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/tree.ts:155)). This is exactly the defect the background plan identified.  
  **Fix:** a leaf is real only in the global leaf column; in intermediate columns mark it continuation. Add mixed-depth plus supplement geometry tests.

- **PR-4 — P1: the two-column atomic splice does not fit the existing capacity algorithm.**  
  The projection already warns that mixing detail rows into the measured/windowed list can truncate the detail and displace mandatory sections ([structure.ts:591](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/structure.ts:591)). The panel measures the full projected rows and then windows that same flat list again ([StructurePanel.tsx:617](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/StructurePanel.tsx:617), [StructurePanel.tsx:763](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/StructurePanel.tsx:763)). Sub-sections can therefore be cut in half and steal section capacity. `attachCards` also only understands “paragraph children shown” ([structure.ts:421](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/web/structure.ts:421)).  
  **Fix:** simplest is to defer the two-column splice. If built, make current-section-plus-subsections one atomic measured unit; window section siblings as units, substitute one count unit when it does not fit, and suppress the section card only when the full child unit is drawn. The DOM-measured ribbon already adapts correctly, and this preserves “never scrolls.”

- **PR-5 — P1: the headings-fallback change points at the wrong builder.**  
  `section.depth < 2` belongs to `buildHeadingTree` ([heading-tree.ts:269](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/heading-tree.ts:269)), but production fallback and `awaiting-structure` use `buildBoundedHeadingTree` ([structure.ts:2633](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/structure.ts:2633)), which explicitly emits root→parts→sections→leaves ([heading-tree.ts:585](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/heading-tree.ts:585)).  
  **Fix:** either keep provisional trees uniform, or redesign the bounded planner too, preserving its `MAX_BATCH` guarantee. Test both `headings` and `awaiting-structure`.

- **PR-6 — P1: Stage 2 does not guarantee the swallowed-2.5 fix.**  
  The current prompt says headings are hard boundaries but also targets 5–9 children ([structure.ts:114](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/src/structure.ts:114)); invariants validate tiling, not that headings became boundaries. Merely adding depth 3 lets the model put `2.5` underneath `2.4`, preserving the reported defect.  
  **Fix:** state precedence precisely: same-level author headings start depth-2 siblings; deeper headings start depth-3 children; author headings override fan-out. Add post-build checks and eval counts for swallowed same-or-shallower headings.

- **PR-7 — P1: the short-section rule contradicts the heading rule.**  
  Stage 2 says deepen when author sub-headings divide a section, but also “never split a short section,” with a target of no splits under ten blocks ([plan:165](/var/tmp/spideryarn-worktrees/fbpn7gvw-structure-one-level-deeper/docs/plans/261029a-structure-one-level-deeper.md:165)). A short section containing two real sub-headings should split under the plan’s own rationale.  
  **Fix:** author headings beat the size floor; “never short” applies only to model-invented topic shifts. Report heading-driven and invented short splits separately.

The schema recursion, start-to-range conversion, invariants, label sibling sets, checkpoint fingerprinting, question-depth enforcement, arc, and disabled deepening wave are otherwise depth-generic. The best-value smaller version is: build the separate Structure frontier, fix list/Expanded focus and styling, then allow fourth-level nodes only at author sub-headings. Greg was using Expanded, which already recurses; the risky two-column splice can wait for evidence that it is needed.
