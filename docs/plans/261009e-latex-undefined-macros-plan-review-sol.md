1. **Blocking: rules 2 and 3 can silently delete authored words.** Rule 2’s “one whitespace-free token” is not a semantic discriminator. The surveyed `\workshoptitle`, `\bmsection`, `\hohsettheme`, and `\bibliographyfullrefs` cases all have the same `div.ltx_para > error span + p.ltx_p` structure. For example:

   ```html
   <span class="ltx_ERROR undefined">\workshoptitle</span>
   <p class="ltx_p">LP4FM</p>
   ```

   deletes the real workshop title, while `\bmsection` followed by `<p>Funding</p>` or `<p>None.</p>` loses real back matter. Rule 3 is broader still: `\excite` contains “cite”, so `We \excite electrons in the sample` becomes `We in the sample`; `\citeauthor Smith argues…` becomes `argues…`. These deletions run before `protectAuthoredStructure` in [extract.ts](/var/tmp/spideryarn-worktrees/fbnhhd0x-latex-junk/src/extract.ts:822), in both extraction arms, so the prose-retention fallback cannot recover them. There is no better structural discriminator in these pages; use an exact measured allowlist—`\hohsettheme` and `\bibliographyfullrefs` for one-token paragraphs, and exactly `\ucite` for inline keys—rather than token length or `/cite/i`. This directly contradicts [the module’s existing no-authored-words rule](/var/tmp/spideryarn-worktrees/fbnhhd0x-latex-junk/src/latexml.ts:21).

2. **Rule 1 should match the diagnosed producer shape more exactly, while covering every visible prose context.** The evidence is specifically `span.ltx_ERROR.undefined` with one plain control-sequence text child; [the plan currently says any element with `ltx_ERROR`](/var/tmp/spideryarn-worktrees/fbnhhd0x-latex-junk/docs/plans/261009e-latex-undefined-macros-leave-the-page.md:74). Other LaTeXML error kinds may use `ltx_ERROR`, and removing their only visible fallback has not been measured. Require the `undefined` class and observed `span` tag. Within visible HTML, it should work in paragraphs, headings, the article-title `<h1>`, captions, and table cells: stage 3 emits headings, figures, and tables as complete leaf blocks, so nested marker text otherwise reaches the reader ([blocks.ts](/var/tmp/spideryarn-worktrees/fbnhhd0x-latex-junk/src/blocks.ts:53)). Do not apply it inside `math`, SVG, code/source, script, style, or textarea; in particular, `canonicaliseMaths` runs immediately afterwards and reads MathML annotations as TeX. The document’s `<head><title>` is outside `article.ltx_document` and therefore remains deliberately out of scope unless a real example demonstrates otherwise.

3. **Removing a marker can itself glue real words, and the survey already contains an example.** In `2610.10541`, the source has `CC BY 4.0.<span …>\conference</span>Workshop on Quality…`; plain removal produces `CC BY 4.0.Workshop…`. The three `\sep` markers similarly leave four keyword phrases with no semantic separator, and the acknowledged `\captionof` case still reads `tableThe 39…`. Add exact regression cases for these surveyed shapes. A targeted replacement such as `\sep` → `; ` and preserving a boundary around `\conference` would improve the reader result without inventing a generic spacing rule; `\captionof` needs its own measured transform if this change is meant to clean the whole class.

4. **Rule 4 is unnecessary for the measured cases and adds anchor complexity.** The `\keypart` “paragraph” is actually an empty `div.ltx_para`; Greg’s wrapper becomes the same after removing its marker and argument. Stage 3 descends through `DIV` containers and emits nothing from an empty one ([blocks.ts](/var/tmp/spideryarn-worktrees/fbnhhd0x-latex-junk/src/blocks.ts:524)), so leaving that wrapper produces the same reader output. Readability also drops these exact empty wrappers. Omitting rule 4 is simpler and preserves a potential anchor home. If it remains, tests should separately cover links to the marker ID (`#p1.1`), argument ID (`#p1.2`), and wrapper ID (`#p1`); deleting any before stage 3 prevents `retargetAnchors` from recovering it.

5. **The diagnosis is right for the marker, but too broad for its arguments.** “Converter diagnostic leaked into reader prose” names the root class well: Readability is correctly reading text LaTeXML emitted, and `prepareLatexml` lacks a recognizer. `hohRose` and the BibTeX keys, however, are unparsed source arguments, not themselves error reports; other orphaned arguments are explicitly authored and intended to remain visible. Consequently, the proposed documentation sentence saying the rule deletes “the argument it orphaned, never the author’s sentences” is false ([plan](/var/tmp/spideryarn-worktrees/fbnhhd0x-latex-junk/docs/plans/261009e-latex-undefined-macros-leave-the-page.md:131)). Document the two classes separately and name the exact technical arguments removed.

6. **The planned negative tests do not exercise the dangerous boundaries.** Add the concrete one-word real cases `\workshoptitle` + `LP4FM` and `\bmsection` + `Funding`; `\excite` + `electrons`; `\citeauthor` + `Smith`; an `ltx_ERROR` without `undefined`; visible markers in a heading, caption, and table; a marker inside MathML annotation; and the actual `\conference` adjacency. Running all surveyed error snippets through the transformation would also catch sibling degradation that the current three positive fixtures miss.

Verdict: **Revise before implementation—universal removal of the exact visible undefined-marker is sound, but argument deletion must be macro-specific and the empty-wrapper rule can be dropped.**
