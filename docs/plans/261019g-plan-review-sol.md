## P1

1. **A cross-tab text-size change can reflow the article without preserving the reader’s place.** The proposed `resize` event makes `useRootFontPx()` update ([measure.ts:154](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/reader/measure.ts:154)), but the reflow key omits the root size ([Reader.tsx:718](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/reader/Reader.tsx:718)). At widths where fitted column widths remain unchanged, every paragraph can rewrap while `layoutKey` does not change. Scroll restoration explicitly treats an unchanged key as “nothing reflowed” ([useReadingPosition.ts:155](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/reader/useReadingPosition.ts:155)), and the position spy has the same dependency ([useReadingPosition.ts:185](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/reader/useReadingPosition.ts:185)). Add `rootFontPx` or the text-size value to `layoutKey`, with a regression test where root size changes but `tableW`/`modeW` do not.

2. **The plan’s preserved-contrast claim is false.** It says the overlay keeps text/page contrast at the same ratio ([plan:121](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/docs/plans/261019g-reading-comfort-on-profile-brightness-and-text-size.md:121)). Alpha compositing scales encoded RGB values, while WCAG contrast uses linear luminance plus a `0.05` term; the ratio therefore falls, often sharply. This matters because several muted colours were calibrated just above 4.5:1 ([tokens.css:182](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/styles/tokens.css:182)). Keep the overlay design, but describe it honestly and calibrate the three levels for readable body, muted, disabled, and danger text in both themes. Pixel brightness alone is insufficient acceptance evidence.

3. **The claim that JS layout “gives up columns sooner” is only partly true, and the browser matrix misses the risky boundaries.** Standard bands retain fixed `MODE_MIN`/`MODE_IDEAL` values ([layout.ts:232](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/layout.ts:232)), fixed prose thresholds ([layout.ts:59](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/layout.ts:59), [layout.ts:125](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/layout.ts:125)), and the same 700px cover crossover ([layout.ts:482](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/layout.ts:482)). Marginalia remains 200/288/384px while its text grows ([layout.ts:529](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/layout.ts:529)). At a 22px root, the 400px prose floor is substantially narrower in characters than the 30.2ch measured at 16px. Either scale the type-readability thresholds or explicitly accept that trade-off and test 700px, the band-plus-marginalia crossover, narrow landscape, and a dense mode—not only 390px and 820px Plain/Glossary.

4. **Dimming needs an explicit print exemption and a real installed-iPad check.** A fixed overlay can otherwise darken printed pages/PDFs; the repository already removes screen-only effects in print ([site.css:218](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/styles/site.css:218), [dock.css:1072](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/src/web/styles/dock.css:1072)). Add a print rule disabling the overlay and dialog filter. Also, the proposed Playwright run cannot answer the plan’s acknowledged iOS-standalone uncertainty: safe-area insets are zero on every development machine ([tokens.css:201](/var/tmp/spideryarn-worktrees/fbq645m0-dim-mode-and-text-size/styles/tokens.css:201)). Require an installed-iPad pass covering first paint, portrait/landscape, elastic overscroll seams, status-bar/home-indicator edges, and an open dialog.
