3. **P2 — the seven-key list is complete for the installed parser, but it is not future-proof as claimed.** Installed `pg-connection-string` only constructs or changes `ssl` through `ssl`, `sslmode`, `sslrootcert`, `sslcert`, `sslkey`, and `sslnegotiation`; `uselibpqcompat` changes `sslmode` semantics ([index.js:69](</home/greg/code/spideryarn2/.claude/worktrees/ssl-refuse-unverified/node_modules/pg-connection-string/index.js:69>), [index.js:106](</home/greg/code/spideryarn2/.claude/worktrees/ssl-refuse-unverified/node_modules/pg-connection-string/index.js:106>)). `options` is only a PostgreSQL startup option ([connection-parameters.js:83](</home/greg/code/spideryarn2/.claude/worktrees/ssl-refuse-unverified/node_modules/pg/lib/connection-parameters.js:83>)). `PGSSLMODE` cannot override callers that supply the SSL object; `PGSSLNEGOTIATION` changes the handshake but retains that object. Percent-encoded key names are decoded by `URLSearchParams`, so `%73slmode` is caught; key names are case-sensitive in both implementations. Both `postgres:` and `postgresql:` behave identically. Non-URL libpq `key=value` strings are not interpreted as libpq strings by this package and are refused by `sslDecisionFor`; raw/socket forms do not create a silently unverified remote path, though they are not supported as local URLs. However, [plan:56](</home/greg/code/spideryarn2/.claude/worktrees/ssl-refuse-unverified/docs/plans/261001j-refuse-unverified-tls-to-the-remote-database.md:56>) wrongly says a future spelling would be refused: an unknown future key is absent from the denylist and from the tests. Scope that claim to 2.14.0, or use a safe-key allowlist/exact dependency pin.
