## Findings

**F1 — P1 — The identifier branch can mechanically accept the wrong paper.**  
The plan first establishes that a DOI anywhere in the uploaded article is likely to belong to a cited work, not the upload itself, but then accepts an exact normalized title plus that DOI anywhere in the article. The identifier branch does not require an author or content match. A cited paper sharing the upload’s title therefore passes. The planned “DOI mismatch” test also contradicts the written OR rule, under which matching opening text can override a different DOI. Evidence: [plan:62](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:62>), [plan:67](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:67>), [plan:127](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:127>).  
Concrete fix: never treat an arbitrary identifier in article text as the upload’s identity. Either extract an own identifier from positionally/labelling-constrained raw front matter, or require author plus independent content agreement for the identifier branch. Write one truth table covering matching and conflicting DOI/arXiv IDs before implementation.

**F2 — P1 — “Same paper” does not establish “canonical/original page.”**  
The reused search explicitly permits an author’s copy, while the plan stores whichever search-result URL the model selected, even when fetching redirects elsewhere. A repository mirror, author PDF, or other copy can pass every identity check, yet the UI calls it “Probably the original” and “where it came from.” Evidence: [citation-find.ts:157](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/citation-find.ts:157>), [plan:85](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:85>), [plan:104](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:104>).  
Concrete fix: when the candidate supplies a verified DOI or arXiv ID, store the mechanically constructed DOI/arXiv canonical URL. Otherwise label it only “A matching page for this paper”; do not claim provenance or originality.

**F3 — P1 — Fire-on-first-open violates the stated background-per-upload constraint.**  
The plan explicitly says an upload never searched if its article is never opened. It also couples the work to a browser request that can disappear when the tab closes. The existing successor mechanism was built to queue work transactionally with publication and let the browser job engine drive it from any page. Evidence: [plan:31](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:31>), [plan:42](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:42>), [pg-revisions.ts:2258](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/store/pg-revisions.ts:2258>).  
Concrete fix: queue an upload-only successor when the initial upload revision publishes. Classify it as successor work so it is not offered as an ordinary Metadata rerun. If the product owner intentionally relaxes “every upload,” record that explicitly rather than treating opening as equivalent.

**F4 — P1 — The reclaimable row is not a safe claim protocol.**  
`claimed_at` makes a stale claim detectable but does not fence its writer. After attempt B reclaims, late attempt A can still overwrite B’s result—for example, replace `found` with `none`. The proposed client shape also omits `claimedAt`, while the hook is described as firing only for “never searched,” leaving no clear path that actually invokes stale reclamation. The job system already fences writes with an attempt ID. Evidence: [plan:34](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:34>), [plan:93](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:93>), [plan:113](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:113>), [pg-revisions.ts:2248](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/store/pg-revisions.ts:2248>).  
Concrete fix: preferably inherit the successor job’s lease and attempt fencing. If the custom row remains, mint a claim token and finalize only with `WHERE status='searching' AND claim_token=?`; discard a stale writer’s result. Define transient-failure handling and a deadline covering both search and page fetch.

**F5 — P1 — “Once per article” is not an adequate paid-search bound once reclamation exists.**  
A timeout or killed process leaves a reclaimable claim, so the same article can buy another search repeatedly. Moreover, the provider’s five-result cap does not cap billed searches: the existing implementation records a probe that ran 36 searches and therefore has per-owner and global fuses. `findWorkPage` explicitly requires each caller to supply its own bound. Evidence: [citation-find.ts:29](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/citation-find.ts:29>), [citation-find.ts:107](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/citation-find.ts:107>), [citation-find.ts:375](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/citation-find.ts:375>), [plan:117](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:117>).  
Concrete fix: add a dedicated allowance with concurrency, per-owner, and global daily bounds, plus a small durable attempt cap per article. Specify how the route injects `openRouterJson("upload-source-guess", …)`, since `findWorkPage` currently defaults its ledger/model job to `citations-find`.

**F6 — P2 — The proposed measurement does not test whether normal correct pages pass.**  
Counting any DOI in blocks does not measure whether the candidate’s own DOI survives there. PDF front matter deliberately classifies DOI lines and arXiv stamps as unrendered publisher furniture. The fallback 12-word exact run compares model transcription with HTML/pdf.js text even though this repository documents constant hyphen and spacing disagreements between those representations. The first long body paragraph can also be authors or affiliations, which front-matter processing deliberately retains—not “usually the abstract.” Evidence: [pdf-frontmatter.ts:197](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/pdf-frontmatter.ts:197>), [pdf.ts:319](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/pdf.ts:319>), [pdf-score.ts:244](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/pdf-score.ts:244>), [plan:57](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:57>).  
Concrete fix: before building storage or UI, run the actual predicate against known arXiv abs, DOI, and publisher pages for representative uploads. Read identifiers from the stored raw document, and replace “first paragraph, 12 exact words” with an abstract-aware or multi-shingle content check tolerant of known PDF tokenization differences.

**F7 — P2 — The table is appropriate, but `meta.sourceGuess` is the wrong projection seam.**  
Keeping the guess out of `final_url` is correct, and a separate article-keyed table is reasonable. But `Meta` is revision extraction metadata; this is mutable article-level state attached at read time. Making it optional also lets a store projection forget it silently. The existing `Article` type keeps non-artifact article state such as visibility at the top level and uses required-but-possibly-undefined keys where omission must be caught. Evidence: [plan:88](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:88>), [plan:113](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/docs/plans/260929g-canonical-link-for-an-uploaded-paper.md:113>), [types.ts:1723](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/types.ts:1723>), [types.ts:1755](</home/greg/code/spideryarn2/.claude/worktrees/fb5h-canonical-link-for-uploads/src/types.ts:1755>).  
Concrete fix: expose a required `sourceGuess: SourceGuess | undefined` on the owner article/metadata DTOs, with a discriminated union. Add SQL checks tying each status to its required/null columns.

A simpler safe v1 is: queue a successor; search once under an allowance; accept only exact title + author + a candidate DOI/arXiv identifier found in constrained raw front matter; then store the constructed DOI/arXiv canonical URL. Defer the opening-text fallback until the real-page eval demonstrates it is both safe and useful.
