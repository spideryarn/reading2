1. **P1 — The steady-title rule can preserve a wrong title indefinitely.** Every model-selected title must be printed in the opening, so containment alone cannot distinguish a correct prior choice from a bad one. It can also preserve the old LaTeXML fallback without ever calling the new model—for example, a previous title `1 Introduction` that also appears near the opening. The existing [`stepTitleTidier`](/var/tmp/spideryarn-worktrees/fbjd-arxiv-title-leading-1/src/pipeline.ts:2269) is narrower because `titleOriginal` proves that tidying changed a known incoming title. Either omit the new hold initially or persist selection provenance/version and opening hash; at minimum, never hold a previous title equal to the rejected Readability title.

2. **P2 — The model approach is reasonable, but its semantic accuracy is unmeasured.** It fits Greg’s preference better than a new arXiv-specific fetch, and it is safer than blindly taking record one. However, the verifier proves only that the answer occurred on the page—not that it is the title. Any 3–300-character run such as `Abstract`, an author, institution, section heading, or injected instruction passes. The only real evidence currently has the correct title as the whole first record. Add a small negative corpus containing the date/preprint/logo/institution cases cited by the plan, score the model against a “first non-empty record” baseline, and consider requiring a whole record unless the corpus proves substring selection is needed.

3. **P3 — The detection signal is basically right, but scope it to the recognized document root.** LaTeXML’s class convention represents the logical element/role, so `.ltx_title_document` is preferable to requiring an `h1`; it already catches the title under another HTML tag. I found no evidence of a second LaTeXML document-title class. [LaTeXML’s class documentation](https://math.nist.gov/~BMiller/LaTeXML/manual/cssclasses/) supports that interpretation. However, “anywhere in the page” lets an unrelated or author-added class outside `article.ltx_document` suppress detection. Query beneath the recognized root and test: unsupported origin, no document root, a non-`h1` document title, and an unrelated out-of-root class. Also correct the plan’s “no `<meta>` tags at all”: the fixture has charset and viewport tags, just no bibliographic metadata.

4. **P2 — Pin all title consumers in tests.** [`runExtract`](/var/tmp/spideryarn-worktrees/fbjd-arxiv-title-leading-1/src/extract.ts:1370) currently fans one raw title into three outcomes: tidied `meta.title`, the untidied `extractedHtml` `<title>`, and the pipeline job title through `detail: result.meta.title`. `ExtractResult` has no separate top-level title. Tests should assert all three for both a selected title and the slug fallback; otherwise the bad `1Indicator Properties` can survive in the stored HTML even while the shelf is fixed. Preserve the established rule that the HTML head contains the selected pre-tidying title.

5. **P2 — The new AI job needs more registration than “models.ts job + model.”** Add `opening-title` to `NonTaskAiJob`, `AI_JOB_WIRE`, `NON_TASK_MODELS`, `AI_JOB_ROUTE`, `CHAT_REASONING`, and `JOB_DISPOSITION`, with route and wire tests. The call will then be cost-tracked automatically because it runs inside the `extract` step’s collector and uses `openRouterJson`; classify it as step-driven. Copying the `front-matter-authors` route is the consistent choice for the same model, content, and strict schema.

6. **P3 — JSON encoding does not by itself make stranger text inert.** Follow [`front-matter-authors.ts`](/var/tmp/spideryarn-worktrees/fbjd-arxiv-title-leading-1/src/front-matter-authors.ts:195): explicitly tell the model the records are untrusted data and never instructions, retain the existing visible-opening caps, expose no tools, and log no page text. The verbatim check limits the damage to choosing the wrong words from that page, but does not prevent prompt injection from influencing which words it chooses.

7. **P3 — The slug is safe but not the best available placeholder.** `ownIds` is already available after `readArticle`, so this case can fall back without a model or second fetch to a recognizable identifier such as `arXiv:2308.08708`, instead of the internal `arxiv-2308-08708-spya-xax6v4`. This is optional; the slug is still preferable to the known-wrong LaTeXML title.

8. **P3 — No PDF-path change is required.** The condition belongs only to supported LaTeXML HTML, while PDFs already obtain a title through their front-matter ladder and then use the same title tidier. Add a regression test that the opening-title reader is never involved in `runPdfExtract`; no new PDF logic should be introduced.
