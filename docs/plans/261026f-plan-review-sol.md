No P0, but seven P1s should be resolved before building.

F1 — P1 — Keep the free list experimental. The 94% is 33/35 readable top-five hits, not 94% of everything the UI will show: 13 further candidates were unreadable, ranks 6–25 were not assessed, and two readable candidates were wrong. The gate also hides four genuine *Bitter Lesson* citers. This remains below the consult’s stated 95% threshold and does not cover the proposed 25-row list ([investigation:58](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/docs/investigations/261026a-cited-by-with-no-doi-full-text-and-web-search-recall-and-cost.md:58), [consult:10](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/docs/plans/261026f-design-consult-sol.md:10)). Fix: put *Possible citations* behind Experimental while evaluating all displayed ranks, especially no-year, short-title, namesake and negative cases. Greg’s “free work runs proactively” rule determines when eligible work runs, not whether insufficiently validated results become non-experimental.

F2 — P1 — The reader-facing evidence claim is false. “Each contains this piece’s exact title” and “OpenAlex has the full text of these papers” are not guaranteed ([plan:84](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/docs/plans/261026f-cited-by-when-there-is-no-doi-from-the-full-text-and-a-web-search.md:84)). OpenAlex documents that `fulltext.search` searches title, abstract and full text, applies stemming and removes stop words; even a quoted phrase is only exact after that processing. The Olah false match demonstrated this locally. [OpenAlex search documentation](https://help.openalex.org/api/searching/). Fix: say “OpenAlex’s search matched the title words in these papers’ indexed text”; label the headline number “full-text-search matches,” not papers that probably cite it. If `fulltext.search.exact` is adopted, rerun the evaluation rather than transferring the 94%.

F3 — P1 — The phrase gate is not implementable unambiguously. `year-10…year-2` is nine years, while the investigation measured ten; “that is more than 5% of the per-year rate” compares an unnamed quantity with a rate; equality, `since=0`, and one or two hits are unspecified. The investigation says *Fashionable Problems* is kept despite 23 prior and zero later hits, which the stated formula would classify as common ([investigation:88](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/docs/investigations/261026a-cited-by-with-no-doi-full-text-and-web-search-recall-and-cost.md:88)). Future years can create an empty range or non-positive denominator; `plausibleYear` accepts through 2100. Fix: define exact inclusive ranges, denominators and `>`/`>=`; inject `nowYear`; reject or separately handle years after `now+1`; specify zero-count behavior and no-year behavior. Test 0/2/3 prior hits, zero later hits, exact 5%, current year, next year and 2100. Replace “This title is a common phrase” with the evidenced claim: “Older papers used these words too often for this search to distinguish citations.”

F4 — P1 — The OpenAlex filter remains injection-prone as specified. The spike directly interpolates the title into `fulltext.search:"…"`, and URL encoding does not neutralise commas, quotes, pipes or Boolean syntax inside OpenAlex’s filter grammar ([spike:66](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/scripts/spikes/261026a-cited-by-full-text.ts:66)). The proposed hostile-title test states the destination but the plan never defines the transformation. Fix: explicitly derive a bounded query from `tokens()`/`titleQueryOf`: NFKC, lower-case letter-and-digit runs only, punctuation and operators removed, cut at a word, then build the whole request with `URLSearchParams`. Assert the decoded `filter` exactly for hostile quotes, comma, `AND`, `OR`, pipe and colon.

F5 — P1 — `isThePiece` contradicts its required test. “The title with at most two words added” drops `Response to <title>`—exactly two added words—although the plan and consult require that row kept ([plan:120](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/docs/plans/261026f-cited-by-when-there-is-no-doi-from-the-full-text-and-a-web-search.md:120), [spike:131](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/scripts/spikes/261026a-cited-by-full-text.ts:131)). Fix: exclude exact-title records and narrowly identified copies/variants, not arbitrary one- or two-word wrappers; pin *Response to*, *Comment on* and *Revisiting* as retained cases.

F6 — P1 — The privacy guard cannot be implemented through the named identity loader. `importedFromAPublicAddress` requires both `filename` and `url`, but `loadArticleIdentity` returns no filename ([contract:427](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/src/store/contracts.ts:427), [helper:884](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/src/citation-blurbs.ts:884)). Using URL alone would leak titles from uploads that acquired an address. Also, Stage 1 exposes a callable route before Stage 2 updates `/privacy`; “the current client does not call it” is not a privacy boundary. Fix: extend one owner-scoped snapshot with `raw_filename`, fail closed through the existing helper before any full-text or paid search, and ship the privacy page, `LAST_UPDATED`, and privacy tests with the route. Document separately that the pre-existing Cited-by title lookup may still run first for uploads; enumerate exactly which requests happen on open. Apply the same public-address gate before Stage 3 sends title, surname or address to OpenRouter/Exa.

F7 — P1 — Cache invalidation and rollback behavior are incomplete. The fingerprint hashes query and publication year, but the gate also depends on the current year and its exact range; the same fingerprint can therefore mean a different classification after New Year. The plan also does not say whether an expired same-fingerprint row is served when refresh fails, or how a new client handles an old server that returns `no-doi` without `possible`. Fix: hash recipe version, sanitised query, usable article year, `nowYear` and exact gate boundaries; never serve a mismatched row, but serve an expired same-fingerprint row with its original date after transient failure. Make `possible` optional in the client for old-server rollback, while strictly validating it when present, and test both deployment orders.

F8 — P2 — Lifecycle and tests need an explicit checklist. The free table’s “as `related_work_searches` is” points in the right direction, but name both `ARTICLE_TABLE_COVERAGE` projections—rollback export and reader bundle—with intentional export/omission reasons, `ARTICLE_TABLES` transfer classification, cascade deletion, schema drift, guarded-store and timestamp/SQL shape checks. Stage 3 mentions deletion only; it still needs decisions for transfer, both exports and rollback. Add PostgreSQL route tests for ownership and no-network refusals, migration constraints, cascade, transfer, export coverage, malformed cached JSON, old-server compatibility, gate boundaries, exact request counts, and privacy/help copy. The Sources help page is remembered; its assertions are not.

F9 — P2 — Stage 3 is correctly deferred, but its queued design still lacks a hard spend bound. It describes “one Haiku call,” then adds a second checker; `max_total_results` caps returned evidence, not searches or spend, and “at most two searches” is only a prompt request ([consult:79](/var/tmp/spideryarn-worktrees/fbvx23nt-cited-by-web-search/docs/plans/261026f-design-consult-sol.md:79)). Fix before Stage 3 starts: measure both calls, enforce a per-press fuse, fence the hostile title as untrusted prompt data, reuse already-qualified Reception rows, and deduplicate the two evidence classes by strong identifiers while retaining both provenance labels.
