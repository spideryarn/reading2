No P0 findings. I found two P1 issues that should be resolved before building.

- **P1 — The plan creates conflicting answers for the same reading.** The plan first calls this “the same share,” then excludes folded matter only from the masthead while explicitly retaining it for chat ([plan](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/docs/plans/261025j-how-much-of-the-article-you-have-read-at-the-top.md:25), [matter rule](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/docs/plans/261025j-how-much-of-the-article-you-have-read-at-the-top.md:51)). It also overlooks the quiz: `bodyWords` includes every non-supplement block ([Reader.tsx](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/src/web/reader/Reader.tsx:2576)), and the quiz calculates its displayed share directly from that map ([QuizPanel.tsx](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/src/web/QuizPanel.tsx:1611)). Thus the masthead can say **Finished** while the quiz says, for example, **about 67%**, and chat says **about three quarters**. The claim that matter is only an abstract and byline amounting to “a few percent” is also wrong: folded matter includes executive summaries, contents, declarations, and more, and a front summary may reach 1,500 words ([front-and-back-matter.md](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/docs/project/front-and-back-matter.md:43)). **Concrete fix:** for v1, calculate the masthead band from the existing `bodyWords` unchanged and rely on the forgiving 80% threshold. That is simpler, genuinely reuses the existing share, and removes `foldedOnArrival`. If matter exclusion is essential, define one shared denominator for masthead and quiz and do not claim chat agreement until the server can use it too.

- **P1 — The card promises more than the 80% threshold guarantees.** “Skipping a section or a few paragraphs still counts as finished” ([plan](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/docs/plans/261025j-how-much-of-the-article-you-have-read-at-the-top.md:64)) is false whenever that section or those paragraphs exceed 20% of counted words. The quoted request supports a forgiving threshold, but not the plan’s unsupported assertion that a skipped section is normally 10–20%. **Concrete fix:** retain 80% if desired, but say: “You do not need to read every passage for this to say Finished.” That accurately describes the rule without introducing a precise percentage.

- **P2 — A 5% share is drawn as 25%, contrary to the existing visual contract.** The proposed first visible band jumps directly from nothing to a quarter pie ([plan](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/docs/plans/261025j-how-much-of-the-article-you-have-read-at-the-top.md:31)). `SharePie` explicitly promises to draw the exact share and calls stretching a slice “lying” ([SharePie.tsx](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/src/web/SharePie.tsx:16)); the design guide repeats that invariant ([design-css-overview.md](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/docs/project/design-css-overview.md:231)). **Concrete fix:** either add a small/eighth `small` band for 5–15% and keep the quarter from 15%, or use a distinct segmented status mark rather than silently changing `SharePie`’s meaning. Any deliberate override must update the component and design documentation.

- **P2 — The accessible name lacks context.** `SharePie` uses `label` verbatim as the button’s accessible name ([SharePie.tsx](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/src/web/SharePie.tsx:93)). Names such as “Started” and “Finished” do not say what was started or finished, especially immediately after the read-time control. **Concrete fix:** use names such as “Reading progress: Started” and “Reading progress: Finished,” with a component test asserting them.

- **P2 — Required documentation and styling work is missing from the plan.** `reading-time.md` enumerates every consumer but has no planned masthead addition ([reading-time.md](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/docs/project/reading-time.md:159)). If matter remains excluded, `front-and-back-matter.md` must record that new consequence. The pie styles also explicitly say they must move out of `quiz.css` when a second feature uses them ([quiz.css](/var/tmp/spideryarn-worktrees/fbe5477u-how-much-read/src/web/styles/quiz.css:398)). **Concrete fix:** add those documentation/style changes and the existing touch-target test to the plan’s checklist.
