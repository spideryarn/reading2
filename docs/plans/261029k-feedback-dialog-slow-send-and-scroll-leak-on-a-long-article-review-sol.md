### P2

- The diagnosis is too universal. The Chrome A/B evidence is strong, but it did not test WebKit or prove that every unrelated mutation produces a document walk. Blink does track ancestor traversal for `:has()` invalidation, while current WebKit has added scope-based `:has()` invalidation improvements. Native modal changes do invalidate document-root style/inert state in both engine sources. **Fix:** say “observed in tested Chrome; consistent with engine invalidation mechanisms and plausibly relevant to affected Safari versions,” not “Blink and WebKit after any DOM change.” [Blink `:has()` invalidation source](https://chromium.googlesource.com/chromium/src/%2B/af3159f6b882f925733a6dae791cd2f075937e80/third_party/blink/renderer/core/dom/has_invalidation_flags.h), [Blink dialog source](https://chromium.googlesource.com/experimental/chromium/src/%2B/bcddb6642f94748d593b22ee99054e44c25f7f1d/third_party/blink/renderer/core/html/html_dialog_element.cc), [WebKit’s recent scope-invalidation work](https://bugs.webkit.org/show_bug.cgi?id=312866).

- Preserve the specificity ladder explicitly. The no-bar replacement keeps its specificity, but the main bar guard and narrow dock guard lose one class-weight if replaced with straightforward root attributes ([shell.css:667](/var/tmp/spideryarn-worktrees/fbk3g78t-dialog-scroll-and-send/src/web/styles/shell.css:667), [narrow-window.css:676](/var/tmp/spideryarn-worktrees/fbk3g78t-dialog-scroll-and-send/src/web/styles/narrow-window.css:676)). **Fix:** record expected specificity beside each replacement and use duplicated attributes or an equivalent deliberate specificity carrier.

## A–F verdicts

- **A:** Sound for the measured Chrome case; modal inertness is document-wide style work in both engines. The WebKit/all-mutations wording is unproven. Nothing contradicts the Chrome diagnosis; the scroll-leak explanation remains a hypothesis.
- **B:** Root flags are the right shape. Layout effects are early enough for painting, provided the semantic state is used directly and cleanup is ref-counted. Child-combinator scoping is not a general substitute: portal state escapes the chain, and any descendant combinator needed to find Reader recreates the broad search.
- **C:** No behaviour loss found. Fetching, decision counts and reply drafts live above the frozen subtree; the visible→hidden transition still stops dictation; re-showing runs the thread scroll-reset effect. The new and existing feedback-dialog tests pass: 337 tests.
- **D:** Too loose as phrased, and its migration list is incomplete.
- **E:** Yes; recommend and measure it separately, then ask the owner.
- **F:** Native dialog open/close restyle—and therefore the leading scroll-leak hypothesis—survives Stage 1. Actual affected-iPad testing is still missing.
