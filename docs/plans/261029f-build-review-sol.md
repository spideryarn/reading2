Verdict: Q1 is not universally true; Q2 is sound for a valid non-null block. The design needs a stronger settlement handshake and dirty-write protocol.

1. **High — “Last answer for the current article” is insufficient.** Normal initial loads are ordered: `useLastView`’s parent layout effect runs before `useArticleAccess` starts its passive effect, so preloading and StrictMode do not reverse them ([last-view.ts:819](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/last-view.ts:819), [access.ts:263](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/article/access.ts:263)). But:

   - Metadata can receive the answer before the reading-view arrival; access persists across view changes ([ArticlePage.tsx:70](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/article/ArticlePage.tsx:70)).
   - `attempt` starts another access resolution without triggering `useLastView` ([access.ts:310](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/article/access.ts:310), [last-view.ts:865](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/last-view.ts:865)).
   - After the auth deadline, ArticlePage can load while `known=false` and `useLastView` has `slug=null`; settlement can precede the arrival, or the arrival can never happen ([App.tsx:264](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/App.tsx:264), [App.tsx:278](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/App.tsx:278), [App.tsx:398](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/App.tsx:398)).
   - A retained signed-out/public answer must not satisfy a later signed-in arrival.

   **Suggested change:** use a keyed, consume-once handshake: `{slug, readerId, accessGeneration}` plus an arrival generation/status. Keep an answer across Metadata→article, but reject stale attempts/readers and call settlement only after the existing `live` guard ([access.ts:276](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/article/access.ts:276)). Explicitly settle non-owned and error outcomes too; the catch currently goes directly to `setAnswer` ([access.ts:295](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/article/access.ts:295)).

2. **High — “Clear after a 2xx” also needs write-version protection.** While place P1 is in flight, the reader can move to P2. P1’s success must not clear P2. Current sending is fire-and-forget and discards response status/failure ([useReadingTime.ts:100](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/useReadingTime.ts:100), [useReadingTime.ts:370](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/useReadingTime.ts:370)); `pagehide` uses a different path ([useReadingTime.ts:394](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/useReadingTime.ts:394)).

   **Suggested change:** snapshot a monotonically versioned place per send; clear only if that exact version remains current and the response is 2xx. Retain newer places. On a failed combined request, retry only the place—never the already one-shot additive seconds.

3. **Medium — `{block:null}` does not itself guarantee “at the top” or that a row gets written.** On first mount, `synced.current` and `at` are both null, so the arrival effect returns without `scrollToTop()` ([useReadingPosition.ts:52](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/reader/useReadingPosition.ts:52), [useReadingPosition.ts:68](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/reader/useReadingPosition.ts:68)). This matters on Metadata→article, where the window can retain Metadata’s scroll position. Also, the initial top note occurs in a child passive effect ([useReadingPosition.ts:212](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/reader/useReadingPosition.ts:212), [useReadingPosition.ts:308](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/reader/useReadingPosition.ts:308)); on Metadata→article the parent’s saver is not installed until its later passive effect ([last-view.ts:900](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/last-view.ts:900), [last-view.ts:954](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/last-view.ts:954)). The top note can therefore be lost.

   **Suggested change:** give initial `synced` an “unseen” sentinel so initial null calls `scrollToTop`, and install/capture the place saver before child passive effects—or enqueue the opening null place directly.

4. **Medium — the store must special-case nullable blocks.** Copying `reading_time`’s inner join would silently write no row for null because `block_id = NULL` never matches ([pg-reading-time.ts:44](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/store/pg-reading-time.ts:44), [pg-reading-time.ts:49](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/store/pg-reading-time.ts:49)).

   **Suggested change:** authorize the owned article first, then insert null directly; for non-null, gate the insert with block-identity existence. Preserve three distinct results: no row, row with null block, row with block.

5. **Low — the historical fallback is narrower than documented.** `reading_time` proves a prior read only when positive seconds successfully flushed; it does not cover every article read before shipping ([useReadingTime.ts:380](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/useReadingTime.ts:380)). Also, block identities include historical blocks, so a saved block may no longer be drawable; `arriveAt` then cannot scroll.

   **Suggested change:** change “every article read before this ships” to “articles with stored reading time,” and downgrade a saved block absent from the returned article to `{block:null}`.

For Q2 specifically: yes, replacing `?at=` before the initial `setAnswer` is reliable for a valid block—the URL changes synchronously, Reader mounts from it, and the URL→page effect calls `arriveAt` ([useReadingPosition.ts:68](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/reader/useReadingPosition.ts:68)). On Metadata→article, Reader’s first render can precede the parent layout rewrite, but the existing guard explicitly supports that restore ordering ([useReadingPosition.ts:205](/var/tmp/spideryarn-worktrees/reading-place-across-devices/src/web/reader/useReadingPosition.ts:205)). The plan should say “before first paint/arrival,” not universally “before the prose is drawn.”
