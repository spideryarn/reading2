No P0/P1 findings. This is a reasonable simplest version and the tooltip design should work, subject to the URL fix below.

1. **P2 — Quoted names can break both search grammars; URL encoding does not escape query syntax.**  
   Evidence: [plan:26](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/261003f-authors-outside-links-to-find-more-about-each.md:26), [plan:74](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/261003f-authors-outside-links-to-find-more-about-each.md:74). A name such as `Jane "JJ" Doe` produces `author:"Jane "JJ" Doe"` after Google decodes the URL. The planned quote test would bless correct transport encoding while missing the malformed search expression. Google’s documented `author:"name"` operator itself is appropriate; the problem is embedded delimiters.  
   **Fix:** Before constructing either query, remove straight and curly quotation marks from the name, collapse whitespace, then quote the cleaned name. Preserve initials and diacritics. Test the decoded `q` value, not merely the encoded URL. Apply a conservative encoded-length budget to the affiliation hint as well: stored affiliations may be 300 characters ([src/authors.ts:16](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/src/authors.ts:16)), becoming several thousand URL characters for non-ASCII text. Trim by Unicode code points or omit the tail once the budget is reached.

2. **P2 — “Phone width” does not verify the touch interaction on which the fallback depends.**  
   Evidence: [plan:45](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/261003f-authors-outside-links-to-find-more-about-each.md:45), [plan:77](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/261003f-authors-outside-links-to-find-more-about-each.md:77), [Tooltip.tsx:269](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/src/web/Tooltip.tsx:269), [prior plan:241](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/260929d-authors-and-affiliations-at-import-shown-and-linked.md:241). The tooltip code explicitly records that synthesized touch events can produce a different sequence from mouse events and that unit tests do not catch it. The previous phone check also says touch was not emulated.  
   **Fix:** Add a genuine touch-emulated browser check: one tap on the masthead name still follows the shelf link without being consumed by the newly interactive dialog; expanding Metadata exposes both directly tappable external links. Also extend the masthead test to exercise the actual composition—focus the author `<Link>`, verify the named dialog, Tab through Scholar and Web, then out—rather than testing only that `interactive` was set.

3. **P3 — Several claims are stronger than the implementation or external service guarantees.**  
   Evidence: the plan says every new/reset article keeps `meta.authors` at [plan:13](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/261003f-authors-outside-links-to-find-more-about-each.md:13), while the prior plan explicitly leaves pages without structured author metadata without a list ([prior plan:83](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/260929d-authors-and-affiliations-at-import-shown-and-linked.md:83)) and rejects failed PDF extraction wholesale. Likewise, [plan:26](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/261003f-authors-outside-links-to-find-more-about-each.md:26) guarantees a Scholar profile first, and [plan:64](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/docs/plans/261003f-authors-outside-links-to-find-more-about-each.md:64) says searches provide the same top links as an in-app lookup. Scholar profiles may be private, and matching/ranking is not guaranteed ([Google Scholar Profiles](https://scholar.google.com/intl/en-us/scholar/citations.html)).  
   **Fix:** Say “eligible articles keep a verified structured author list,” “Scholar may show a matching public profile,” and “the searches often lead to those links,” respectively.

There is no nested-anchor problem: the trigger remains the shelf link, while the card is portalled outside it ([Tooltip.tsx:350](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/src/web/Tooltip.tsx:350)). The non-modal focus manager is expressly designed to put the card’s links after the trigger in keyboard order ([Tooltip.tsx:397](/home/greg/code/spideryarn2/.claude/worktrees/fbuvxq8e-citations-authors-links/src/web/Tooltip.tsx:397)). `noreferrer noopener` is also the right privacy treatment: Google receives the intentional author/affiliation query, but not the article URL.

Deferring both Citations-band duplication and the paid in-app lookup is reasonable. The masthead already supplies the cross-mode location; Metadata supplies the visible/touch-accessible location. Ensure those Metadata links are genuinely inline—not only copies inside the hover card.
