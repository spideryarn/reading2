## Findings

1. **P0 — The 150-work sample cannot produce Greg’s explicit rare top-level subjects at 1,000–3,000 works.** Greg asked for *Neuroscience*, *Buddhism*, and *Carpentry* when only a few papers are outside neuroscience ([plan:14](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/docs/plans/261003f-shelf-topics-named-by-a-model-as-concepts-not-phrases.md:14)). But `nameLevel` names topics from only 150 evenly sampled works, then can only file the remainder into those names ([model-topics.ts:455](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:455)). On a 1,005-work shelf, a five-paper Carpentry field contributes about 0.75 sampled papers, while `parseNamed` requires three. Once Carpentry is absent from the sample’s names, filing cannot invent it. **Change:** discover candidates from every chunk, consolidate chunk candidates in another call, then file all works into the consolidated names. Evaluate shuffled 1,000- and 3,000-work versions of the expert shelf, including five-work minority fields, before enabling large shelves.

2. **P0 — A large re-think does not fit the execution envelope the design claims to support.** Filing uses batches of 40 and concurrency four ([model-topics.ts:68](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:68), [model-topics.ts:420](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:420)). At 3,000 works, the top level alone needs one naming call plus 72 filing calls—18 waves—before recursive levels begin. Each call may take 150 seconds; observed filing already took 14–30 seconds for one batch. The request is capped at 800 seconds ([vercel.json:16](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/vercel.json:16)), while the claim expires after 600 seconds ([shelf-topic-sets.ts:83](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:83)). That permits duplicate work before Vercel itself stops the first invocation. **Change:** make a re-think a checkpointed, multi-invocation job, or otherwise prove a hard bound below both limits; heartbeat/renew the lease and measure 1,000 and 3,000 works. Until then, gate large shelves to the old pills rather than repeatedly starting an operation that may never write.

3. **P0 — The claim fences an old writer, but does not stop a stale reader from becoming the next writer.** `claimTopicSet` accepts only a lease duration; it does not bind the claim to the stored result generation or shelf snapshot ([contracts.ts:852](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/store/contracts.ts:852)). The orchestrator computes `due` and captures `works` before claiming ([shelf-topic-sets.ts:227](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:227)). A delayed request can therefore read generation A, another request write B and clear its claim, then the delayed request claim and overwrite B using A’s topics and shelf. A work added during the first re-think is likewise absent from its result and depends on a later browser poll or reopening the shelf. **Change:** add a stored generation and shelf/work fingerprint; claim with the expected generation, recompute after claiming, and refuse writes if either changed. After a re-think, re-read and drain arrivals before declaring the job complete. Browser polling should update the UI, not supply correctness.

4. **P1 — Failed finer-topic calls are silently blessed as a complete, current re-think.** Every exception below the top is swallowed into `[]` ([model-topics.ts:513](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:513)); the result is then stored with the current model and prompt version. A transient failure—or a programming bug—can permanently remove one subject’s finer tree until unrelated shelf growth triggers another re-think. **Change:** either fail the whole re-think and retain the old complete tree, or persist incomplete branch jobs and retry them. Never catch unexpected exceptions as “this topic has no children.”

5. **P1 — Downward shelf transitions are wrong, especially crossing below eight works.** Stored topics are rendered before `whatIsDue` runs ([shelf-topic-sets.ts:237](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:237)), while `whatIsDue` simply does nothing below eight ([shelf-topic-sets.ts:190](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:190)). Thus an eight-work shelf reduced to seven keeps model topics, contrary to “the row behaves as today.” Larger shrinkage also leaves `result.works` as a permanently high growth baseline, so a shelf reduced from 100 to 20 may not re-think until it reaches 125. Archived articles are handled correctly because the stored set covers active plus archived; deletion is the problematic shrink. **Change:** suppress the stored model set below eight, and trigger or reset after a material shrink; prune dead memberships during that write.

6. **P1 — A single `unplaced` count cannot implement “new unplaced works since the last re-think.”** The contract retains only the old count ([contracts.ts:901](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/store/contracts.ts:901)), and due-ness compares current and old totals ([shelf-topic-sets.ts:196](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:196)). If ten previously unplaced works are deleted and ten new works file nowhere, the total is still ten and no trigger fires. **Change:** persist stable work keys seen and unplaced at the last re-think, then compute set differences. Use content hashes with an article-id fallback, rather than the current representative article id alone.

7. **P1 — Profile edits never refresh a tree even though the profile is model input.** The prompt includes the profile ([model-topics.ts:175](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:175)), but `TopicSetResult` stores no profile fingerprint, and due-ness checks only model, prompt version, and counts ([shelf-topic-sets.ts:193](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:193)). **Change:** store the normalized profile hash and re-think when it changes, or remove the profile from this feature’s stated inputs.

8. **P1 — “First duplicate name wins” is deterministic, but dropping the later topic is not generally correct.** Parallel completion does not introduce nondeterminism: `pooled` writes results into task-index order, and siblings are consumed in frontier order ([model-topics.ts:420](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:420), [model-topics.ts:530](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:530)). But if both *Neuroscience* and *AI* produce a child called *Methods*, keeping only Neuroscience’s membership means selecting AI + Methods does not recover AI methods. The plan’s intersection argument holds only when the retained topic is genuinely global. **Change:** qualify duplicate labels with their parent, or merge and promote a genuinely identical concept to a global topic. Add a parallel-sibling duplicate test.

9. **P1 — The filing eval overstates what it establishes.** Categories without an F1 ≥ 0.6 match are removed, articles with no remaining target are skipped, and the score is recall-only—it never penalizes filing an article into wrong topics ([hier.ts:190](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/evals/shelf-topic-clusters/hier.ts:190)). In greg-wide, only 10/12 categories and 18/19 held-out articles are scored ([hier-greg-wide.md:54](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/evals/shelf-topic-clusters/results/hier-greg-wide.md:54)). `bestTopics` also lets several intended sibling categories reuse one broad topic. **Change:** report unmatched categories and unscored articles as failures; report precision, recall, and F1 over mapped intended topics; use hierarchy-aware one-to-one matching among siblings; and repeat stratified/random holdouts and order permutations. The files still do not show run variance, real shelves, previous-label stability, adversarial inputs, failure recovery, or anything above 172 works.

10. **P1 — The model response inherits the old phrase path’s scope metadata.** When model terms are installed, the orchestrator replaces `terms`, `chosenBy`, and `pending`, but leaves `scope.works` and `scope.skipped` from the phrase extractor ([shelf-topic-sets.ts:237](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:237)). Model topics include articles the phrase extractor skips, and may group works differently. The client uses `scope.works` for the eight-work state ([ShelfTerms.tsx:245](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/web/ShelfTerms.tsx:245)). **Change:** recompute the model path’s visible article/work counts and define what `skipped` means there. Do not set `pending` to zero in a way that permanently stops the text-hash fill used for exact-copy grouping.

11. **P1 — The cost fuse counts jobs, although one “job” now contains many paid calls.** The allowance treats a filing or re-think as one fill regardless of its number of subcalls ([shelf-topic-sets.ts:90](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-topic-sets.ts:90)). From the result files, re-think cost is $0.0064/96 = **$0.0000667/work** on greg-wide and $0.0196/172 = **$0.0001140/work** on expert; filing is **$0.000042–$0.000059/work**. With one-at-a-time additions, the implemented quarter thresholds re-think at 8, 13, …, 880: 4,324 re-thought work appearances plus 973 filings. Carrying the two measured slopes forward gives **$0.33–$0.55 total**, or **0.033–0.055¢ per article**. Thus the plan’s $0.55/0.06¢ is a reasonable conservative endpoint, but not a single measured estimate. One 1,000-work re-think extrapolates to **$0.067–$0.114**, before large-shelf batching and overlap. The global 3,000-job fuse could therefore permit hundreds of dollars per day. **Change:** present the range and assumptions, measure by level at scale, and weight the allowance by predicted calls/tokens or dollars.

12. **P2 — The plan and UI should state the transient state plainly.** The plan says filing happens before re-think is considered ([plan:84](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/docs/plans/261003f-shelf-topics-named-by-a-model-as-concepts-not-phrases.md:84)); the actual due-order is re-think first, correctly avoiding a redundant filing because re-think also files everything ([plan:161](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/docs/plans/261003f-shelf-topics-named-by-a-model-as-concepts-not-phrases.md:161)). Until either job lands, a newly added article is absent from topic memberships and can disappear under an active topic filter, with no visible “sorting” message. **Change:** correct the prose and expose `{kind, works}` or similar so the row can say “Sorting 3 new articles…” while continuing to show old topics.

13. **P2 — Key cleaning is safe but unnecessarily lossy.** `keyOf` drops every non-ASCII character, so an all-CJK label disappears, and distinct labels such as `C++` and `C#` collide ([model-topics.ts:148](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/shelf-terms/model-topics.ts:148)). `slice(0, 40)` can also cut a surrogate pair. **Change:** truncate by code points and append a short deterministic hash when the readable slug is empty or collides. Prompt injection is otherwise bounded appropriately for v1: untrusted strings are clipped to one line, the call has no tools, references are allow-listed, and output is rendered as text; stronger structured delimiters would still be cheap hardening.

The current 18×10-second ask-again loop now covers the measured 126-second re-think ([useShelfTerms.ts:35](/home/greg/code/spideryarn2/.claude/worktrees/fbntyes8-topic-pills-research/src/web/useShelfTerms.ts:35)); the old four×8-second loop would not have. Ancestor membership is guaranteed on both paths, `t1…` churn is safe because topics and memberships replace atomically while URLs use keys, unchanged unplaced results do not immediately loop, and one JSONB row is reasonable at roughly 3,000 articles/150 topics. The deferred Redo button, topic editing, and old-score removal are not required for v1 correctness; a real-shelf trial is required before production, but not before dev.

**With the P0s and P1s dealt with, yes—v1 is sound to ship to dev.**
