- **P1 — `margin` is missing from last-view state, so shared links and restore are not independent.** `hasArticleState()` recognises only parameters listed in `REMEMBERED`/`NEVER_REMEMBERED` ([last-view.ts:66](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/last-view.ts:66), [last-view.ts:139](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/last-view.ts:139), [last-view.ts:231](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/last-view.ts:231)). Unless `margin` joins `REMEMBERED`, opening `?margin=1` can also replay the browser’s remembered `?mode=…`, violating “the link always wins,” and the margin will not itself be restored. Old stored `?mode=annotations` is another gap: restore happens after boot-time rewrites ([last-view.ts:267](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/last-view.ts:267), [last-view.ts:348](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/last-view.ts:348)). Specify an atomic raw-address migration after last-view restore, or transform the stored spelling during restore. Test cold links, old stored views, Back/Forward, and `?margin=1` over a remembered band.

- **P1 — Dock needs two visibility/current-state axes; the plan currently assumes one.** `visibleModes` keeps an experimental item only when it equals the single current `Mode` ([Dock.tsx:1026](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/Dock.tsx:1026)), and Dock derives that current value solely from `mode` ([Dock.tsx:1604](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/Dock.tsx:1604)). Thus `mode=glossary&margin=1` with Experimental off would hide the pressed Annotations toggle, leaving no way to close it. A single `visible` list also feeds both the radio segment and command bar ([Dock.tsx:1901](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/Dock.tsx:1901), [Dock.tsx:1992](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/Dock.tsx:1992)): Annotations must remain in commands while being excluded from the radiogroup. `fitSignature` also knows only the active mode ([Dock.tsx:1221](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/Dock.tsx:1221)); toggling `.on` changes label width at fit rung 2 ([dock-fit.css:293](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/styles/dock-fit.css:293)). Add `margin` to Dock props/signature and define a canonical `withMargin` link for the metadata arm rather than generating another legacy `mode=annotations` URL through `withMode` ([Dock.tsx:2336](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/Dock.tsx:2336)).

- **P1 — “The band wins” is undefined once `bandAway` has made the band yield.** A covering band can remain the active mode while being `display:none` after a passage jump ([Reader.tsx:504](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/reader/Reader.tsx:504), [narrow-window.css:373](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/styles/narrow-window.css:373)). At 650px, margin-alone has room, but `fitBoth` would suppress it because an active band nominally wins; the reader then sees prose, no notes, and—if suppression keys on `.mode-band`—no explanation. A direct Annotations press resets `bandAway`, but Back/Forward and an already-away band do not. Decide explicitly whether an away band still wins; the coherent reading is to fit the visible layout as margin-only while away, while retaining the band’s state and Back chip. Add the away × 650px/390px cases.

- **P2 — `BandMode` catches Reader’s direct comparisons, but not every active-state seam.** Direct `tsc` already flags the intended Reader sites, including `bandOpen`, `marginOpen`, `modeBand()` and `setMode` ([Reader.tsx:342](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/reader/Reader.tsx:342), [Reader.tsx:1889](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/reader/Reader.tsx:1889), [Reader.tsx:2914](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/reader/Reader.tsx:2914)). But state-derived functions still accept `Mode`, so `"annotations"` remains silently legal: `selectPassages` retains a dead annotations arm ([passages.ts:113](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/reader/passages.ts:113), [passages.ts:163](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/reader/passages.ts:163)), and page-title state still permits an Annotations mode ([page-title.ts:118](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/page-title.ts:118)). Use `BandMode` at every current/read-state seam; retain `Mode` only for catalog-wide records such as policy, activation and labels.

- **P2 — The narrow notice still needs explicit geometry and a test.** It is currently centred on the viewport with `left: 50%` ([marginalia.css:158](/home/greg/code/spideryarn2/.claude/worktrees/fu-annotations-beside-a-mode/src/web/styles/marginalia.css:158)).
