1. **P0 — `judgeLocatedRegion` can accept the wrong object.** The claim that one printed figure caption makes a wrong figure “unreachable” is false. `captionPrintedOn` only searches for a normalized prefix anywhere on the page, so a prose reference can satisfy it while the page’s sole actual caption belongs to another figure ([src/pdf-figures.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figures.ts:737)). Meanwhile, short or narrow text is classified as a label, so a model box around a captionless table can absorb its grid and cells and pass ([src/pdf-figure-region.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-region.ts:386)). That is especially material because every target page contains tables, and the plan itself concedes this case ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/docs/plans/261001q-pdf-tables-and-composite-figures.md:139)). Require positive binding: uniquely locate the target caption at line start, prove a spatial relationship between that caption and the candidate, and reject any table caption between them. Given the evidence that all three answers match printed frames, the simpler rule is to require one unique rectangular ink frame matching the model box, bind that frame to the target caption, and render it. If no unique frame exists, refuse or use the whole-page fallback.

2. **P1 — Visible table cells would remain outside the checks that gate invention.** `scorePage` scores every record for general recall, but `invented`, forbidden markup, and garbage gate only `RENDERED`; everything else merely appears under `unshown` ([src/pdf-score.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-score.ts:739)). Once `tabledata` is visible, an invented numerical cell is no longer “unshown”; tables are also materially more central than the footnote exception used as precedent. Keep `tabledata` outside `RENDERED` for continuation/rendering mechanics, but introduce a separate “visible/gated” set for the scorer that includes it.

3. **P1 — Adding cells guarantees the existing table block’s id will be reminted.** A `<figure>` is one leaf block, so its text changes from just the caption to caption plus every cell ([src/blocks.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/blocks.ts:524)). Carry-over matches the whole block text exactly or folded; it has no caption-only identity for table figures ([src/blocks.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/blocks.ts:914), [src/blocks.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/blocks.ts:950)). Therefore every previously caption-only table loses its id and any block-level bookmark/chat. Add a carry-over test and either preserve the id by an exact, ambiguity-checked direct-`figcaption` match for this migration or explicitly accept and document the loss.

4. **P1 — The regional route omits the existing layout-safety vetoes.** The drawn route refuses strict/flexible layout disagreement, shadings, unmeasured paint, and page-sized ink before rendering ([src/pdf-figure-region.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-region.ts:360)). The proposed rules mention none of them, while handing the entire region to containment makes the renderer’s “every pixel was measured” check nearly tautological inside the crop ([src/pdf-figure-render.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-render.ts:298)). Preserve `strictAgrees`, operator/path ceilings, `shadings === 0`, and `unmeasuredPaint === 0`, or explicitly replace them with another render-side content check.

5. **P1 — `other` image paints cannot safely participate in snapping as currently represented.** The existing judge vetoes every non-XObject image because repeat/group placements can be on-page while their recorded unit-square box is elsewhere ([src/pdf-figure-locate.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-locate.ts:183)). The interpreter collapses inline images, repeated images, groups, and masks into the same `other` type and ignores operator-specific placement arguments ([src/pdf-figure-paint.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-paint.ts:267)). Refusing `other` loses Figure 3; admitting it makes snapping unsound. Split the operator kinds and implement/prove exact bounds for ordinary inline images, while continuing to refuse repeats, groups, masks, inexact clips, and altered appearances.

6. **P1 — Low-text scans bypass the proposed background check.** `readPdfRasters` classifies a page with fewer than `SCAN_WORDS_PER_PAGE` words as scanned and returns before reading any image paints ([src/pdf-figure-read.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-read.ts:352)). A scan with 1–19 OCR words therefore has a nonempty text layer but an empty `paints` list, satisfying both proposed checks. Refuse every page listed in `skippedPages` as `scanned`; also check aggregate/union image coverage so tiled scans cannot evade the per-paint `BACKGROUND_SHARE` rule.

7. **P1 — `readPdfPageLayouts` is not “already read on this route.”** `locatedRoute` currently reads only rasters for each three-page window ([src/collect-pdf-figures.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/collect-pdf-figures.ts:782)). Layouts are read separately inside `drawnRoute`, only for claimed pages of `no-raster` candidates, and that map is not available to the located route ([src/collect-pdf-figures.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/collect-pdf-figures.ts:905)). Amend the wiring and cost account: read the union of eligible locator-window pages once, fail closed on missing layouts, and preferably reject ineligible pages before spending the model call.

8. **P1 — Regional choices need the duplicate-ownership protection the current located route has.** Today two markers selecting one decoded picture are both rejected by identity ([src/collect-pdf-figures.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/collect-pdf-figures.ts:806), [src/collect-pdf-figures.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/collect-pdf-figures.ts:847)). The plan specifies `taken` only against other routes, not two model-located crops. Since the rule allows at most one legitimate figure per page, collect choices before storage and reject all regional choices sharing a page or materially overlapping; raster-hash equality alone is insufficient because slightly different crops of the same object hash differently.

9. **P1 — The proposed containment box does not match what the renderer draws.** `renderPdfRegion` always renders four points beyond `region` on every side ([src/pdf-figure-render.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-render.ts:261)). Passing the unpadded region as containment does not, as the plan says, admit “everything PDFium draws”; nearby ink in the pad will fail containment, while enlarging containment would admit content rule 3 never inspected. Run snapping and all text/content checks against the actual padded crop, and pass that same checked geometry to containment.

10. **P1 — The proposed integration test misses the gate change it is meant to justify.** A fixture with two pictures exercises `assembly`, but not the new behavior of calling the locator when there is no usable picture ([plan](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/docs/plans/261001q-pdf-tables-and-composite-figures.md:164)). Add a zero-picture vector fixture that is stored only after the gate change, plus adversarial cases for a different sole caption, a captionless table, a low-text scan, `other` paint, shading/unmeasured paint, and two markers choosing one region. The real-paper hand check is valuable but is not a permanent regression test.

11. **P2 — `|` and newline are observed conventions, not a transcription contract, and seam repair does not cover them.** Rule 7 asks for cells “reading across each row” but specifies neither delimiter nor escaping ([src/pdf-read.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-read.ts:415)). A literal `|` splits one cell; a newline inside a cell invents a row. Also, `continuationTargets` treats non-`RENDERED` records only as intervening material, so `mendSeamHyphens` can never repair a visible `tabledata` seam ([src/pdf-read.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-read.ts:1555)). Keep the heuristic if desired, but state the fidelity limit and test literal pipes, multiline cells, and continued `tabledata`; a future structured row/cell schema is the sound fix.

12. **P2 — The diagnosis is right for tables and bitmap recovery, but “one connected drawing” is inaccurate.** The drawn route deliberately admits up to six disconnected drawings (`ADMIT_DISCONNECTED_DRAWINGS = true`); Figure 2 failed `small-component`, not a single-connected-component rule ([src/pdf-figure-region.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-region.ts:258), [src/pdf-figure-region.ts](/home/greg/code/spideryarn2/.claude/worktrees/fbpawfwx-jco-tables-and-figures/src/pdf-figure-region.ts:561)). Revise the class description accordingly. Conversely, the downstream table claim is correct: a figure remains one `media` leaf block, and the existing reader/CSS already supports tables inside it. The `pdf-figures/6` policy bump is also the correct freshness mechanism.

**Verdict: Revise before building—Stage 1 is close but needs scoring and id decisions; Stage 2’s current acceptance rule can silently attach a table or other wrong region to a figure caption.**
