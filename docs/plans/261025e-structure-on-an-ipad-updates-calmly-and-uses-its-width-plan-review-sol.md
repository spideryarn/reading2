## Findings

1. **SHOULD — The height fix compensates for the Dock, but not for the top bar.**  
   The band’s top follows `--bar-bottom` ([mode-band.css:47](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/mode-band.css:47)). When `data-bars="hidden"`, a present controls bar moves that edge upward by `--bar-h` ([shell.css:732](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/shell.css:732)), while the new padding compensates only for bottom travel ([mode-band.css:61](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/mode-band.css:61), [outline-mode.css:58](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/outline-mode.css:58)). Therefore the content box still grows and shrinks by the top bar’s height, firing the observers and potentially changing the rung/capacity.

   This is reachable for the side-by-side public-reader case that `shell.css` explicitly describes ([shell.css:830](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/shell.css:830)); the guard pins the bar only for focus, crumbs, or a covering band ([shell.css:857](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/shell.css:857)). The trace signs in as the seeded administrator, so it cannot establish the plan’s broader “works generally” claim ([structure-scroll-trace.ts:26](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/scripts/structure-scroll-trace.ts:26), [structure-scroll-trace.ts:73](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/scripts/structure-scroll-trace.ts:73)).

2. **SHOULD — Anchor bypass tracks a sampled boolean, not anchor-change events, so a jump can still be held.**  
   `anchored` stores only whether an anchor existed at the last measurement, and `jumped` compares that boolean with the current one ([useColumnContext.ts:93](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/useColumnContext.ts:93), [useColumnContext.ts:124](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/useColumnContext.ts:124)). Anchor notifications are coalesced into one animation frame ([useColumnContext.ts:146](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/useColumnContext.ts:146)).

   A glide clears the old anchor ([scroll.ts:711](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/scroll.ts:711)), and an already-at-destination glide may settle synchronously ([scroll.ts:770](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/scroll.ts:770)), causing `scrollToBlock` to install the new anchor before the scheduled measurement ([scroll.ts:1221](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/scroll.ts:1221)). The hook can therefore observe `true → true`, miss both the clear and appearance, and throttle a changed focus row. A listener-side `anchorChanged` flag or generation counter would preserve the events. The new test covers a simple appearance only ([structure-focus-row.test.tsx:241](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/tests/structure-focus-row.test.tsx:241)).

3. **SHOULD — The throttle still performs the entire section rect scan every animation frame, so it only partially addresses the CPU requirement.**  
   Every scheduled measurement reads every row’s rectangle ([useColumnContext.ts:108](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/useColumnContext.ts:108)); only after that work does it decide the update is held ([useColumnContext.ts:128](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/useColumnContext.ts:128)). It reduces React reconstruction and layout of the five candidates, which is valuable, but it does not reduce Structure’s scroll-time DOM reads.

   The simpler shape is to gate ordinary scroll measurements before the rect scan: during the hold, arm one trailing remeasurement without scanning; anchor changes force an immediate measurement. This also makes “what is throttled” closer to Greg’s CPU request.

4. **NIT — `holdMs` is captured by the effect but absent from its dependencies.**  
   The effect depends on `sections`, `enabled`, and `layoutKey` only ([useColumnContext.ts:168](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/useColumnContext.ts:168)). The current caller passes a constant, so there is no present product failure, but the option’s public behavior is stale if a caller changes it without changing those other values.

## Answers to 1–7

1. **Throttle correctness: mostly correct, with the anchor-event defect above.** It is genuinely leading plus trailing; the timer remeasures rather than replaying; returning to the published section while a timer is pending does not lose a later change; cleanup cancels both frame and timer ([useColumnContext.ts:160](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/useColumnContext.ts:160)); and a `sections`/`layoutKey` effect run starts fresh. `performance.now()` is the right monotonic clock to pair with `setTimeout`; background timer delay is harmless because release remeasures current layout.

2. **1000 ms and leading edge: yes.** One second directly matches Greg’s proposed cadence. Leading-edge publication is right: a slow reader gets immediate feedback, while only fast successive crossings are calmed. Holding the first crossing would add visible latency without reducing sustained-scroll redraw frequency.

3. **Keyboard ←/→: acceptable for this first cut.** The article responds immediately and only Structure can lag. `glideTarget()` is an existing signal that motion is programmatic ([scroll.ts:646](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/scroll.ts:646)), but using `glideTarget() !== null` as an unconditional bypass would publish every intermediate section crossed during a smooth glide—the flicker pattern this work is removing. There is no existing clean settlement subscription for the hook. I would not add plumbing unless the one-second keyboard lag proves objectionable.

4. **`--band-bar-travel`: correct for bottom-bar travel, not a complete invariant for every `data-bars` transition.** Its resting and hidden arithmetic is sound, including `--safe-bottom` and the install hint; every dock guard restores all terms together ([narrow-window.css:676](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/narrow-window.css:676)), so travel is zero there and does not go negative. Outline subtracts the same padding from `avail` ([OutlinePanel.tsx:290](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/OutlinePanel.tsx:290)); Structure measures the grid content box ([StructurePanel.tsx:654](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/StructurePanel.tsx:654)). Expanded’s flex scroller still ends at the resting content edge and retains its own 0.75rem scroll clearance ([outline-mode.css:389](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/outline-mode.css:389)). The uncompensated top bar is the exception.

5. **Removing the list-wide about room is correct.** The negative margin still bleeds the head exactly to the band edge using the new ordinary right inset ([outline-mode.css:405](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/outline-mode.css:405)), while the head itself reserves the full corner-button room and minimum height ([mode-band.css:2023](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/mode-band.css:2023)). `StructureNotice` and `StructureArriving` are inside that head ([StructureMode.tsx:361](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/modes/structure/StructureMode.tsx:361)); nothing below it needs the reservation.

6. **Prose right margin: I agree with declining it.** On no-hover screens the right pad is already `max(1.25rem, 19px)` ([narrow-window.css:306](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/narrow-window.css:306)), while the documented mark, inset, and hairline consume approximately 19px ([narrow-window.css:281](/var/tmp/spideryarn-worktrees/fbtj0vqa-structure-ipad/src/web/styles/narrow-window.css:281)). Only about one pixel is safely reclaimable.

That removes most per-frame Structure work and fixes the coalesced-anchor case in the same state machine. The plan’s bottom-bar arithmetic is otherwise clean, but “content box stays the same” and the administrator-only trace are overclaimed unless explicitly limited to bottom travel and the tested owner state.
