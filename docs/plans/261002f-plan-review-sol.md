1. **P1 — `root_gist === excerpt` is not a sound provenance test.** The fallback chooses the first non-null value, not the first unequal value: `root.gist ?? root.summary ?? excerpt` ([library-scalars.ts:134](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/library-scalars.ts:134)). A model gist or summary can reproduce the excerpt verbatim, in which case the proposed equality test labels AI text as author text. The plan’s “right for every existing row” and “same answer” claims are false ([plan:153](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/docs/plans/261002f-the-three-faces-for-everyone-and-every-surface-voiced.md:153)).

   The separate concern about the excerpt changing while `root_gist` stays stale is not present in the supported lifecycle: `rootGist` is explicitly derived while `excerpt` is carried ([pg-revisions.ts:186](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/store/pg-revisions.ts:186)), and publication derives and writes the scalars in the same transaction ([pg-revisions.ts:2319](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/store/pg-revisions.ts:2319)).

   **Change:** persist `root_gist_source: "gist" | "summary" | "excerpt"` or equivalent at derivation time. Existing rows can be backfilled from the stored root node’s field presence, rather than text equality; genuinely indeterminate rows should be `unknown`/UI, not guessed author.

2. **P1 — “unknown title override means author” will visibly misvoice renamed titles.** `titleFor()` substitutes the reader’s override but returns only `Meta`, discarding that provenance ([library-scalars.ts:296](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/library-scalars.ts:296)). `loadArticle` applies it before constructing `Article` ([pg.ts:2697](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/store/pg.ts:2697)), while `Article` has no override flag ([types.ts:1729](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/types.ts:1729)). The rename hook therefore starts unknown and learns only after a write ([TitleEditor.tsx:182](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/web/TitleEditor.tsx:182)). Masthead, Metadata and unread-paper titles can consequently be the reader’s words while rendered as author text.

   The same loss exists in library search, which coalesces `title_override` without selecting its presence ([pg-shelf.ts:633](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/store/pg-shelf.ts:633)), and citation matches ([pg-cited-in-spideryarn.ts:69](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/store/pg-cited-in-spideryarn.ts:69)).

   **Change:** resolve titles centrally as `{ text, voice }` or `{ text, overridden }` and carry that through owner `Article`, `UnreadPaper`, `LibraryHit`, and `CitedInSpideryarn`. Seed `useArticleRename` from it. Only explicitly public DTOs may safely default to author; they deliberately never select the private override ([public/dto.ts:134](/home/greg/code/spideryarn2/.claude/worktrees/fbpeanctkn-ai-faces-for-everyone/src/public/dto.ts:134)).
