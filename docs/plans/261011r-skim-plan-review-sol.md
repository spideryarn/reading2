1. **High — the two-phase repair terminates, but it is neither complete nor order-independent.**  
   Evidence: the plan adds carries once, then runs the existing remove/move phase without revisiting additions ([plan:65](/var/tmp/spideryarn-worktrees/fbwu83xh-skim-purpose-and-lengths/docs/plans/261011r-skim-more-always-longer-than-gist-a-pass-intro-shorter-quotes-skim-for-box.md:65)); the existing shrink phase may drop a carry or move a stop, changing both adjacent inequalities ([src/skim.ts:1101](/var/tmp/spideryarn-worktrees/fbwu83xh-skim-purpose-and-lengths/src/skim.ts:1101)). For example, at `q=8`, own counts `3/2/3` become `3/3/3` after carrying into More. If lengthening stops at that still-unfixed first pair, shrinking eventually produces `1/3/4`; if Most is lengthened first, `2/3/4` is attainable, preserving another Gist stop. Worse, a validated four-stop route with own counts `2/1/1` can be transformed to the valid `1/2/3` using one carry into More, one into Most and one depth move, but the sequential phases can drop the More carry after the move and finish at `1/1/3`, which `growthFailure` rejects. The phases are individually finite, so termination is sound; the result is not confluent or complete.  
   Concrete fix: compute the final count state before mutating stops. With only three passes and at most 36 kept stops, enumerate the bounded numbers of `Gist→More` and `More→Most` moves plus legal carry counts, choose lexicographically by “preserve Gist, fewest moves, fewest carry changes, quote priority,” then apply that solution. Add an exhaustive property test over all own/carry count states within the caps, asserting that the repair succeeds whenever a legal state is reachable.

   Evidence: the guide requires old-old control runs, before/after arms separated in time, recorded source hashes, shuffled like-for-like pairs with a checked balanced key, a fresh blind judge assessing both benefit and fidelity, and comparison against control variation ([prompting-guide.md:196](/var/tmp/spideryarn-worktrees/fbwu83xh-skim-purpose-and-lengths/docs/project/prompting-guide.md:196)). The six-article set has no `q=8` case and was previously run with no profile, despite intros being profile-shaped.  
   Concrete fix:

   - run and save `skim/12` twice before changing the module, then `skim/13` twice afterward;
   - record both hashes and immutable result files;
   - compute actual-walk Idea coverage for Gist and More, not Gist alone;
   - compare length changes against old-old variation and blind-read changed quote choices for usefulness/fidelity;
   - judge each intro with its actual repaired pass, asking both “does this orient the reader?” and “does it reveal, invent, or mention the reader?”;
   - include at least one real or fixed fixture at `q=8`, one at `q=11`, articles containing competing >90-word quotes, and a small profiled/purpose-shaped subset.

   Evidence: mounting only over a ready route preserves the automatic-run invariant ([src/web/SkimPurpose.tsx:22](/var/tmp/spideryarn-worktrees/fbwu83xh-skim-purpose-and-lengths/src/web/SkimPurpose.tsx:22)); saving first and then calling unforced `ensure()` is also correct because the profile hash drives replanning.    Concrete fix: specify and test one state machine: the editor and re-plan banner action are mutually exclusive; Edit/save is disabled while `owner.starting`, `owner.job`, or `owner.rewriting`; the local double-submit ref remains held until `ensure()` has started; and a changed purpose still follows the existing ambiguous-save reconciliation. Keep the canonical shared-field question—“What do you want from this piece?”—and use helper copy such as “Skim will plan around this; other modes use it too.” “What are you skimming for?” implies a Skim-only value even while the product stores a shared purpose.
