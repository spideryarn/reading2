F1 — should — The touch guarantee is incomplete. `mouseOnly` applies only to `useHover`; `useFocus` remains enabled (`src/web/Tooltip.tsx:303-336`). A tap can focus before its click, a sequence the existing precedent explicitly handles (`src/web/SkimPanel.tsx:1363-1373`). Thus an iPad tap can briefly open—or, if activation is cancelled, leave open—the citation dialog despite the plan promising it never appears (`docs/plans/261020g-…md:94-99`). Fix: record touch/pen at `pointerdown`, refuse focus-driven opening for that press, clear on click/cancel, and test `pointerdown → focus → click` plus a cancelled press.

F2 — should — “A press closes the card” does not keep it closed while the disclosure panel is open. `Tooltip` will reopen on any later hover or focus whenever `enabled` remains true (`src/web/Tooltip.tsx:303-341`), while `ShutNote` currently owns its disclosure state privately (`src/web/marginalia/MarginaliaColumn.tsx:358-405`). Fix: expose/lift the disclosure state, set `enabled={!panelOpen}`, and close the card when opening the panel. The `Tooltip` must clone the actual `.marg-shut-button`, not the surrounding `<div>`, because interaction and ARIA props are applied to the cloned child (`src/web/Tooltip.tsx:400-448`). Test leaving and re-entering/refocusing the line while its panel remains open.

F3 — should — Two `CiteCard` actions rely on the caller to close the card, but the plan and tests only require that their senders are called. `onOpen` is documented as closing first and `onJump` as caller-closing (`src/web/ProseHoverCard.tsx:2276-2282`); the prose implementation explicitly closes before both actions (`src/web/ProseHoverCard.tsx:854-865`). Without equivalent wrappers, *Open in Sources* leaves a floating dialog over the newly opened mode, and a numbered jump leaves it anchored to the passage scrolled away. Fix: wrap both context senders with `setCardOpen(false)` before dispatching, and assert the dialog closes as well as the sender firing.

F4 — should — The cut-line content will be stale when the line opens. Delegated content is snapshotted by `contentFor` when opened and only changes through `refresh` (`src/web/useDelegatedCard.tsx:136-160`). Attribute refresh observes only the trigger’s named attributes (`src/web/useDelegatedCard.tsx:203-207`), while `BlockLinkCard` currently names none (`src/web/BlockLinkCard.tsx:388-398`). `ShutNote` puts `data-open` on the parent (`src/web/marginalia/MarginaliaColumn.tsx:368-401`), and that attribute removes truncation (`src/web/styles/marginalia.css:218-231`). Thus a card opened before clicking can keep repeating the words after they wrap, contrary to the plan (`docs/plans/261020g-…md:69-70`). Fix: mirror expansion state onto the trigger and observe it, or explicitly refresh/close the delegated card on activation. Also refresh on label resize if “actually cut” is intended to remain true through rotation/window resizing. Extend the test to open the card, expand the line, and verify the drawn words disappear.

F5 — should — A context preserves the `marginNotes` prop identity, but an unmemoized provider value still bypasses `memo(TableView)` and rerenders every `CitationNote` consumer. This matters because Reader rerenders 77–79 times during a long scroll (`src/web/reader/Reader.tsx:2523-2526`), while the existing margin memo is deliberately kept stable (`src/web/reader/Reader.tsx:2599-2675`). Fix: require a `useMemo`-stable context value built from the four stable senders, changing only when a sender genuinely changes, and add a render-count assertion for an `?at=`-only update.

F6 — should — The plan copies `TermChip`’s interactive-tooltip shape but omits its viewport-height protection. `TermChip` wraps its reused card in an internal scroller specifically so its final actions remain reachable (`src/web/SkimPanel.tsx:1328-1348`; `src/web/styles/skim.css:500-518`). A marginal citation card can contain a long entry, abstract/web note, verdict, up to twenty cited-passage jumps (`src/web/ProseHoverCard.tsx:2455-2526`), and the plan stacks several works in one card (`docs/plans/261020g-…md:39-42`). `Tooltip` only flips and shifts; it does not resize content (`src/web/Tooltip.tsx:274-294`). Fix: add an inner max-height/overflow wrapper, preserving the arrow outside the scroller, and browser-check that the action row is reachable in a short viewport.
