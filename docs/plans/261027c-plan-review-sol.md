## Findings

- **P1 — The DataCite fallback still admits a different OpenAlex work by the same collaborating pair.** [plan:58](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:58>), [citation-index.ts:490](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:490>), [citation-index.ts:581](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:581>). Suppose DataCite says arXiv X is title A by Smith, Jones and Lee, while OpenAlex has wrongly attached X’s DOI to title B by Smith and Jones. The titles disagree, but `twoStructuredAuthorsAgree` returns true, so B’s citers are listed. BERT only proves safety when the wrong work shares no authors. This is especially weak for recurring teams and organizational creators, which DataCite explicitly permits. Require title + author as usual, but for the title-mismatch exception require near/full one-to-one author-list equivalence; conservatively refuse truncated or ambiguous lists. [DataCite creator fields and organizational names](https://schema.datacite.org/meta/kernel-4.4/doc/DataCite-MetadataKernel_v4.4.pdf).

- **P1 — Treating every spaced ` - ` as prose erases a mathematical operator and can confirm the wrong DOI.** [plan:74](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:74>), [article-registry.ts:115](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/article-registry.ts:115>), [article-registry.ts:255](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/article-registry.ts:255>). After the proposed normalization, `Learning from x - y in complex networks` equals `Learning from x y in complex networks`; with an agreeing author, both Cited by and `withRegistryFacts` accept it. The current contract deliberately preserves maths operators. The measured case needs only arXiv’s whitespace-surrounded `--` normalized to prose punctuation; Unicode dashes are already punctuation. Keep a spaced single hyphen as an operator and add a negative spaced-minus test.

- **P1 — Dropping every digit makes distinct organizational authors identical.** [plan:74](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:74>), [article-registry.ts:129](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/article-registry.ts:129>), [bibliographic.ts:404](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/bibliographic.ts:404>). “No name has digits” is false for organizations: Crossref and DataCite both support organizational creators. `Working Group 1` and `Working Group 2` collapse to the same words and can corroborate the wrong same-title record. Strip only article-side footnote suffixes attached to a name token, such as `Webb1`, rather than globally deleting digits from both sides. Preserve standalone and registry-side digits; add an organizational-name negative.

- **P1 — A DataCite outage is classified as an identity disagreement, suppressing the retryable outcome.** [plan:66](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:66>), [citation-index.ts:525](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:525>), [citation-index.ts:922](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:922>), [types.ts:8292](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/types.ts:8292>). `lookupWork(...).kind === "unavailable"` is absence of evidence, not evidence that the DOI failed confirmation. Returning `unconfirmed` shows the permanent-looking DOI warning without “Try again”; after a successful OpenAlex refresh it also prevents the stale path because `theList` treats `unconfirmed` as an affirmative answer. Make confirmation tri-state: confirmed, disagreed/not-found, or unavailable. Propagate unavailable as `unavailable`; do not serve stale data unless its identity can still be confirmed.

- **P2 — Confirmation should be lazily memoized once per request.** [plan:102](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:102>), [citation-index.ts:824](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:824>), [citation-index.ts:950](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:950>), [citation-index.ts:1016](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:1016>). A successful fresh DOI path confirms in `askWork`, then confirms again when converting the newly stored answer; a topic request confirms the plain and topic rows separately. Use one request-local, lazy promise for the DataCite identity and pass one confirmer through `askWork`, `answerFor`, and the topic path. Each target should still be compared, but the identity should be loaded once.

- **P2 — “First 19 + last for the target” also needs the title-search target constructor.** [plan:70](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:70>), [citation-index.ts:702](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/citation-index.ts:702>). `parseOpenAlexWork` constructs DOI targets, but `titleMatchOf` separately constructs cached targets through `authorsOf`. If only the named DOI parser changes, DOI-less articles still cannot match a last-listed author. Route both target constructors through the selection helper while leaving `parseOpenAlexCiters` on the first 20. The selection itself does not create a new false confirmation, though it trades away author #20.

- **P3 — Two plan facts are inaccurate.** [plan:57](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:57>), [bibliographic.ts:173](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/bibliographic.ts:173>), [plan:70](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/docs/plans/261027c-cited-by-confirms-a-doi-against-arxiv-own-record.md:70>), [schema.ts:9233](</var/tmp/spideryarn-worktrees/fbufn2xj-doi-confirm/src/db/schema.ts:9233>). Found registry records are cached for 180 days; only misses use seven days. The author cardinality limit is part of `citation_index_lookups_shape`, not a constraint named `citation_index_lookups_target_authors`. No migration is still correct because the cardinality remains 20.

For an exact canonical arxiv.org paper URL, I found no ordinary case where the identifier names another paper: arXiv documents it as a unique article identifier, with an unversioned identifier referring to its latest version. [arXiv identifier documentation](https://info.arxiv.org/help/arxiv_identifier.html). One wording caveat: `arxivDoiAtAddress` uses the shared parser, which also recognizes designated Hugging Face and alphaXiv paper pages; normal ingest canonicalizes those back to arxiv.org, but the helper itself does not enforce the plan’s literal “arxiv.org address” boundary.

Overall, DataCite is the right independent identity source and is simpler than weakening title matching. I would keep that design, strengthen only its title-mismatch author comparison, narrow the two normalizations, and use a lazy request-scoped tri-state confirmer. No files were edited.
