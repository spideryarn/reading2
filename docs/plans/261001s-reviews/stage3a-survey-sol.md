## 1. Proposed Stage 3b migration order

1. Let Structure stage 2 finish and stabilise first. Its whole-document call is already schema-constrained in the working copy (`src/hierarchy.ts:699-705`), while scoped expansion remains unschematized (`src/hierarchy-expand.ts:663-681`). This keeps the survey from competing with the concurrent `src/hierarchy*.ts` work.

2. Before migrating Ideas—or any other member of a shared group—add schema identity to `sharesArticleCache`, or explicitly declare different schemas incompatible. It currently compares only `STAGE_EFFORT` and `ARTICLE_RENDERER` (`src/pipeline.ts:326-342`), whereas the plan requires schema identity, red-first grouping tests, and a paid non-zero-cache-read witness (`docs/plans/261001s-…md:258-265`).

3. Migrate the three observed failures in the specified order:

   1. Ideas, including the same-draw `high`/`medium`/`low` evaluation, without changing production effort (`docs/plans/261001s-…md:267-269`).
   2. Sketch at `low`, with a same-effort before/after quality panel (`docs/plans/261001s-…md:270-271`).
   3. Quotes, adding a validity count to its production-generator eval (`docs/plans/261001s-…md:272`; `scripts/eval/quotes-spread-eval.ts:13-26`).

4. Finish Messages calls by the existing cache groups:

   - `ids/high`: Tweets, Timeline, Quiz, FAQ, Simple; Ideas is already done. These are currently one renderer/effort group (`src/models.ts:1872-1908,1722-1843`), but their schemas differ, so the new identity rule must prevent false compatibility.
   - `text/medium`: Glossary after Quotes (`src/models.ts:1725-1752,1877-1881`).
   - `text/high`: Arc (`src/models.ts:1722-1724,1870-1872`).

## 2. Reader-visible behaviour that must be preserved

- Search, Referee criteria, and Referee claims show validated items before the model finishes (`src/search.ts:677-686`; `src/referee-criteria-run.ts:660-675`; `src/referee-claims-run.ts:528-538`). Keep `hitExtractor`, per-item validation, duplicate-top-level-key detection, and the authoritative final parse. The migration test must prove that the first item is emitted before stream completion and that the final list still agrees with the preview (`src/search.ts:836-889`; `src/referee-criteria-run.ts:821-864`; `src/referee-claims-run.ts:678-718`).

- Referee candidates displays ordinary prose while hiding the fenced shortlist, including while it is still arriving (`src/web/CandidatesPanel.tsx:749-770`). A response-wide schema would delete that prose. Preserve the current hybrid format, or make the shortlist a second call; do not attach a schema to the existing combined response.

- Mirror emits raw JSON deltas only to keep the connection alive, explicitly not for display (`src/referee-mirror.ts:475-489`). Keep the delta events even though the completed response becomes schema-constrained.

- The Messages stages expose only progress derived from byte or approximate-item counts—not model prose or parsed output—such as Ideas (`src/ideas.ts:975-987`), Sketch (`src/sketch.ts:559-569`), and Simple (`src/simple-summary.ts:702-708`). Structured output can retain those callbacks unchanged.

- Preserve tolerant, reader-visible fallbacks in the schemas where they are intentional: Tweets accepts legacy string posts (`src/tweets.ts:403-422`); Search defaults missing confidence to 50 and missing reasoning to empty text (`src/search.ts:335-363`); Claims permits absent reasoning and blanks it (`src/referee-claims.ts:1143-1185`); Simple checker accepts a missing ordinal and conditional `why` (`src/simple-check.ts:107-113`). Encoding only the prompt’s ideal shape would change these failure-path results.

- Citation and Debate fences/preambles are not displayed directly: readers receive validated stored rows. Their parsers can move from fenced JSON to the schema’s bare JSON without a UI change (`src/debate.ts:1728-1770`; `src/citation-find.ts:354-408`).

## 3. Surprises

- The plan’s expected Dig-deeper misfit is no longer a JSON call. It asks for a one-line keyword query and reads the first non-empty line (`src/dig-deeper.ts:295-317,331-344`). It therefore belongs in the web-search annotation audit, but not this JSON matrix.

- `src/citations.ts` is indeed ordinary schema-shaped JSON: the name is unrelated to web-search annotations (`src/citations.ts:1674-1694`).

- No model-answer call uses `parseJsonFrom`; every such call in `src/` reads stored state. The model-facing lenient parser is `parseJsonAnswer`, plus Search’s special `parseHits` path (`src/parse-json.ts:469-480`; `src/search.ts:377-476`).

- Labels is the only Messages answer whose present shape does not map strictly onto the supported subset without changing the wire shape: exact `[ordinal,label]` tuples need unsupported tuple keywords (`src/labels.ts:1379`; `src/messages-structured-output.ts:50-70`).

- The three streaming JSON calls and Mirror intentionally do not reject every `length`/filter ending before parsing. A provider may report `length` after closing a valid JSON object, so they parse and keep that object (`src/search.ts:803-812`; `src/referee-criteria-run.ts:786-795`; `src/referee-claims-run.ts:644-653`; `src/referee-mirror.ts:1673-1682`). Stage 3b’s general “checks before parse” rule needs this explicit exception.

- Four already-strict calls still parse before fully checking completion: PDF authors (`src/pdf-authors.ts:671-679`), PDF figure location (`src/pdf-figure-locate.ts:395-401`), PDF front matter (`src/pdf-frontmatter.ts:431-443`), and PDF transcription, whose finish check occurs much later (`src/pdf-read.ts:906-920,2932-2952`). Shelf scoring checks only `length`, not all non-clean endings (`src/shelf-terms/model-scores.ts:332-343`).

- Adding schema identity will make most current cross-stage cache groups incompatible because their output shapes genuinely differ, even when article bytes and effort match. That is the correct outcome unless two stages deliberately share the same schema; the current predicate cannot express it (`src/pipeline.ts:317-342`; `docs/plans/261001s-…md:263-265`).
