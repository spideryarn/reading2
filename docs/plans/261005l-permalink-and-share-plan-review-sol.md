A browser-only v1 is feasible, but I would revise this plan before implementation. The server’s publication and billing boundaries hold up; the main gaps are in browser state and navigation. No files changed.

1. **P1 — Sharing state must belong to a specific slug.**  
   The proposed HighPowerIntent pattern changes its target in [add-high-power.ts:94](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/add-high-power.ts:94), while retaining states such as `on` and `unknown`. Its request completion also updates state without checking whether the target changed ([line 169](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/add-high-power.ts:169)). A retry can adopt another slug: share A, retry onto B, and the copied controller can say B is public without sharing it; unticking would privatise B while leaving A public.  
   **Do:** bind confirmed state, requests and compensating unshares to their original slug. On a target change, read B’s state and reset the confirmation instead of carrying A’s state across. Test a slug change both after success and during an unanswered request.

2. **P2 — “Nothing built yet” is not a safe sharing inventory.**  
   The proposal at [plan:84](/var/tmp/spideryarn-worktrees/import-permalink-and-share/docs/plans/261005l-permalink-and-share-while-an-article-is-importing.md:84) assumes a fresh article. But [freeSlug:4146](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/jobs.ts:4146) can adopt an existing shelf article with generated material and personal notes already present. Sharing then exposes that published revision immediately, while the confirmation describes generated material as something that would be shared *if built*. Metadata deliberately withholds its share offer when inventory is unknown ([AccessSharing.tsx:576](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/AccessSharing.tsx:576)).  
   **Do:** use the actual inventory for an adopted article. A synthetic empty inventory is appropriate only when the browser has established that no published article exists. Also avoid promising that an adopted article becomes readable only after this job finishes.

3. **P2 — Part 2 must restrict its match to import jobs.**  
   [Plan:63](/var/tmp/spideryarn-worktrees/import-permalink-and-share/docs/plans/261005l-permalink-and-share-while-an-article-is-importing.md:63) matches any live job for the slug. Mode jobs can carry a URL: `enqueue` reads it from the existing article when the request supplies none ([jobs.ts:3579](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/jobs.ts:3579)). Redirecting that job to `/add/<url>` starts a default import, because AddPage posts on arrival ([AddPage.tsx:542](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/AddPage.tsx:542)). A mode job plus an unrelated article 404 must not become a new import.  
   **Do:** use the same import predicate as the permalink button. Test an unreadable article with a live mode job, and a return from AddPage whose article still 404s. Ordinary successful imports do not inherently loop; the broad match creates the problematic recovery path.

4. **P2 — `loaded` does not establish a fresh absence of jobs.**  
   Waiting for the engine’s first list covers a cold start, but an existing tab may already have `loaded: true` with an old empty snapshot. An import started elsewhere can therefore still produce “Not shared”. The engine explicitly provides [afterFreshList:362](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/jobEngine.ts:362) for this distinction. Conversely, a failed first list leaves `loaded` false and records an error ([line 701](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/jobEngine.ts:701)); the proposed loading branch would conceal that indefinitely.  
   **Do:** reconcile after the article’s 404 before concluding there is no import, and expose list failure/authentication recovery instead of an unexplained spinner.

5. **P2 — Automatic completion can remove the sharing confirmation or its result.**  
   AddPage automatically leaves when the purpose box is neither focused nor unsaved ([AddPage.tsx:785](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/AddPage.tsx:785)). Reading the proposed sharing confirmation does not satisfy either condition. A fast import can navigate away before the owner presses *Share it*. Copying the existing fire-and-forget settlement also allows navigation before a refusal or uncertain sharing result is visible ([line 182](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/AddPage.tsx:182)).  
   **Do:** hold automatic navigation while confirmation is open or sharing is unresolved. Resume after success; let the reader see a failure before explicitly opening the article.

6. **P2 — The copied address is not guaranteed “for good” across retry.**  
   [Plan:25](/var/tmp/spideryarn-worktrees/import-permalink-and-share/docs/plans/261005l-permalink-and-share-while-an-article-is-importing.md:25) overstates stability. Normally retries retain the slug, including uploads. But [slugForRetry:4265](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/jobs.ts:4265) adopts a published shelf article for the same URL. Example: A fails; a fresh paste imports that URL as B; retrying A returns B. The previously copied A address has no alias to B. Cancellation can also leave the copied address permanently unreadable.  
   **Do:** describe it as the address of **this import**, acknowledge failure/cancellation, and update the displayed link when Retry returns another slug. A guarantee covering previously distributed links needs server support.

7. **P2 — The HighPowerIntent retry cap can silently abandon sharing before a queued import starts.**  
   The plan’s “second or two” window at [line 108](/var/tmp/spideryarn-worktrees/import-permalink-and-share/docs/plans/261005l-permalink-and-share-while-an-article-is-importing.md:108) begins only once a worker claims the job. Jobs can wait longer. HighPowerIntent caps 404 retries at five minutes ([add-high-power.ts:59](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/add-high-power.ts:59)), then enters `refused`. Its completion settlement only sends from `waiting`, so finishing later does not revive that intent ([line 161](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/add-high-power.ts:161)).  
   **Do:** define queued-job behavior explicitly and ensure completion gives an abandoned pre-row intent another attempt. Do not inherit this cap unchanged.

8. **P2 — Unsharing is unrestricted, but not allowance-free.**  
   [Plan:101](/var/tmp/spideryarn-worktrees/import-permalink-and-share/docs/plans/261005l-permalink-and-share-while-an-article-is-importing.md:101) calls switching private “free”. It sends no new paid operation, but it removes the public discount from charged ingest and High-powered AI rows. Usage is recomputed from current visibility ([pg-billing.ts:503](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/store/pg-billing.ts:503)).  
   **Do:** reuse `UNSHARING_COSTS_ALLOWANCE` beside the public state, as Metadata does ([AccessSharing.tsx:555](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/AccessSharing.tsx:555)). Keep unsharing available without another confirmation.

9. **P3 — The candidate incorrectly says it is built.**  
   [Plan:20](/var/tmp/spideryarn-worktrees/import-permalink-and-share/docs/plans/261005l-permalink-and-share-while-an-article-is-importing.md:20) says “Status: built”, despite the stated plan-only scope and empty landing record.  
   **Do:** mark it proposed until implementation and validation exist.

The claims I checked and found true:

- **The job provides an address promptly.** `enqueue` assigns `Job.slug`; `Job.url` and `upload.id` survive the browser projection ([types.ts:3611](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/types.ts:3611), [routes.ts:6632](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/routes.ts:6632)). Uploads obtain their job after transfer.
- **An owner can share before publication.** The route requires ownership, a row and non-minimal processing, but no current revision ([pg-visibility.ts:171](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/store/pg-visibility.ts:171)). The claim creates that row when opening its draft.
- **An unpublished draft is invisible on every public surface inspected.** Article reads, assets and heads require the current-revision join ([public-reader.ts:583](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/store/public-reader.ts:583)); shelf/showcase use the guarded listing ([public-library.ts:257](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/store/public-library.ts:257)); “cited in Spideryarn” also joins the current revision ([pg-cited-in-spideryarn.ts:90](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/store/pg-cited-in-spideryarn.ts:90)). Comments and saved-search queries do **not themselves** join revisions, but are only reached after the article’s publication/readability gate. I found no reachable disclosure through them.
- **An owner’s early full-import visit currently becomes “Not shared”, with no import retry.** The owned/public fallback and final branch match the plan ([access.ts:545](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/article/access.ts:545), [ArticlePage.tsx:164](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/web/article/ArticlePage.tsx:164)).

Billing remains sound: an unsettled reservation counts **200 points regardless of visibility**; after successful settlement it counts **100 while public**. Admission remains conservative, and settlement atomically records success and the article ID ([pg-billing.ts:505](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/store/pg-billing.ts:505), [line 1700](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/store/pg-billing.ts:1700)). Greg’s admin exemption remains unchanged.

The provisional first publication is safe for visitors: it contains readable prose and a marked headings tree, not an unpublished draft. The public projection preserves that marker ([dto.ts:383](/var/tmp/spideryarn-worktrees/import-permalink-and-share/src/public/dto.ts:383)). Visitors get the real structure on their next load; live replacement is owner-only.

A delayed `rightsConfirmed: true` still represents the owner’s statement when the rights tick and explicit press created the intent. Seconds of retry do not invalidate it. Keep that consent scoped to the confirmed target and cancel unsent retries when withdrawn.

For a simpler Part 2, keep `/read/<slug>` open, show the matching import’s existing `JobCard`, and retry the article read on completion. That avoids navigating to a page whose arrival performs another POST. Private-link creation and a visitor waiting page can remain deferred.

**Verdict: REQUEST CHANGES — retain the browser-only approach, but resolve target identity, confirmation/navigation and retry behavior before building.**
