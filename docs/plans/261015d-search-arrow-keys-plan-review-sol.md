1. **P1 — The history behavior contradicts the plan.** Evidence: the plan says `?at=` follows scrolling without a history write ([plan:20](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/docs/plans/261015d-search-arrow-keys-step-the-results.md:20)), but a row’s `onOpen` calls `onJump` ([SearchMode.tsx:813](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/modes/search/SearchMode.tsx:813)), `bandJump` calls `jumpTo` ([Reader.tsx:836](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/reader/Reader.tsx:836)), and `jumpTo` explicitly pushes `?at=` history ([useReadingPosition.ts:263](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/reader/useReadingPosition.ts:263)). Thus successful arrow steps create Back entries and return-chip journeys. **Fix:** give keyboard traversal a non-pushing path—`setOpenHit`, direct `scrollToBlock`, and narrow-band handoff—while retaining `bandJump` for deliberate row presses. Add a test proving several arrow steps do not push history.

2. **P2 — Following the selected row fails after a narrow-window jump, and repeated hidden steps lose saved focus.** Evidence: `bandJump` makes the covering band step aside ([Reader.tsx:836](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/reader/Reader.tsx:836)); that makes `.mode-band` `display:none` ([narrow-window.css:409](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/styles/narrow-window.css:409)), so `followScrollTop` sees zero height and returns ([list-step.ts:37](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/list-step.ts:37)). Returning to the band does not change `openKey`, so an effect depending only on it does not rerun ([SearchPanel.tsx:1754](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/SearchPanel.tsx:1754)). Also, `bandJump` records focus unconditionally, unlike `bandStepsAside`’s preservation guard ([Reader.tsx:830](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/reader/Reader.tsx:830)); another arrow while the band is hidden replaces the saved band focus with the Back chip/body. **Fix:** observe the list becoming visible, as Outline does, and use a keyboard-specific band-aside helper that preserves focus once already away.

3. **P2 — Streaming can move the open row without triggering the follow effect.** Evidence: pending searches append hits live ([SearchMode.tsx:675](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/modes/search/SearchMode.tsx:675)); every update is reordered and filtered ([SearchMode.tsx:703](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/modes/search/SearchMode.tsx:703)), while an open key that remains present is deliberately retained ([SearchMode.tsx:741](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/src/web/modes/search/SearchMode.tsx:741)). An effect keyed only by `openKey` therefore does not run when newly streamed rows push the selected row offscreen. The plan also never states whether a newly inserted row before the current result is considered already passed. **Fix:** specify live-list semantics—simplest is “each press uses the order currently displayed”—and rerun following when the selected row’s index changes, without reacting to appends after it.

4. **P2 — The proposed tests cannot catch the history, ordering, visitor, streaming, or follow failures.** Evidence: the integration case contains one literal result ([test:758](/var/tmp/spideryarn-worktrees/fbb4vfq5-search-arrow-keys/tests/the-marks-in-the-prose-belong-to-the-mode-showing.test.tsx:758)); it can prove first/open/end state, but not movement between rows, chosen ordering, filtering, reordering, visitor wiring, actual scrolling, or history. The helper tests prove only pure arithmetic. **Fix:** add focused integration coverage with at least three results, a reorder/insertion ahead of the open row, visitor Search, history assertions, and a hidden-then-restored narrow band.

In those states arrows will step Search behind the open surface. **Fix:** state whether that is intended.
