1. **P1 — Reporting from an effect on `error` is not sound.** The effect in [useDictation.ts](/var/tmp/spideryarn-worktrees/fbm2pyfq-dictation-mic-error/src/web/useDictation.ts:819) observes rendered state, not failure occurrences. React can coalesce `setError(null)` followed by the previous string, identical consecutive strings cause no state change, and an unmount before passive effects run loses a failure entirely. It also reads mutable cause/context after the failure, allowing incorrect metadata. Use one synchronous `publishFailure(message, cause, context)` wrapper that reports and updates display state; hide the raw setter. Deduplicate repeated calls for the same incident using the existing artifact/session identity plus code. Retry should create a new incident, while abandoned/unmounted work should remain unreported.

2. **P1 — `NotAllowedError` and especially `SecurityError` do not justify “Allow it for this site.”** `NotAllowedError` also covers global/device denial, Permissions Policy, and insecure contexts; `SecurityError` now means media support is disabled on the document, not ordinary site permission. Safari additionally has real defects that return `NotAllowedError` despite permission being granted, including an iOS audio-service failure fixed only recently. WebKit also applies gesture rules when reprompting after denial. Use neutral copy such as “This page wasn’t allowed to use the microphone. Check the browser and device microphone settings…” or distinguish permission state where available. [W3C specification](https://www.w3.org/TR/mediacapture-streams/), [WebKit gesture handling](https://bugs.webkit.org/show_bug.cgi?id=203362), [recent iOS `NotAllowedError` device failure](https://bugs.webkit.org/show_bug.cgi?id=319706).

3. **P1 — The fallback rule needs explicit multi-request tests.** [deviceMissing](/var/tmp/spideryarn-worktrees/fbm2pyfq-dictation-mic-error/src/web/mic-devices.ts:246) correctly treats `OverconstrainedError` and `NotFoundError` as recoverable when another route remains. Once fallback begins, retain the **last attempted request’s** rejection and its step; the earlier missing-device error no longer explains why capture ultimately failed. Test at least: exact `NotFound` → fallback `NotAllowed`; exact `Overconstrained` → named-default `NotFound` → unconstrained `NotReadable`; and a resolved stream containing no audio track, which needs a closed synthetic reason such as `no-track`. Terminal unconstrained `NotFoundError` can map to `[mic-none]`; `NotReadableError`, `AbortError`, and `InvalidStateError` should remain general.

4. **P2 — The privacy claim is correct only because the reporter constructs a fresh error with a literal name.** `neverAuthored` does not protect a custom `err.name`: [sanitise](/var/tmp/spideryarn-worktrees/fbm2pyfq-dictation-mic-error/src/monitoring-scrub.ts:219) copies it into both the sanitized name and message, while [safeEvent](/var/tmp/spideryarn-worktrees/fbm2pyfq-dictation-mic-error/src/monitoring-scrub.ts:150) preserves the exception type and passes tags/fingerprints unchanged. A reader-controlled custom name would therefore leak. The proposed literal `DictationFailure`, bounded code regex, and closed tag sets are safe, but add an end-to-end test using a sentinel custom name and assert it is absent after `sanitise` and `safeEvent`. Prefer not to expose the generic context or original exception to the reporter contract.

5. **P2 — The proposed metadata would identify the sentence but not adequately diagnose #551.** `context.kind` means vocabulary scope—only `article` or `profile`—not whether Greg was in chat, Feedback, Quiz, or another box. The scrubber also removes browser contexts and request/user-agent data. Add closed `dictation_surface` and coarse browser engine/platform tags. Preserve whether a preferred/default request fell back or was honoured, because a successful fallback followed by `[mic-silent]` otherwise loses the strongest clue that the wrong microphone opened.

6. **P2 — `[mic-full]` is missing from the non-failure set.** It is the intentional fifteen-minute ceiling and keeps everything recorded up to that point, so reporting it as an error will create noise. Add it to the skipped codes and test the complete informational-code set.

7. **P2 — A permission request can remain pending indefinitely.** `getUserMedia()` is allowed to neither resolve nor reject when the prompt is ignored, so no `error` state or Sentry event will occur. If the promise is “every dictation failure reaches Sentry,” add a bounded, once-per-attempt `mic-opening-stalled` observation, carefully stopping any stream that resolves later. [MDN documents the indefinitely pending case](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

8. **P3 — Making `report` required is the right dependency shape.** An optional callback would recreate silent omission, importing product monitoring would break the fleet’s leaf-module boundary, and attaching reporting to `Transcriber` would miss pre-upload failures. Keep it required, hold it in a ref, and let the fleet wrapper pass one explicit stable no-op. A product-specific wrapper could reduce repetitive wiring later, but is not necessary for this change.
