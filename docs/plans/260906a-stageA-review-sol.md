No correctness defect found in the Stage A implementation. The PNG writer, validator, pairing gate, transparency rule, and ref construction are sound. I found four test/documentation weaknesses.

### Findings

- **A-1 — P1: The persistent ref contract lacks a known-answer test.** The tests establish determinism, format, and sensitivity to each field, but they would all pass if the separator, field order, caption-hashing scheme, or outer hash algorithm changed without bumping `PDF_FIGURE_REF_VERSION` ([tests/pdf-figures.test.ts:452](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/tests/pdf-figures.test.ts:452), [src/pdf-figures.ts:587](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/src/pdf-figures.ts:587)). Because these refs become stored identifiers, their exact value is observable behaviour. A golden vector would lock the contract: the existing `base` input should produce `pdffig1-36aeeb468c2fc161037b25d138d539f2` ([src/pdf-figures.ts:629](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/src/pdf-figures.ts:629)).

- **A-2 — P2: The cross-page pairing test would pass under a common wrong implementation.** Its sole raster belongs to page 3 and the page-3 marker comes first, so an incorrect global “give the first raster to the first marker” implementation would satisfy the assertion ([tests/pdf-figures.test.ts:398](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/tests/pdf-figures.test.ts:398)). Reverse the marker order, or put the raster only on the second marker’s page. The actual implementation correctly groups both sides by page ([src/pdf-figures.ts:461](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/src/pdf-figures.ts:461)).

- **A-3 — P2: The PNG tests do not cover all strict framing requirements.** The home-grown parser checks signature, chunk order, CRCs, IHDR, and inflated scanlines, but never asserts that `IEND` has a zero-length payload ([tests/pdf-figures.test.ts:227](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/tests/pdf-figures.test.ts:227)). A non-empty `IEND` would pass the committed tests while violating PNG’s required framing. The current writer is correct—it supplies an empty buffer ([src/pdf-figures.ts:317](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/src/pdf-figures.ts:317))—so this is only a regression-test gap.

- **A-4 — P2: The overflow test does not prove the protection its comment claims.** The `2^40 × 2^40` case would still be refused by a bare product comparison, so it would pass if the per-dimension guard were removed ([tests/pdf-figures.test.ts:183](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/tests/pdf-figures.test.ts:183)). More precisely, any product near the 12-million cap is exactly representable; a product large enough to round is already vastly above the cap and cannot round down to 12 million. The implementation remains safe: dimensions are safe positive integers, each is capped before multiplication, and all later products are exact ([src/pdf-figures.ts:218](/home/greg/code/spideryarn2/.claude/worktrees/pdf-figures/src/pdf-figures.ts:218)). The test/comment overstate why the guard is necessary.
