No P0 findings. The plan needs revision before implementation.

- **F1 — P1 — established rule; consequence reasoned.** The primary title-to-Abstract rule will hide authored content. On legacy web imports, block 0’s `h1` was injected by Spideryarn, so it is not evidence of a paper’s genre ([prior plan](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/docs/plans/261007b-the-title-is-drawn-once-and-the-masthead-loses-its-back-arrow.md:107)). More fundamentally, standard formats put substantive summaries before `Abstract`: PNAS’s [“Informal connections outweigh coauthorship ties in academic impact”](https://www.pnas.org/doi/10.1073/pnas.2511050123) has a two-paragraph `Significance` section there; JAMA’s [CONSORT-Outcomes 2022 Extension](https://jamanetwork.com/journals/jama/fullarticle/2799401) has `Key Points` containing Question, Findings and Meaning. Both fit the 15-block/600-word/short-heading guards in the [candidate rule](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/docs/plans/261007d-front-matter-folded-by-default-and-arxiv-html-authors.md:87). They would be hidden and falsely described as “authors, affiliations, contact details.” The first rule is demonstrably less safe than the suspected second rule.

- **F2 — P1 — established.** The proposed safety audit can certify a false positive without seeing it. [“Nodal sets of Laplace eigenfunctions”](https://arxiv.org/html/1605.02595) is title → funding prose → one fused author/address block ending “In memory of our teacher Victor Petrovich Havin” → `Abstract.` The rule hides both intervening blocks, while the planned first-80-character inspection ([plan](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/docs/plans/261007d-front-matter-folded-by-default-and-arxiv-html-authors.md:149)) never reaches the dedication. Full-block inspection is necessary for measurement, but a 49-article corpus still cannot make this generic future-import rule sound.

- **F3 — P1 — established.** `isFoldedAway = true` is wrong for a Structure section that starts in the run and continues into the visible abstract. A section is represented only by its first block ([position.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/position.ts:76)). The reading-position writer, Structure focus and section arrow navigation all discard it solely from that start id ([useReadingPosition.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/reader/useReadingPosition.ts:181), [useColumnContext.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/useColumnContext.ts:85), [keynav.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/keynav.ts:675)). The visible abstract is then attributed to the previous section, Structure highlights the wrong section, and arrows cannot reach it. This shape is explicitly invited by the Structure prompt: one node may span “abstract and paperwork” ([paperwork.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/paperwork.ts:90)). A section-range-aware predicate is required; an id-only `isFoldedAway` cannot answer this.

- **F4 — P1 — established.** Marginalia is a missed fold consumer. Margin items live inside the hidden table cell ([TableView.tsx](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/TableView.tsx:1734)), but `useMarginLayout` still measures every `[data-marg-note]`, including those under `display:none` cells ([MarginaliaColumn.tsx](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/marginalia/MarginaliaColumn.tsx:847)). Each zero-height hidden note still advances collision layout by 8px ([notes.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/marginalia/notes.ts:412)). This is realistic because Relations deliberately emits an item for every paperwork paragraph ([paperwork.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/paperwork.ts:38)). Several hidden front-matter notes will push the first visible abstract note downward. The layout must filter `isFolded` rows and re-run on store changes.

- **F5 — P1 — reasoned from established code.** “Show authors and details” can be a no-op when a real fold also covers the run. Hidden rows are the union of echo and real-fold coverage ([fold.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/fold.ts:183)). After a rename, block 0’s `h1` is no longer an echo and can be folded over the entire article. Opening only the new front-matter state leaves its rows hidden. The control must also unfold every real fold covering the run, as `revealBlock` already does for one destination. The plan also needs a policy for a front-matter heading folded while the run is open; simplest is that these headings are never independently foldable.

- **F6 — P1 — established.** Stage 2’s central premise is stale: new arXiv HTML imports already read the title-block authors. `metaAuthors` calls `latexmlAuthorNames` ([meta-authors.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/meta-authors.ts:48)); the existing reader is all-or-nothing and exact-shaped ([latexml.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/latexml.ts:619)); five real-page fixtures and end-to-end storage are tested ([latexml.test.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/tests/latexml.test.ts:425)). The reported `2608-13566` fixture is included. There is also no name-shape check in `src/authors.ts`; it contains limits and stored-shape decoding. Stage 2 should be reduced to possible affiliation enrichment.

- **F7 — P1 — established.** Yes, `.ltx_authors` is still present when `metaAuthors` runs: extraction prepares the source DOM, then calls `metaAuthors`, then invokes Readability ([extract.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/extract.ts:484)). Sanitization is later. But “only when no `citation_author`” is an unsafe gate. The existing fallback declines whenever any credible author metadata exists, including one `dc.creator` or another author/creator meta declaration ([meta-authors.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/meta-authors.ts:62)). The proposed narrower gate could override a valid declared author or JSON-LD-backed Readability byline. Any extension should preserve the existing arXiv/ar5iv source gate, unique document/author block, exact direct-child grammar and separator checks. Blindly “dropping `sup`” is also unsafe: `Jane Doe<sup>1</sup> John Smith<sup>2</sup>` must be rejected, not joined into one plausible name; the existing reader does this at [latexml.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/latexml.ts:673).

- **F8 — P1 — established source data; consequence reasoned.** The affiliation fields are not clean enough for the stated parser. Real fixtures contain the visible `Affiliation:` label, an email embedded inside an affiliation contact, whole legal disclaimers appended to affiliations, institutions encoded as `ltx_role_address`, and one address split into Department/University/city fragments ([fixtures](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/tests/fixtures/latexml/authors-2605-20355v1.html:3)). These values are displayed verbatim and the first becomes an author-search hint ([AuthorNames.tsx](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/AuthorNames.tsx:67)). The plan needs explicit policies for labels, embedded email, address roles, fragments and disclaimer prose; otherwise names-only is safer. Its “all or nothing” claim also conflicts with current cleanup, which deduplicates equal names, drops overlong values and truncates at 100 authors ([meta-authors.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/meta-authors.ts:82)).

- **F9 — P1 — established facts; consequence reasoned.** The staged release makes the reported existing article worse before it makes it better. The plan records that its stored masthead has no `meta.authors` and a wrong fused one-author byline, while the source row contains the full list ([plan](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/docs/plans/261007d-front-matter-folded-by-default-and-arxiv-html-authors.md:69)). Stage 1 hides that accurate row by default; Stage 2 is new-import-only and the rebuild is deferred. Thus the feedback article still shows the wrong author presentation and now conceals the correct one. Default folding should require a complete trustworthy masthead list, or ship with the re-extraction that supplies it.

- **F10 — P2 — reasoned from established lifecycle.** The third store state lacks transition rules. Existing real folds are preserved across same-key block changes ([fold.ts](/var/tmp/spideryarn-worktrees/fbduh4w3-front-matter-collapse/src/web/fold.ts:196)); the plan does not say whether an opened front run remains open when re-extraction changes its ids, when detection appears/disappears, or when a rename changes the echo with the same block array. Nor does “headings are not foldable while shut” define what happens to folds created while open. These need explicit state and tests rather than being left to `setFoldArticle` identity comparison.

The remaining consumers are mostly coherent if `revealBlock` opens both the front state and overlapping real folds: first-load `?at=` installs the store in a layout effect before URL restoration; search and comment jumps reveal before measuring; reading-time sampling skips hidden rows; the spine deliberately suppresses hidden search/reading/quote marks and remeasures; chat cards dock while their block is hidden. Comments, highlights, search marks and marginal items inside the run are nevertheless invisible until disclosure, so the production audit must count marginalia as well as comments.

The simpler design is to delete the already-built author-name work from Stage 2, conservatively extend the existing exact LaTeXML reader only if affiliations can be cleaned reliably, and abandon the generic title-to-Abstract interval. For a display-only first version, fold only a contiguous run where every block has positive author/contact evidence and the masthead has a complete structured author list. Longer term, the import-time `front-matter` role the plan calls “right” is simpler than maintaining a third fold state across all these consumers.

VERDICT: revise before build
