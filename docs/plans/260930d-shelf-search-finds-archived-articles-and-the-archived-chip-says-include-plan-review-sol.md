## Findings

No P0 findings.

1. **P1 — The plan does not preserve stale-response protection across archive toggles.** The hook’s existing response identity is only the echoed query ([useLibrarySearch.ts:15](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/src/web/useLibrarySearch.ts:15)). Toggling the chip changes the question without changing `q`, so an old active-only response that escapes `AbortController` can pass the query check and overwrite the archive-inclusive result. “Re-asks when it changes” ([plan:46](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/docs/plans/260930d-shelf-search-finds-archived-articles-and-the-archived-chip-says-include.md:46)) is insufficient. Require either an echoed `archived` scope checked alongside `query`, or a request-generation token guarding both success and error paths. Add a test that holds the first response, toggles the chip, lets the second response land, then releases the first.

2. **P1 — The widened search path needs an ownership regression test.** The query correctly retains `ownedByReader()` beside the archive predicate ([pg-shelf.ts:611](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/src/store/pg-shelf.ts:611)), so there is no apparent ownership bug in the proposed design. But the existing isolation test only calls the default search path ([owner-isolation.test.ts:1261](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/tests/owner-isolation.test.ts:1261)); the plan’s new store test covers only a same-owner archived article ([plan:77](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/docs/plans/260930d-shelf-search-finds-archived-articles-and-the-archived-chip-says-include.md:77)). Exercise `includeArchived: true` as another owner. Failure here would expose another reader’s article prose.

3. **P1 — The documentation and reader-facing copy inventory is incomplete.** The plan names only `library.md`, but `shelf-terms.md` explicitly says passage search remains active-only ([shelf-terms.md:150](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/docs/project/shelf-terms.md:150)). Metadata says archived articles are out of library search and still directs readers to “Show archived” ([Metadata.tsx:2621](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/src/web/Metadata.tsx:2621)); the privacy page makes the same now-qualified claim and uses the old control name ([PrivacyPage.tsx:529](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/src/web/PrivacyPage.tsx:529)). Update those, and bump the privacy version date ([PrivacyPage.tsx:58](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/src/web/PrivacyPage.tsx:58)).

4. **P1 — The plan needs the important-doc approval gate.** `library.md` is an entry-point document, and both its index rule and `shelf-terms.md`’s active-only sentence are rule changes. The repository requires exact before/after wording and approval before editing ([edit-important-docs.md:18](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/docs/reusable/edit-important-docs.md:18), [edit-important-docs.md:41](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/docs/reusable/edit-important-docs.md:41)). The plan currently treats the edit as an ordinary implementation step.

5. **P2 — The Unread fix is correct only after the archived listing has loaded.** Building `only` from `scope` fixes the normal case, but `scope` deliberately contains active rows alone while the archive is loading or has failed ([Library.tsx:232](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/src/web/Library.tsx:232)). An archived passage can therefore be temporarily—and after a listing failure, permanently—classified as “already opened” because its slug is absent from the set. Separately, Unread remains a post-cap filter, so thirty opened hits can consume the server result before an unread archived hit is reached; the code already documents that limitation ([Library.tsx:1028](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/src/web/Library.tsx:1028)). The plan should state the intended loading/failure behavior and acknowledge or test the cap limitation.

6. **P2 — “Include archived” is a good label, but the planned tooltip understates its effect.** The visible label resolves the additive-versus-exclusive ambiguity. The tooltip should say “list **and search** archived articles too”; “list them too” ([plan:52](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/docs/plans/260930d-shelf-search-finds-archived-articles-and-the-archived-chip-says-include.md:52)) omits the exact behavior this work repairs. The proposed no-result sentence is good, but adding it verbatim to both simultaneously rendered no-match lines will repeat it; say it once for the combined search state.

7. **P2 — Existing text-pinned tests and fixtures should be named explicitly.** The chip is located by an accessible-name prefix in both [shelf-archived-in-the-list.test.tsx:211](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/tests/shelf-archived-in-the-list.test.tsx:211) and [shelf-topics.test.tsx:250](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/tests/shelf-topics.test.tsx:250). `LibraryHit` also has a typed factory in [library-hits.test.ts:25](/home/greg/code/spideryarn2/.claude/worktrees/fb72-shelf-archived-search/tests/library-hits.test.ts:25). The client test should additionally assert the request URL, archived mark, unchanged-query re-request, and stale-response race—not merely copy and the static hint.

## Conclusion

I agree with the root cause and the product conclusion: the card matcher already followed the archive scope, while the Postgres passage matcher unconditionally excluded archived rows; “Wolfram” therefore had no route to Greg’s article. `includeArchived` defaulting false also correctly leaves chat unchanged.

There is no second adapter, no other runtime caller of the HTTP search route, and no caching change is needed: library search is deliberately excluded from the offline cache. The plan is directionally right, but I would not approve it unchanged until the three behavioral P1s—scope-aware stale-response handling, widened-path ownership coverage, and the complete copy/doc migration—are included.
