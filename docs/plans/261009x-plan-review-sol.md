2. **F2 — P1: Nonempty current-round prose is not a safe completion signal for `offer_to_save`.** The prompt instructs the model to call `offer_to_save` *before* writing its reply, so prose accompanying that call is precisely the protocol-violation case; it might be the full answer, but it may equally be “Let me note that.” before the intended answer. `roundText.trim() !== ""` cannot distinguish them. The existing suite demonstrates the broader problem by treating the visibly incomplete `"Start with the abstract, because"` as terminal when the round is truncated. The proposed rule would extend that behavior to save offers and failures. Require `outcome.kind === "wants-tools"` for any terminal shortcut, retain the successful-next-steps completion marker, and add a deterministic preamble case that must continue to the real answer. Do not make `offer_to_save` alone terminal merely because it shares a round with prose. A too-long save refusal tells the model to offer shorter words; a thrown tool tells it to answer without the tool and report that it could not run; a refused next-steps call tells it that no button exists. The proposal deliberately discards all of those results, even though failed/refused outcomes have no self-explanatory card.
