1. **P1 — Semantic Scholar’s commercial-use approval is not enforced at the request boundary.** `registryKeyHeaders()` sends the S2 key whenever it exists, without checking approval (`src/registry-keys.ts:64-72`), while the generic fetcher permits S2 requests with or without that key (`src/fetch.ts:2722-2746`). The callable eval `registry` phase bypasses `optionalSources()` entirely and unconditionally issues S2 batch/title requests (`evals/citation-blurbs-spike.ts:358-375`, `:452-464`, `:973-977`). Tests codify the gap: they expect a key without approval to be attached and allow an anonymous request (`tests/registry-keys.test.ts:77-107`); another test sets only the key, manually enables S2, and makes a request (`tests/citation-evidence.test.ts:971-999`). Thus `SEMANTIC_SCHOLAR_COMMERCIAL_USE=approved` is not required for every S2 request, contrary to R5.  
   **Fix:** put the key-plus-exact-approval check in the sole S2 request boundary, refusing the request before DNS unless both are present. Route or remove the eval’s legacy S2 calls. Reverse the tests so missing approval proves the fetch implementation was never called.

2. **P1 — The OpenAlex key still enters a URL in a callable eval path.** `openAlexByDoi()` reads `OPENALEX_API_KEY` directly, adds it as `api_key`, and passes the resulting URL to `fetch` (`evals/citation-blurbs-spike.ts:313-318`, via `getJson` at `:138-159`). That phase remains exposed by the script’s command switch (`evals/citation-blurbs-spike.ts:973-977`). This also contradicts the claimed single reader and “headers only” invariant (`src/registry-keys.ts:1-15`) and makes the privacy/security statements false (`docs/project/privacy.md:755`, `docs/project/security.md:1137-1142`).  
   **Fix:** remove the direct environment read and query parameter; use the guarded bibliographic fetch path with `registryKey: "openalex"` or delete the obsolete registry path in favour of the production phase.

3. **P2 — A transport error can copy a key into `FetchFailure` and logs; the redaction test does not simulate that.** The secret-bearing headers are handed to `fetchImpl`, and any thrown error is preserved as the raw cause (`src/fetch.ts:2383-2394`, `:2063-2110`). The fallback additionally interpolates the transport’s message into the top-level `FetchFailure` (`src/fetch.ts:2107-2110`), while logging follows cause messages (`src/log.ts:98-114`). The alleged “headers and all” test only inserts `typeof init` into the error, never the actual header value, and it does not exercise the logger or Sentry sanitizer (`tests/registry-keys.test.ts:138-159`). Sentry’s current sanitizer drops causes, but the claimed end-to-end test is absent.  
   **Fix:** for keyed requests, rebuild network failures from safe fields without retaining or interpolating arbitrary transport messages. Test with a fake transport that reads the actual key from `init.headers` and throws it in both its message and cause; assert against `FetchFailure`, serialized logger output, and the sanitized Sentry event.

4. **P2 — Keyless behaviour is not exactly unchanged at the budget boundary.** Previously, a DOI worker that began within budget immediately continued to its OpenAlex fallback (`d55fe3d99^:src/citation-evidence.ts:436-452`). Now it returns a pending item (`src/citation-evidence.ts:724-739`), waits for all phase-one work to finish (`:975-990`), and phase three refuses to start it if the clock has since crossed `stopAt` (`:913-918`). Therefore the same keyless run can change from an OpenAlex request and evidence/negative result to no request and `transient:over-budget`. The keyless regression test uses a fixed clock and only proves the two new optional searches are absent (`tests/citation-evidence.test.ts:646-657`).  
   **Fix:** retain the old immediate OpenAlex continuation when the source policy is the base/keyless policy, while using the phased path for keyed policies. Add a fake-clock regression where the registry lookup begins before `stopAt` and completes after it.

5. **P2 — The new S2 429 breaker has no test.** The implementation cools S2 down, turns it off for the run, and returns `semantic-scholar-off` (`src/citation-evidence.ts:695-700`), but the breaker test covers only 401 and 403 (`tests/citation-evidence.test.ts:745-762`); the following test covers 500 fall-through (`:764-775`). This is one of the builder’s explicit departures and could regress while the suite stays green.  
   **Fix:** add a two-row 429 case asserting one S2 request, one shared cooldown, both rows transient, one warning with `off-for-run`, and no configuration error.

6. **P3 — The reader-facing privacy text says three indexes while naming four.** The page says “Three public indexes” and then names Crossref, DataCite, OpenAlex, and Semantic Scholar (`src/web/PrivacyPage.tsx:393-439`). The owning document repeats “all three” before calling Semantic Scholar a fourth (`docs/project/privacy.md:757-764`), and the security overview’s introductory sentence still omits Semantic Scholar despite its abstract appearing on the page (`docs/project/security.md:1131-1145`). The test only checks that every host’s name appears; its own title and lower bound remain “three”/`>= 3`, so it passes (`tests/privacy-page.test.ts:272-290`).  
   **Fix:** say “Four public indexes,” update both documents and the test name, and assert the exact current count or the exact introductory wording.
