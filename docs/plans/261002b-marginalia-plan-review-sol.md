2. **P1 — The stale-artifact claim is false for visitors, and citations need a separate owner freshness gate.**  
   The plan says stale owner artefacts are not drawn ([plan:59](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/docs/plans/261002b-marginalia-shows-faq-citations-debate-and-comments-shut-by-default.md:59)). Public FAQ and Debate carry no freshness result by design; the public reader explicitly says it does not compute one ([public-reader.ts:301](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/store/public-reader.ts:301)). A stale public row whose block ID still exists can therefore be placed confidently beside changed prose. Missing-block filtering catches only fully orphaned IDs. Separately, Reader’s existing owner citation list ignores `status` and `stale` ([Reader.tsx:983](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/web/reader/Reader.tsx:983)); reusing `works` would violate the plan.  
   **Fix:** either omit stale FAQ/Debate from the public payload for this surface, or carry a public drawable/fresh decision as cross-references already do. At minimum, verify FAQ `quote` and Debate `claimQuote` against the current block before placing them. Derive marginal citations separately as `owner && status === "ready" && !stale`; never fall back to `artefacts.citations`. Add owner-stale, visitor-stale, and visitor-with-public-citations tests.

3. **P1 — Per-block grouping does not solve citation density.**  
   The plan claims grouping makes a forty-reference paper cease producing forty margin lines ([plan:52](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/docs/plans/261002b-marginalia-shows-faq-citations-debate-and-comments-shut-by-default.md:52)). It only groups works sharing one block. Each work has its own `firstCited` ([types.ts:3949](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/types.ts:3949)), and a list can contain 80 works ([types.ts:4349](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/types.ts:4349)). A normal paper citing one work per paragraph still adds forty lines—the “second article” the plan says it prevents. Citations are already marked precisely in owner prose ([citations.md:184](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/docs/project/bibliography.md:184)).  
   **Fix:** simplest is to omit citation marginalia in v1. Otherwise specify an article-wide density policy, such as showing margin citation rows only for multi-citation blocks or unmarked footnote-only citations, with a hard cap and a test using forty distinct `firstCited` blocks.

4. **P2 — FAQ anchoring must choose the earliest surviving current block, not `passages[0]`.**  
   The plan describes the anchor as both `passages[0]` and “by block position” ([plan:47](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/docs/plans/261002b-marginalia-shows-faq-citations-debate-and-comments-shut-by-default.md:47)). If the first passage disappears while a later one survives, skipping the whole question wastes a still-valid anchor.  
   **Fix:** resolve every surviving passage through `blockIndex`, choose the lowest current index, and skip only when none survive. Mirror the existing Ideas scan ([notes.ts:103](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/web/marginalia/notes.ts:103)). Test random ID order, reordered passages, and a missing original first passage.

6. **P2 — Owner comments include referee notes unless explicitly filtered.**  
   `Comment` includes `criterionId`, identifying a peer-review placement rather than an ordinary reading note ([types.ts:2828](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/types.ts:2828)). The public query correctly excludes those rows and unfinished calls ([public-reader.ts:503](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/store/public-reader.ts:503)), so visitors are safe if Reader passes its existing unified `comments` value. The owner list is unrestricted, though; passing it wholesale would show referee notes as context-free “YOUR NOTE” marginalia and increase density.  
   **Fix:** filter owner marginalia to `criterionId === undefined`. If referee placements are intended, make them a separate labelled kind retaining criterion context. Add a visitor test proving ordinary published comments appear while referee, pending, and failed comments do not.

7. **P3 — The count → shut rows → individual open rows design is unnecessarily two-level.**  
   The plan makes a count disclosure open another set of disclosures ([plan:52](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/docs/plans/261002b-marginalia-shows-faq-citations-debate-and-comments-shut-by-default.md:52)). That adds nested state, extra tab stops, and more collision-layout transitions.  
   **Fix:** use one disclosure per kind per block. Its shut label is the item title for one item or “N citations/comments” for several; opening it renders the details for that kind directly.

The current collision mechanism itself is suitable: `useMarginLayout` observes every outer note with `ResizeObserver` ([MarginaliaColumn.tsx:325](/home/greg/code/spideryarn2/.claude/worktrees/fb82-marginalia-other-modes/src/web/marginalia/MarginaliaColumn.tsx:325)), so an in-flow disclosure changing the note’s height schedules another pass. Keep opened content inside that observed box and add one interaction test proving the next note’s translate changes after opening.
