1. **P1 — The generic “link-only child” deletion can remove real figure content.**  
   Evidence: a wrapper containing an image, a long ordinary description, and `<span><a>Photo: Jane Example</a></span>` survives unchanged in the control. The spike deletes the credit while preserving the image, and `proseRetention` reports `lost: 0` because the credit is under 25 characters. Real examples include photographer credits, source attributions, museum records, licences, and dataset/download links.  
   Proposed change: remove the generic deletion. Handle Nature’s known control through the existing furniture mechanism, using its publisher-defined `.c-article-section__figure-link` selector plus the usual structural guards. That selector alone also prevents Nature’s enclosing item from becoming link-dense. Do not infer “control” merely from link-only text.

2. **P1 — `linkText > 0` and the repeated outward walk are substantially broader than the diagnosed failure.**  
   Evidence: Raschka has 15 linked captions, but only nine cross Readability’s `0.2` low-weight threshold and lose their images. The other six have link densities from `0.062` to `0.181` and already survive, yet the spike unwraps them. Quanta fires because of a privacy-policy link and the outward loop then strips several single-child layout wrappers, including `hide-on-print`; every outer ancestor inherits the figure’s link text, whether that ancestor was at risk or not.  
   Proposed change: gate each candidate `div` on the relevant Readability condition—its own class weight and link density crossing either `weight < 25 && density > 0.2` or `weight >= 25 && density > 0.5`. Re-evaluate each ancestor independently while walking outward. Pin the copied weight regexes and density calculation, including Readability’s reduced weight for fragment links. Add linked-but-safe Raschka figures and Quanta’s outer wrappers as negative controls.

3. **P1 — The production re-run sequence cannot work as written and can temporarily publish mismatched artefacts.**  
   Evidence: `scripts/stage.ts` submits one-step jobs. An `extract`-only job can publish new extracted HTML beside the carried-forward old blocks and tree. The following `blocks`-only command is rejected by `unrunnableStepPlan`, because any job containing `blocks` must also contain `hierarchy`. Consequently, the proposed `extract`, then `blocks`, then `assets` sequence cannot rebuild the article.  
   Proposed change: submit one job with `steps: ["extract", "blocks", "hierarchy", "assets"]` and `force: ["extract"]`, or add an equivalent supported multi-step CLI. This forces all four named steps in order and publishes them together. Re-running blocks is safe for stable IDs: the draft carries the published blocks, unchanged text and image sources reuse their IDs, new figures mint new IDs, and `assertIdsCarried` refuses total identity loss. A new hierarchy invalidates paragraph labels and publication queues the labels successor. Other modes are not automatically rerun; their fingerprints make them stale until regenerated or requested.

4. **P1 — Unwrapping can reproduce the global candidate-selection failure, so the fallback needs a real end-to-end adversarial test.**  
   Evidence: with four sibling authored `<article>` sections and a separate figure whose long linked caption is inside the media `div`, the control keeps all four author paragraphs and no image. After unwrapping, the figure wins candidate selection, the image survives, and all four author sections disappear. `proseRetention` reports four runs lost, so the existing fallback correctly chooses the control. The current helper-level assertions only prove option/label bookkeeping, not that `readArticle` actually makes this decision.  
   Proposed change: add this topology as the rollback test. Assert the four paragraphs survive, the desired image is sacrificed, and `kept` contains the Rule C rollback key. Also retain a gallery/figure-only case to show the rule does not invent a prose regression there.

5. **P2 — Candidate selection remains a separate way to lose the image after unwrapping.**  
   Evidence: a long prose `<article>` and a sibling wrapped figure produce zero output images both before and after the spike; Rule C fires, but Readability selects the prose article and never appends the unscored figure sibling. `_cleanHeaders` is irrelevant, and the extra-paragraph pass preserves paragraphs containing descendant images. For the measured pages, DIV→P does not remove the rescued image. Candidate selection is the remaining branch that invalidates the plan’s absolute “nothing else can remove it” wording.  
   Proposed change: state the narrower guarantee: Rule C prevents these `_cleanConditionally` deletions when the figure has already entered the selected article; it does not generally guarantee figure selection.

   Proposed change: correct the counts and wording, then repeat the corpus comparison through `readArticle`/the actual Rule C control arm after implementation.
