3. **P1 — `pathsInUse` does not establish that all live users of a file were observed. Reporting; not fixed.** [box-tidy.mjs:111](/var/tmp/spideryarn-worktrees/box-disk-hygiene-rebuild/infra/hetzner/box-tidy.mjs:111). A process can mmap a rollout, close its original descriptor, and remain alive with that mapping; neither cwd nor fd lists it. Linux exposes these separately through [map_files](https://man7.org/linux/man-pages/man5/proc_pid_map_files.5.html). Bind mounts and another mount namespace can expose the same inode under a different path, while the cleaner compares literal strings. For example, a container opening a host job log through its `/logs` mount need not produce the host pathname used by `inUse.has(file)`. Descriptor links also carry `(deleted)` suffixes; stripping those blindly can associate an old unlinked inode with a newly created pathname. Inode identity and namespace-aware observation are needed, rather than textual normalization. A hidden/incomplete PID listing or an empty substitute `/proc` returns success without proving completeness. The real unit now clears the substitute-proc override (finding 10), but the scanner itself does not verify its procfs view. Reading maps and namespace identities would improve the snapshot; it still would not solve finding 4. This is a blocker for the unconditional claim that live work cannot be removed.
