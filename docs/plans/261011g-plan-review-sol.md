The compatibility view itself is sound, provided it exposes every column as a plain reference, including `attempt_id` and `finished_at`. PostgreSQL supports `INSERT`, `UPDATE`, `DELETE`, `RETURNING`, and `INSERT … ON CONFLICT DO UPDATE` through such a view. The old store does not catch production constraints by name, and old/new writes reach the same physical row. [PostgreSQL’s updatable-view documentation](https://www.postgresql.org/docs/current/sql-createview.html) confirms this.
