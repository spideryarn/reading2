1. **P1 — The widened door would expose Referee to ordinary Chat, not only Guide.** The plan widens the single `chipModes` door ([plan:64](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/plans/261009u-the-guide-offers-referee-to-a-reader-who-says-they-are-refereeing.md:64)), but `chatExecutor` copies that door’s runners and sources wholesale ([command-runners.ts:412](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/web/command-runners.ts:412)), and the same executor wraps ordinary Chat ([Reader.tsx:3368](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/web/reader/Reader.tsx:3368)). Old or injected Referee tokens in Chat would therefore become buttons with the switch off. **Fix:** retain the existing door for Chat and the command bar; build a second, widened Guide-only door/executor selected by thread kind.

2. **P1 — The confidentiality requirement is not actually measured, and the proposed sentence is too weak.** The plan calls a pointer to Notices “honest about confidentiality” ([plan:70](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/plans/261009u-the-guide-offers-referee-to-a-reader-who-says-they-are-refereeing.md:70)), while the mode contract says the crucial fact is past tense: the manuscript has already gone to a provider ([referee-mode.md:1182](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/project/referee-mode.md:1182)). The eval’s `ok` ignores `notices` entirely ([referee-offer.ts:163](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/evals/guide/referee-offer.ts:163)); `/notices/i` would not establish the past-tense disclosure anyway. **Fix:** require the offer to say, briefly, that the text was already sent and that Notices explains relevant venue rules; make its absence fail positive cases, with at least two runs by default.

3. **P2 — The hostile-article case can auto-navigate, despite being described only as an offer.** Referee is non-generating, so its token passes `actsAlone` ([guide-acts.ts:108](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/web/guide-acts.ts:108)) and `CommandChip` presses it automatically ([CommandChip.tsx:106](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/web/CommandChip.tsx:106)); mounting Referee also starts the deterministic source scan ([RefereeMode.tsx:162](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/web/modes/referee/RefereeMode.tsx:162)). The prompt and eval reduce injection likelihood but do not enforce provenance. **Fix:** print behind-switch exceptions as `Button:` regardless of `modeActsAlone`, so the reader confirms the model’s persona inference. This is not an authorization/security-gate change—the switch changes discoverability, not authority—but it preserves the press boundary against a mistaken inference.

4. **P2 — The spoken Guide is left giving false instructions.** The plan leaves it unchanged because voice has no buttons ([plan:63](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/plans/261009u-the-guide-offers-referee-to-a-reader-who-says-they-are-refereeing.md:63)), yet spoken mode copy says the reader can find every named mode in the bottom bar ([guide.ts:141](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/guide.ts:141)), and `SPOKEN_GUIDE` repeats that instruction ([live.ts:383](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/live.ts:383)). Referee is absent there with the switch off. **Fix:** either give spoken Guide a truthful route to the offered mode, or explicitly scope this feature to typed Guide and prevent voice from recommending the hidden mode.

5. **P2 — `chipDoorRows` is the right test seam only as a row transformer.** If it imports `visibleModes` and `subModeRows` from its proposed home in `command-runners.ts`, it creates the cycles the code explicitly forbids: Dock imports CommandBar one-way ([Dock.tsx:206](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/web/Dock.tsx:206)), while CommandBar already imports `command-runners.ts` ([CommandBar.tsx:170](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/web/CommandBar.tsx:170)). **Fix:** have Reader build today’s ordinary rows as now, then pass them through a pure `guideDoorRows(baseRows)` that appends and deduplicates the explicit exceptions. Do not move Dock/CommandBar reachability policy into `command-runners.ts`.

6. **P2 — The tests stop before the failure-prone part of the path.** The plan tests that a token exists in `chipDoorRows` ([plan:101](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/plans/261009u-the-guide-offers-referee-to-a-reader-who-says-they-are-refereeing.md:101)), not `chipFor → modeRunner → openModeUnarmed → Dock activator`. That path does work in the current design, and neither the activators nor `RefereeBand` assumes the switch is on, but the test would not catch a disconnected runner. **Fix:** add an integration test asserting the off-switch Guide token renders, activates the unarmed callback, opens Referee, and never calls the armed callback; also assert ordinary Chat and visitors reject it. Phone needs no separate branch—the same activator is used—but one narrow-layout regression test is worthwhile.

However “every publisher policy” forbids writing the assessment ([research:57](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/research/261009b-what-a-peer-reviewer-needs-and-where-sources-and-referee-divide.md:57)) is stronger than the web pass, which says policies diverge ([web pass:38](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/research/261009b-peer-reviewer-web-pass-sonnet.md:38)). Also change “built today/as built today” to planned tense.

8. **P3 — Keep the separate allowlist, but correct its rationale and shape.** The comment requiring `experimental` does not forbid unrelated optional fields ([mode-catalog.ts:242](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/src/mode-catalog.ts:242)), so the plan’s stated reason is false ([plan:53](/var/tmp/spideryarn-worktrees/fbh5aypq-peer-review-research/docs/plans/261009u-the-guide-offers-referee-to-a-reader-who-says-they-are-refereeing.md:53)).
