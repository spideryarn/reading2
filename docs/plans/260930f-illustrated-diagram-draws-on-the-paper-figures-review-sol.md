## P1

1. **The no-figure path is not unchanged.** The plan promises that articles without figures remain unchanged and that their outgoing request is byte-identical, but it also changes the unconditional `SYSTEM` prompt, adds `figures` to its JSON schema, and globally bumps the version to `/5` ([plan:33](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:33), [plan:82](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:82), [plan:106](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:106)). `SYSTEM` is sent on every run, including the new figure instructions and schema ([illustrated.ts:558](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated.ts:558), [illustrated.ts:625](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated.ts:625), [illustrated.ts:1034](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated.ts:1034)); `/5` also marks every old no-figure illustration stale ([illustrated-plate.ts:149](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated-plate.ts:149)). Either the figure instructions/schema and expected version must be conditional, or the “exactly as today” requirement must be withdrawn.

2. **Omitting figures from the fingerprint creates the feature’s main silent-success path.** The plan explicitly treats missing `assets` as “no figures” while hashing only the Sketch ([plan:111](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:111), [plan:132](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:132)). Therefore a legacy article can be illustrated before its assets step runs, later acquire all its figures, and still report the old figureless result as current. This does not require a re-ingest or version bump, contrary to line 136: the assets step can be run independently. The fingerprint, pipeline stamp, metadata check, and reader load all currently compare only the Sketch ([illustrated.ts:239](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated.ts:239), [pipeline.ts:3909](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/pipeline.ts:3909), [pg.ts:2030](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/store/pg.ts:2030), [pg.ts:3777](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/store/pg.ts:3777)). Hash the eligible figure identities—at least block, hash, and type—and read `assets` at all freshness sites.

3. **Web figures will usually be given the wrong “caption,” often no caption at all.** The plan defines the caption as the image-holding block’s own text ([plan:43](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:43)). In real extracted data, the image is a `media` block with `text: ""`, followed by a distinct `caption` block ([fixture:316](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/tests/fixtures/data-root/data/noema-mythology-of-conscious-ai/blocks.json:316), [fixture:325](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/tests/fixtures/data-root/data/noema-mythology-of-conscious-ai/blocks.json:325)). The proposed implementation consequently emits “no caption” ([illustrated-figures.ts:162](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated-figures.ts:162)). Moreover, `imagesIn` returns every `<img>`, not semantic figures ([collect-assets.ts:318](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/collect-assets.ts:318)); a 300-pixel long-side threshold still admits banners, portraits, and hero art, which can consume the first-eight cap before later scientific figures. Pair media blocks with their extracted caption blocks or `alt`, and restrict web candidates to captioned figure-shaped content. A PDF-only first version would avoid this entire ambiguity.

4. **The blob-store choice can make every figure disappear while the run succeeds.** The plan says only “an injected getter” and silently skips every read failure ([plan:47](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:47), [plan:57](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:57)); the current wiring uses `blobStore()` ([pipeline.ts:3972](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/pipeline.ts:3972)). That function falls back to local files when Supabase credentials are absent, while the manifest came from Postgres—exactly the split-brain case `postgresBlobStore` exists to refuse ([blobs.ts:258](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/store/blobs.ts:258), [blobs.ts:265](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/store/blobs.ts:265), [blobs.ts:303](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/store/blobs.ts:303)). Use `postgresBlobStore(...)` and do not turn configuration/project mismatch into “this article has no figures.”

5. **“Faithful chart, but without any lettering or numbers” is internally contradictory and unenforceable.** Axes, units, tick values, legend labels, panel letters, and annotations commonly carry the relation a chart shows. Removing them produces decorative marks, not a faithful rendering ([plan:93](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:93), [plan:99](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:99)). The “existing rule already forbids them” claim is also false: it is merely prompt text ([illustrated.ts:843](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated.ts:843)); returned pixels are checked only for format and dimensions ([ai-call.ts:1929](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/ai-call.ts:1929)), and the project doc explicitly says Illustrated output is unconstrained ([diagram.md:1904](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/project/diagram.md:1904)). For v1, either preserve charts as unchanged framed insets, or exclude lettering-dependent charts and redraw only photographs/illustrations/unlettered diagrams.

6. **The 4 MiB limit is per figure, not a request budget.** Three accepted figures can contribute 12 MiB raw and about 16 MiB after base64. A zoom also carries the earlier plate; the gateway permits that plate to be as large as 32 MiB ([ai-call.ts:1910](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/ai-call.ts:1910)), making the declared worst-case body roughly 59 MiB before JSON overhead. `outgoingImage` simply serializes every data URL with no aggregate bound ([ai-call.ts:1864](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/ai-call.ts:1864)). Thus the plan’s “a few 1.6 MB PNGs are fine” and “one more image” reasoning does not cover its own maximum ([plan:18](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:18), [plan:52](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:52)). OpenRouter documents that references may be base64 data URLs but supplies no aggregate budget guarantee in the public contract ([OpenRouter image-generation docs](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)). Add a cumulative encoded-byte limit and a worst-case live test; overview-only references or downscaled copies would substantially reduce the risk.

## P2

7. **The attachment-numbering contract is assumed rather than demonstrated.** The wire contains only an ordered array of anonymous `image_url` objects ([ai-call.ts:1879](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/ai-call.ts:1879)); nothing names one `FIGURE A` or “style plate.” The plan assumes the provider/model interprets textual “Image 1 / next image” numbering exactly ([plan:86](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:86)). Also, today’s style reference is the first plate that succeeded, not necessarily the overview ([illustrated.ts:1229](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated.ts:1229)). Test two unmistakable synthetic references in both overview and zoom positions. Looking at one ordinary paper chart is not proof: the model may infer a similar chart from the caption while ignoring or swapping the bytes.

8. **The stored figure record does not identify what was actually sent.** Candidates have a content hash and type, but the artefact retains only an ephemeral `FIGURE A` label and block id ([plan:43](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:43), [plan:79](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:79), [illustrated-plate.ts:320](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated-plate.ts:320)). Labels are reassigned after filtering, so they cannot establish provenance after assets or blob availability changes. Populate `{label, block, sha256, ext}` from the trusted offered map; the model should still supply only the label.

9. **The plan’s per-block PDF walk changes the duplicate-ref safety rule.** `pdfFigureMarkersIn(blocks)` deliberately refuses a ref repeated across two blocks by counting across the whole article ([collect-assets.ts:356](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/collect-assets.ts:356)). Calling it “over that block” independently, as the plan says, accepts both occurrences ([plan:37](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:37)). The current draft has added the necessary whole-article allow-list before per-block attribution ([illustrated-figures.ts:127](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated-figures.ts:127)); that two-pass requirement and a cross-block duplicate test belong in the plan.

10. **The validator currently repairs the exact drift the plan says it will fault.** The plan says only offered labels are accepted exactly and everything else increments `faults` ([plan:76](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/docs/plans/260930f-illustrated-diagram-draws-on-the-paper-figures.md:76)). The current reader uppercases model output before lookup, so `"figure a"` is silently accepted with no fault ([illustrated-plate.ts:1099](/home/greg/code/spideryarn2/.claude/worktrees/fb5x-diagram-paper-figures/src/illustrated-plate.ts:1099)). That contradicts this file’s “drop, never repair” observability contract. Remove the normalization or record a fault when applying it.

A substantially simpler v1 would use stored PDF figures only, attach at most one chosen figure to the overview plate, and leave zoom plates and web `<img>` discovery unchanged. It would satisfy the feedback on the named paper while avoiding web-caption inference, decorative-image filtering, repeated multi-megabyte uploads, and most attachment-order ambiguity.
