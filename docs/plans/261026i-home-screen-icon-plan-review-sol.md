1. The “no preference → dark” claim is incorrect. `prefers-color-scheme` has only `light` and `dark`; `light` also represents no expressed preference. Therefore matching light is still the right future-facing condition for selecting light only, but it guarantees dark only when `matchMedia` is missing, throws, or returns an unknown/non-light value—not for standards-defined “no preference.” Revise [the plan’s wording and test case](</var/tmp/spideryarn-worktrees/fbshpsvx-icon-dark-by-default/docs/plans/261026i-home-screen-icon-follows-the-phone-mode-dark-by-default.md:45>). [CSS Media Queries specification](https://www.w3.org/TR/mediaqueries-5/#prefers-color-scheme)

2. One synchronously mutated link is the best available approach; do not add media-qualified links alongside it. The collector does read direct `<head>` children’s current URLs, does not itself evaluate `media`, and uses a non-stable size sort. However, this proves collection behavior, not when Safari’s Add to Home Screen invokes it. WebKit both snapshots icons after parsing and exposes an SPI that re-collects the live DOM; Safari’s final consumer remains closed. Thus the initial inline swap is well-founded, while the change listener’s effect at share-sheet time remains a device-test hypothesis. [Collector](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebCore/html/LinkIconCollector.cpp), [live `appleTouchIconURLs` SPI](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebKit/WebProcess/InjectedBundle/API/Cocoa/WKWebProcessPlugInFrame.mm), [Safari/WebKit division of responsibility](https://bugs.webkit.org/show_bug.cgi?id=315573)

3. `?v=2` is reasonable and low-risk, but “[Safari’s] icon store [is] keyed by URL” is stronger than the available evidence. Treat it as a defensive cache-buster. It does not interfere with root `/apple-touch-icon.png` probing because that fallback occurs only when no link is supplied, and the plain root asset remains dark. It does require the brand test to parse/strip the query before opening the file rather than retaining its old `.png$` assumption. [Apple’s fallback rules](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html)

The new light asset is not a search-result resource under [that list’s contract](</var/tmp/spideryarn-worktrees/fbshpsvx-icon-dark-by-default/src/site-pages.ts:219>).
