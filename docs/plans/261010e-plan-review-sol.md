Stage 1 is mostly sound. Stage 2 should be cut and redesigned separately; it currently promises behavior and data the existing machinery does not provide.

F1 — high — Stage 2’s button labels do not match their actions. `onOpenComment` opens the comment dialog by writing `?note=`; Comments is a Dock drawer, not a mode ([Reader.tsx:3272](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/reader/Reader.tsx:3272), [Dock.tsx:2232](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/Dock.tsx:2232)). `onOpenChat` writes `?thread=` and leaves the current mode in place, producing the floating conversation panel; it does not call `showBand("chat")` ([Reader.tsx:2409](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/reader/Reader.tsx:2409)). Therefore “Open in Comments” and “Open in Chat” are false. Recommended change: cut Stage 2. If revisited, either label the existing actions “Open comment” / “Open conversation”, or separately design genuine drawer/mode navigation and its Back behavior.

F2 — high — Glossary rows still will not land in view for visitors. `termFocus` is passed only to the owner’s `GlossaryBand`; `VisitorGlossaryBand` receives no focus or acknowledgement props ([Reader.tsx:3425](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/reader/Reader.tsx:3425), [Reader.tsx:3438](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/reader/Reader.tsx:3438)). The visitor wrapper consequently never supplies `GlossaryPanel`’s `useLandOnItem` mechanism ([GlossaryMode.tsx:152](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/modes/glossary/GlossaryMode.tsx:152), [GlossaryPanel.tsx:311](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/GlossaryPanel.tsx:311)). Recommended change: add `focus` and `onFocusTaken` to `VisitorGlossaryBand`, wire them from Reader, and test a visitor opening a term below the fold.

F3 — medium — The survey’s `mark.cmt` row is materially incomplete. Whole-block bookmarks draw no prose mark at all ([types.ts:3332](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/types.ts:3332)); marked selections can be highlights, comments, comments with AI, bookmarks, or Referee placements ([comment-nav.ts:219](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/comment-nav.ts:219)). Coloured, non-Referee highlights are also rows in Quotes ([quote-band-rows.ts:41](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/quote-band-rows.ts:41)), so “Open in Comments” is not the single obvious mode destination. Recommended change: split the survey into comment, highlight, Referee placement, and whole-block bookmark; record which have prose marks and which surfaces own them.

F4 — medium — Stage 2 cannot offer “pointer and keyboard” through the proposed delegated wiring. Bare `mark.cmt` and `mark.chat` elements are not focusable; only cross-references receive `tabindex` and a link role ([annotate.ts:759](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/annotate.ts:759)). `useHoverCard`’s keyboard path only reacts after focus reaches an existing focusable target ([useHoverCard.ts:969](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/useHoverCard.ts:969)). The current design explicitly rejects making ordinary marks hundreds of tab stops ([ProseHoverCard.tsx:537](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/ProseHoverCard.tsx:537)); Glossary documents the same unresolved keyboard cost ([glossary.md:1609](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/docs/project/glossary.md:1609)). Recommended change: remove the keyboard claim from Stage 2 or design a separate roving/shortcut route before implementation.

F5 — medium — The proposed chat card cannot show “its first question” from data currently in reach. `AnchoredThread` carries `title`, turn count, and the latest answer’s first line, but no first question ([useChatAnchors.ts:119](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/useChatAnchors.ts:119)). `ThreadSummary` deliberately omits the transcript and likewise carries no question text ([types.ts:4492](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/types.ts:4492), [routes.ts:4957](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/routes.ts:4957)). Recommended change: if Stage 2 survives, specify `title` instead, or make expanding `ThreadSummary` an explicit API/privacy change. This meets the plan’s own criterion for cutting the stage.

F6 — medium — Stage 2 has unresolved precedence and multiplicity cases. One generated `<mark>` can carry every applicable class and space-separated lists of several comment/chat IDs ([annotate.ts:491](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/annotate.ts:491), [annotate.ts:512](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/annotate.ts:512)). The existing click path has a deliberate linked-comment/chat precedence rule ([TableView.tsx:1516](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/TableView.tsx:1516)). Cross-references must also win hover, which is why all current selectors exclude `.xref` ([ProseHoverCard.tsx:505](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/ProseHoverCard.tsx:505)). Recommended change: before building cards, define whether they show every ID or the same winner as the click, exclude `.xref`, and test multiple comments, linked/unrelated comment+chat, term+comment, citation+chat, and link overlaps.

F7 — medium — The plan wrongly says `openBibliographyWork` made “no selected row / no `?cite=`” stale. It did not: citation focus is explicitly a one-shot scroll request, not selection or URL state ([item-focus.ts:13](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/item-focus.ts:13), [CitationsPanel.tsx:873](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/CitationsPanel.tsx:873)). `openBibliographyWork` does correctly restore the band, switch to Bibliography, lower the bar, and focus the row ([Reader.tsx:1671](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/reader/Reader.tsx:1671)). Recommended change: preserve the no-selection/no-`?cite=` documentation and revise the shared promise to “opens the mode and brings the row into view; selects it where that mode has selection.”

F8 — medium — The proposed documentation invariant, “Every mark on the prose has a card,” would remain false. Search, Ideas, Timeline, Referee, and Skim hits are visible mode-produced marks with no card; already being in their mode solves navigation, not Greg’s separate tooltip request. The existing tooltip policy explicitly says coloured marks whose meaning must be inferred deserve cards ([tooltips.md:35](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/docs/project/tooltips.md:35)). Recommended change: document the narrower truth—“Every existing annotation card has a way into its owning mode”—and keep hit cards as an explicit queued gap.

F9 — low — Showing the button in its own mode is reasonable. Citation and Glossary focus requests have nonces, and Quotes follows selection into view, so a same-mode press can re-land the row. When the row is already selected and visible, it merely closes the card; that is harmless idempotence. On a phone with the band stepped aside, `showBand` correctly restores it. One caveat: restoring an away band in the same mode changes component state only, so browser Back will not put it away again; that is deliberate ([Reader.tsx:506](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/reader/Reader.tsx:506), [Reader.tsx:513](/var/tmp/spideryarn-worktrees/fbzux9w6-tooltips-open-their-mode/src/web/reader/Reader.tsx:513)). Recommended change: keep the always-present button, state this Back rule, and add narrow-window/away and one-Back integration tests. “Show in `<Mode>`” would be marginally more literal than “Open in” but is not necessary.

The simpler coherent plan is Stage 1 only: add the citation callback/button, make Glossary focus work for both owner and visitor, switch Quotes to `showBand`, standardise the three labels, and defer comments/chat as a separately designed feature.
