These are two small tidy-ups, and the overall design is reasonable. The blocking issue is that the offline cache defeats the header’s protection for old tabs. No files changed.

1. **F1 — P1: cached `null` reaches clients that never opted in.**  
   The cache key contains only user and URL ([offline-store.ts:385](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/lib/offline-store.ts:385)). On transport failure, `apiFetch` replays that body as `200`, regardless of request headers ([api.ts:805](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/lib/api.ts:805)). Therefore: a new tab saves `null`; an old tab for the same reader later opens that article offline; Quiz or Citations dereferences `null` and shows an error ([useQuiz.ts:454](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/useQuiz.ts:454), [useCitations.ts:328](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/useBibliography.ts:328)). This is an established source path, not a hypothetical cache layer.  
   **Plan change:** simplest is to skip caching `null` for these three endpoints and remove the cached-null replay requirement. If offline negative caching matters, use a distinct request URL, such as a query parameter, so existing tabs use a separate cache entry. Making only the new client’s replay header-aware cannot repair already-running clients.

2. **F2 — P2: explicitly remeasure after content changes.**  
   Stage 2 specifies scroll and resize, but the pivot can change its columns while its viewport stays the same width. Changing `then by` updates the existing pivot ([AdminCostsPage.tsx:425](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/AdminCostsPage.tsx:425)); headers depend on `pivot.columns` ([AdminCostsPage.tsx:882](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/AdminCostsPage.tsx:882)). Window resize—or observing only the scroll box—does not cover every intrinsic-width change.  
   **Plan change:** require measurement on mount, scroll, viewport-size changes **and table-content-size changes**. Observe the viewport and inner table. Add a check that changing the grouping updates the cue without scrolling or resizing. Specify that the overlays paint above the sticky cells, which already have `z-10` ([AdminCostsPage.tsx:827](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/AdminCostsPage.tsx:827)).

3. **F3 — P2: the existing hidden-question explanation is conditional.**  
   The hidden-count sentence appears only inside `{listing && …}` ([QuizPanel.tsx:1418](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/QuizPanel.tsx:1418)), whereas “Question N of M” appears with the list collapsed ([QuizPanel.tsx:1235](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/QuizPanel.tsx:1235)). Reusing the existing line in its current position would leave the reported ambiguity.  
   **Plan change:** require the filter explanation whenever `hiddenCount > 0`, including with the list collapsed. Moving the existing explanation beside the count is enough; avoid a duplicate sentence.

4. **F4 — P2: specify the HTTP cache policy for the header variant.**  
   These handlers use `send`, which sets content type but no cache policy ([routes.ts:557](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/routes.ts:557)). The blanket `no-store` applies to the public namespace, not these owner endpoints ([routes.ts:7966](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/routes.ts:7966)). The plan leaves HTTP caches with a header-dependent response and no declared variation. I have not established a production CDN failure.  
   **Plan change:** make these responses `Cache-Control: private, no-store`, including the legacy missing-artefact response. That avoids needing `Vary` for HTTP storage. It does **not** fix F1: the application’s offline cache ignores that policy.

On the specific questions:

- **Old tabs:** the argument is correct for initial Quiz and Citations loads. `apiFetch` preserves caller headers, including on retry ([api.ts:546](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/lib/api.ts:546)); these are same-origin requests, so CORS is not the obstacle.
- **Cached null versus newer artefacts:** 404s are never saved ([api.ts:888](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/lib/api.ts:888)). An earlier null response cannot overwrite a later committed real response because ticket ordering rejects it ([offline-store.ts:538](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/lib/offline-store.ts:538)). Unseen server-side generation can leave a stale negative copy, as expected.
- **Other callers:** I found no additional production web callers of these three GETs. Visitors receive artefacts through the public payload. Preserve Quiz’s successful-response bridge and Citations’ enrichment; keep the typed-error catch narrow so enrichment failures remain failures.
- **Scroll cue:** a measured overlay is reasonable given opaque cells. `DataTable` has no existing cue. Prefer an opt-in prop that uses its actual internal scroll box ([DataTable.tsx:622](/var/tmp/spideryarn-worktrees/qi-none-yet-404-and-costs-scroll-cue/src/web/lib/DataTable.tsx:622)); an outside wrapper alone would measure the wrong element.
