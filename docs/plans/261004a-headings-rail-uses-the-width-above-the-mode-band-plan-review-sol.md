No P0 findings. The layout design is sound, but the planned tests and observer cleanup need tightening.

### Findings

- **P1 — The tests can pass without the feature being complete or wired into `Reader`.** The CSS test only finds the negative `margin-left` and selector; it never asserts the required `left` or `width` declarations ([tests/crumbs-narrow.test.ts:74](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/tests/crumbs-narrow.test.ts:74)), although all three are essential in the plan ([plan:83](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/docs/plans/261004a-headings-rail-uses-the-width-above-the-mode-band.md:83)). The observer tests call `watchBarStuck` directly ([tests/bar-stuck.test.ts:55](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/tests/bar-stuck.test.ts:55)); an exported but unused helper would pass them while the actual JSX still lacked a sentinel or effect ([Reader.tsx:3008](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/reader/Reader.tsx:3008)). Add assertions for the exact `left` and `width`, plus an integration/static test proving the sentinel is immediately before `.controls` and that the watcher starts and stops as crumbs appear and disappear. The tests are genuinely red now—six expected failures—but not yet sufficient evidence for the feature.

- **P2 — Cleanup must guard against an already queued observer callback.** The proposed contract says unmounting clears the attribute ([plan:69](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/docs/plans/261004a-headings-rail-uses-the-width-above-the-mode-band.md:69)), but the test checks only the state immediately after `disconnect()` ([tests/bar-stuck.test.ts:82](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/tests/bar-stuck.test.ts:82)). Per the [Intersection Observer processing model](https://www.w3.org/TR/intersection-observer/#dom-intersectionobserver-disconnect), `disconnect()` removes observation targets but does not itself clear `[[QueuedEntries]]`; `takeRecords()` is the operation that clears them. Use an `active`/`stopped` guard in the callback, optionally call `takeRecords()`, and extend the test to invoke the saved callback after teardown and require the attribute to stay absent.

- **P2 — Observe `showCrumbs`, not `showBar`.** The plan proposes the sentinel whenever `showBar` is true ([plan:69](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/docs/plans/261004a-headings-rail-uses-the-width-above-the-mode-band.md:69)), but `showBar` is true for every visitor because of the read-only chip ([Reader.tsx:570](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/reader/Reader.tsx:570)). The CSS deliberately acts only when `.crumbs` exists. Keying the sentinel and observer to `showCrumbs` is the smaller and exact design; it avoids charging all public readers for a signal nothing reads.

- **P2 — The planned “wide table” horizontal-scroll check is likely vacuous.** Article tables scroll inside themselves ([prose.css:785](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/styles/prose.css:785)), while current layout explicitly avoids page-level horizontal overflow ([layout.ts:691](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/layout.ts:691)). Scrolling an inner table does not exercise the sticky bar or sentinel. If horizontal pinning remains a required check, deliberately inject page-level overflow and move `window.scrollX`, then assert the bar’s viewport `left`.

The small-screen hint and masthead are ordinary flow content before the bar and have scrolled away by then; Outline’s content remains inside the band.

2. **CSS geometry:** correct. The premise in the question is slightly outdated: `.reader` has a numeric inline `minWidth`, not `min-width: max-content` ([Reader.tsx:2884](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/reader/Reader.tsx:2884)). The new width plus negative margin has the same outer flow requirement as today:

   `(--page-w - spine) + (-mode-w) = --page-w - spine - mode-w`.

   Thus it gains painted width without adding overflow. `--page-w` already excludes the classic scrollbar and both horizontal safe-area insets ([measure.ts:47](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/reader/measure.ts:47), [Reader.tsx:2898](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/reader/Reader.tsx:2898)). The proposed selector has specificity `(0,4,0)` and beats every relevant `.controls` rule; narrow-window CSS changes padding and overflow, not these three properties ([narrow-window.css:139](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/styles/narrow-window.css:139)).

3. **Stuck signal:** sound, subject to the teardown fix above. Zero-area targets and edge adjacency are explicitly handled by the Intersection Observer specification. Initial deep-link scrolls, late `showCrumbs`, and masthead reflow produce conservative or correcting observer entries. The accepted `--safe-top` delay is in the safe direction. A crumb bar cannot be hidden by `data-bars`, because the existing crumb guard restores both bar tokens ([shell.css:763](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/styles/shell.css:763)). There is no better existing signal: `watchBarVisibility` tracks direction rather than stickiness, and `stickyOffset` deliberately measures only vertical coverage.

4. **Measurements:** nothing behavioral depends on the bar’s x-coordinate or width. `scroll.ts` reads its height/bottom ([scroll.ts:128](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/scroll.ts:128)); `useColumnContext` reads article-row tops ([useColumnContext.ts:68](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/useColumnContext.ts:68)); Floating UI auto-updates crumb tooltips ([Tooltip.tsx:234](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/Tooltip.tsx:234)). `ViewportProbe` records the complete bar rectangle, so its diagnostics will intentionally show the new x/width ([ViewportProbe.tsx:323](/home/greg/code/spideryarn2/.claude/worktrees/fbft2cgg-headings-rail-full-width/src/web/ViewportProbe.tsx:323)).

5. **Simpler design:** no CSS-only alternative preserves both states cleanly on Safari. The worthwhile simplification is merely to scope the observer to `showCrumbs`; the attribute itself remains justified.
