1. **F1 — high — The two-query history read can return an answer and somebody else’s schedule.**  
   The plan adds a second history query to `latestForBatch` ([plan:101](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/docs/plans/261030c-quiz-keeps-right-or-wrong-and-spacing-adapts.md:101>)), after the existing latest-row query ([pg-quiz-attempts.ts:51](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/src/store/pg-quiz-attempts.ts:51>)). A concurrent attempt can land between them, yielding answer A with a schedule calculated from answer B. The post-insert history read for `record` has the same race ([plan:84](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/docs/plans/261030c-quiz-keeps-right-or-wrong-and-spacing-adapts.md:84>)).  
   **Recommendation:** replace the two `latestForBatch` selects with one ordered select of all batch attempts, then derive both latest rows and schedules from that one snapshot. For `record`, calculate the inserted attempt’s schedule from history explicitly bounded to its `(created_at, id)`, or serialize same-question writes. Add a deterministic concurrent-insert test.

2. **F2 — medium — An unjudged attempt can postpone a question for eight weeks.**  
   The plan drops null verdicts but dates the inherited schedule from the newest row regardless of verdict ([plan:65-73](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/docs/plans/261030c-quiz-keeps-right-or-wrong-and-spacing-adapts.md:65>)). After four rights, a failed check therefore resets the 56-day clock even though the latest answer might be wrong. That is more than “changes the schedule as little as possible” and conflicts with “longer each time you get it right.”  
   **Recommendation:** make a latest null use the neutral three-day interval from that attempt, without adding a rung. This is simpler and ensures only an actual stored `right` creates a long delay.

3. **F3 — medium — The chronological rule is internally reversed and lacks the store’s tie-breaker.**  
   History is declared newest-first, but an older row is to count when it is “at least a day after” the newest counted row ([plan:65-73](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/docs/plans/261030c-quiz-keeps-right-or-wrong-and-spacing-adapts.md:65>)); read literally, no older right can ever qualify. The history shape also omits `id`, although the existing latest-answer contract uses `(created_at DESC, id DESC)` to order equal timestamps ([pg-quiz-attempts.ts:63](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/src/store/pg-quiz-attempts.ts:63>)). Equal-time right/wrong rows could therefore select one answer but schedule from the other.  
   **Recommendation:** specify `lastCounted.answeredAt - older.answeredAt >= 24h`, include the attempt id in history, and use the identical total order everywhere. Test 24h−1ms, exactly 24h, future timestamps, and equal timestamps with opposite verdicts.

4. **F4 — medium — Terminal-frame backward compatibility is unspecified.**  
   `keptFromServer` gets a fallback for missing/invalid `recallAfterDays`, but `noteMark` merely “takes” the field from `done` ([plan:109-113](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/docs/plans/261030c-quiz-keeps-right-or-wrong-and-spacing-adapts.md:109>)). During a rolling deploy—or from an older mocked/offline server—the existing parser receives no such field ([useQuiz.ts:829-875](</var/tmp/spideryarn-worktrees/qiehnr2hsh-quiz-store-right-wrong/src/web/useQuiz.ts:829>)). If `undefined` reaches `quizLook`, the comparison can become false forever rather than falling back to three days.  
   **Recommendation:** normalize the `done` field through the same finite, bounded parser before calling `noteMark`; make the normalized internal field required. Test an old frame with no field and malformed values including `null`, `NaN`, fractions, zero, and excessive numbers.
