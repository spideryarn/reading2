Each build creates a fresh `builtAt` timestamp ([build-stamp.ts:81](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/scripts/build-stamp.ts:81)), which is compiled into both client JavaScript ([vite.config.ts:466](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/vite.config.ts:466)) and the API bundle ([vite.api.config.ts:169](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/vite.api.config.ts:169)). Also, most API dependencies are external ([vite.api.config.ts:27](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/vite.api.config.ts:27), [vite.api.config.ts:203](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/vite.api.config.ts:203)), so identical `api-dist/` bytes would not prove identical dependency behaviour. A deterministic, complete client artifact comparison could replace a browser smoke, but this comparison cannot. Keep the smoke check, or first provide a fixed build-time stamp and compare filenames plus bytes.

2. The npm command is correctly scoped today, but it is not exact or literally lockfile-only. All relevant parents admit the intended patches: `minimatch` permits `brace-expansion ^5.0.8` ([package-lock.json:9488](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/package-lock.json:9488)); Tailwind, PostCSS and css-tree permit `source-map-js ^1.2.1` ([package-lock.json:5604](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/package-lock.json:5604), [package-lock.json:7159](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/package-lock.json:7159), [package-lock.json:10156](/var/tmp/spideryarn-worktrees/deps-vulnerabilities/package-lock.json:10156)). `npm update` does not edit `package.json` by default, but without `--package-lock-only` it also updates `node_modules`; it also resolves the newest matching versions when run, rather than pinning 5.0.12/1.2.2. [npm documents both behaviours](https://docs.npmjs.com/cli/update.html/).

   Safer workflow:

   ```sh
   npm update --package-lock-only --ignore-scripts brace-expansion source-map-js
   # Assert exactly 5.0.12 and 1.2.2, and inspect that only their lock records moved.
   npm install --ignore-scripts
   ```

   The plan should make those version and diff assertions explicit before testing. `npm update package@version` is not available—the installed npm accepts package names only ([update.js:37](/usr/lib/node_modules/npm/lib/commands/update.js:37)).
