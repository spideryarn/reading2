1. **P1 — The hover-card privacy boundary is described incorrectly.** The plan says visitors cannot reach `CiteCard` because citations are owner-only ([plan:28](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/docs/plans/261001i-already-in-spideryarn-on-the-hover-card-archived-and-uploaded.md:28>)), but citations are a public artefact ([visitor.ts:327](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/web/visitor.ts:327>)) and the public DTO builds citation rows ([dto.ts:563](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/public/dto.ts:563>)). Today visitors miss prose citation cards only because `Reader` takes hover-card works exclusively from the owner response ([Reader.tsx:912](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/web/reader/Reader.tsx:912>)). The band already adds an explicit owner gate and tests malformed public data ([CitationsPanel.tsx:891](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/web/BibliographyPanel.tsx:891>), [citations-panel.test.tsx:1577](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/tests/bibliography-panel.test.tsx:1577>)). **Fix:** pass the same owner capability into `CiteCard` and gate `InSpideryarn` explicitly; retain the DTO omission as the server boundary. Correct the stale owner-only comments in `ProseHoverCard`, `Reader`, and `reader-capability.ts`.

2. **P2 — The archived-public explanation confuses listing with access.** The proposed exclusion is safe, but the reason is incomplete. `publicSlug` checks visibility only, so an archived public article still opens by direct link ([public-slug.ts:40](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/store/public-slug.ts:40>)); only the public listing filters `archived_at` ([public-library.ts:274](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/store/public-library.ts:274>)). Matching it would therefore make an intentionally unlisted article newly discoverable. **Fix:** state the policy as “the reader’s own openable articles, or currently listed public articles,” and preserve the exclusion test. The owner-direct-link assumption itself is correct.

3. **P2 — The plan’s SQL sketch has the wrong visible precedence.** As printed, `AND readable` binds only to the public arm, despite the comment saying it applies to both ([plan:40](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/docs/plans/261001i-already-in-spideryarn-on-the-hover-card-archived-and-uploaded.md:40>)). That would admit an unreadable owned article and produce a link that 404s. **Fix:** write it as `((owner_id = me) OR (visibility = 'public' AND archived_at IS NULL)) AND readable`, and keep both the generated-SQL assertion and the owned-unreadable fixture.

4. **P2 — `guessed-id` is ranked too weakly without a supporting confidence difference.** A canonical source guess has already passed exact title, author where available, and independent identifier/content checks before its DOI/arXiv URL is constructed ([source-guess.ts:105](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/source-guess.ts:105>)). Ranking it below a “real” identifier means a stranger’s public DOI copy beats the reader’s own live uploaded copy because match strength is compared before ownership ([cited-in-spideryarn.ts:190](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/cited-in-spideryarn.ts:190>)). Also, “before address” is effectively unreachable for well-formed works: `keysOf` produces a DOI/arXiv key or an address key, not both ([citations.ts:1150](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/bibliography.ts:1150>)). **Fix:** put DOI, arXiv, and guessed identifier in one identifier-strength tier, then apply live-own → archived-own → public. If public-real-over-own-guessed is deliberate, name that product decision and test that exact conflict.

5. **P2 — The client test plan is too vague for a privacy-bearing second surface.** A dedicated hover-card render suite already exists ([citation-hover-card.test.tsx:282](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/tests/citation-hover-card.test.tsx:282>)); “a render test if one exists” should therefore be definite. **Fix:** add tests there for an ordinary match, archived wording, guessed-ID tooltip, and a malformed visitor row carrying a private `inSpideryarn` attachment. Keep the existing band tests as separate proof that the shared component has not changed its wording.

6. **P3 — `kind='canonical'` does not itself guarantee an `identityOf`-parseable URL.** The schema constrains `canonical` to `matched_by IN ('doi','arxiv')` and requires HTTP(S), but does not constrain the host or path ([schema.ts:3964](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/db/schema.ts:3964>)). Current application code does construct `doi.org`/`arxiv.org` URLs, while `identityOf` accepts only those precise shapes ([cited-in-spideryarn.ts:84](</home/greg/code/spideryarn2/.claude/worktrees/fu-citations-already-in-spideryarn/src/cited-in-spideryarn.ts:84>)). This fails closed, so it is not a leak, but it is an unstated cross-module invariant. **Fix:** add a malformed canonical-row test proving it yields no match, plus DOI and arXiv integration cases; describe parsing—not `kind` alone—as the final validator.

Verdict: **Rework, then ship—all three changes are worthwhile and can be safe, but the hover-card boundary and identifier ranking need correction first.**
