## Findings

- **P1 — The single liveness read is not a lease; a peer can enter after it and have its live tree removed.** [scripts/worktree-remove.ts:667](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-remove.ts:667), [scripts/worktree-remove.ts:712](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-remove.ts:712). Concrete scenario: a clean, landed tree has a stale Claude lock. Removal reads it as idle. A peer then resumes the tree and is reading before its first edit. Removal does not re-read liveness or the lock; because the original entry was locked, it unlocks the now-live tree, repeats only the landed proof, and `git worktree remove` removes it despite the peer’s cwd being inside. The sweep has the non-destructive equivalent: a peer can resume an early row after its liveness snapshot but before rendering, so it is printed `REMOVABLE` while live ([scripts/worktree-sweep.ts:217](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-sweep.ts:217), [scripts/worktree-sweep.ts:284](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-sweep.ts:284)). **Reproduced:** not end-to-end; this sandbox denies the Git subprocesses required to interleave removal. The unchecked ordering is explicit in the code. A second late read would narrow this; the absolute claim requires an enter/remove exclusion shared with `EnterWorktree`.

- **P2 — “Initial PID namespace” does not prove unrestricted procfs, and an unreadable owner stat is still classified as dead.** [scripts/worktree-inuse.ts:191](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-inuse.ts:191), [scripts/worktree-inuse.ts:316](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-inuse.ts:316), [scripts/worktree-inuse.ts:538](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-inuse.ts:538), [scripts/worktree-inuse.ts:429](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/scripts/worktree-inuse.ts:429). `procTable.stat()` collapses every read error into `null`, which `ownerStanding()` calls “pid gone.” With host PID namespace plus `hidepid=invisible`/`ptraceable`, a live locked owner can therefore look stale; the cwd enumeration can omit it, or explicitly skip it as foreign-UID, and `liveness()` returns `idle`. Linux documents that these mount modes hide PID entries while leaving the caller in the initial namespace. [Kernel procfs documentation](https://cdn.kernel.org/doc/html/latest/filesystems/proc.html). **Reproduced:** yes at the adapter seam—injecting the real adapter’s `null`/empty-table result with an initial-namespace link made a live-owner-shaped lock return `idle`. Not reproduced with a real restricted mount. This box currently shows no `hidepid`, its installed Overseer/dashboard units run as `greg`, configured remote launches use `greg`, and this sandbox is UID 1000; I found no normal different-UID agent path here. The existing `kill(pid, 0)` distinction in [launch-artefacts.ts:508](/home/greg/code/spideryarn2/.claude/worktrees/worktree-floor-ns-review/tools/overseer/launch-artefacts.ts:508) is the appropriate precedent.

The PID-namespace fix itself is correct and closed for the reported namespace failure. Inside this sandbox, `readlink` returned `pid:[4026533427]`, and the requested real `liveness()` call returned `unknown` naming that private namespace. Without the gate, the same real `/proc` inputs composed to `idle`, so the integration test genuinely goes red if the gate is removed. Its weakened host control is acceptable because it isolates the gate while other tests cover idle behavior.

`4026531836` is the reserved initial PID-namespace inode (`0xEFFFFFFC`); dynamically allocated namespace inodes occupy a separate range, so a non-initial namespace cannot naturally collide. Comparing no device number is safe for this special reserved identity. [Linux `nsfs.h`](https://github.com/torvalds/linux/blob/master/include/uapi/linux/nsfs.h), [Linux proc inode allocator](https://github.com/torvalds/linux/blob/master/fs/proc/generic.c). Mismatched procfs/PID namespaces fail closed: `/proc/self` is resolved relative to the procfs instance’s PID namespace, so a host process invisible to a child-mounted procfs gets `ENOENT`; a private process visible through host procfs still exposes its private active namespace. [Linux `fs/proc/self.c`](https://code.googlesource.com/linux/torvalds/linux/+/111d0bda8eeb4b54e0c63897b071effbf9fd9251/fs/proc/self.c).
