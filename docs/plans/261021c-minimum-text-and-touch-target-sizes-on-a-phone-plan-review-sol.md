- **R1 — P1 — Stage 1 enlarges containers or one axis, not every actual target to 40 × 40.** The plan gives `.chat-thread-source` only 40px width, and `.chat-from-btn` only 40px height; “All” can therefore remain narrower than 40px. More importantly, making `.chat-sources li` 40px tall does not enlarge its clickable `<a>`, which currently remains a roughly 20px-tall flex item ([plan](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/plans/261021c-minimum-text-and-touch-target-sizes-on-a-phone.md:77), [mode-band.css](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/src/web/styles/mode-band.css:660), [mode-band.css](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/src/web/styles/mode-band.css:1243)). **Fix:** put `min-width` and `min-height: 40px` on each actual button, including `.chat-thread-source` and `.chat-from-btn`; make `.chat-sources li > a` an `inline-flex`/`flex` target with `min-height: 40px`. Keep the `<li>` sizing only for inter-row spacing.

- **R2 — P1 — A fixed 13px token prevents the reader’s text-size setting from enlarging the smallest text.** The plan says the larger root “still wins,” but `.block-ref` is `0.58rem`: even at Largest’s 22px root it is only 12.76px, so `max(13px, 0.58rem)` stays exactly 13px through every text-size setting. That conflicts with the documented promise that the setting makes everything bigger ([plan](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/plans/261021c-minimum-text-and-touch-target-sizes-on-a-phone.md:54), [prose.css](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/src/web/styles/prose.css:443), [typography.md](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/project/typography.md:209)). **Fix:** under the coarse-pointer query define `--text-min: max(13px, 0.8125rem)`. It remains at least 13px with a small browser root, but grows proportionally once the reader raises the root.

- **R3 — P2 — Tailwind declarations bypass both the token and the proposed guard.** Utilities outrank every stylesheet in `@layer app`, regardless of selector specificity, and the existing iOS-field rule explicitly documents that an app-layer floor cannot reach Tailwind-sized fields ([styles.css](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/src/web/styles.css:12), [narrow-window.css](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/src/web/styles/narrow-window.css:1096)). The plan nevertheless accepts leaving `tw:text-xs` invisible to the ratchet ([plan](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/plans/261021c-minimum-text-and-touch-target-sizes-on-a-phone.md:90)). That does not meet the request to prevent recurrence. **Fix:** scan TS/TSX for `tw:text-xs` and arbitrary sub-floor sizes, requiring either an exact reasoned allowlist entry or a coarse-pointer utility whose value uses `max(var(--text-min), …)`.

- **R4 — P2 — The proposed literal-count ratchet can report green over new undersized text.** Its `0.8125rem` threshold assumes a 16px root, yet the measured root in this very plan is 15.36px: `0.83rem` computes to 12.75px but would not be counted. The claim that `em` only over-reports is also false—a `0.9em` child of a 12px parent computes to 10.8px and is missed. Finally, deleting one old occurrence while adding a new one keeps the per-file count unchanged ([plan](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/plans/261021c-minimum-text-and-touch-target-sizes-on-a-phone.md:16), [plan](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/plans/261021c-minimum-text-and-touch-target-sizes-on-a-phone.md:90)). **Fix:** parse declarations, including `font` shorthands, and keep an exact selector/value/reason allowlist rather than counts. Back that static check with the planned computed-style sweep at both the normal and supported 12px root.

- **R5 — P2 — The universal 40 × 40 rule contradicts the existing deliberate passage-ID exception.** `.block-ref.tap-target` explicitly replaces the 40px halo with the link’s own width and a `1.3rem` height to prevent adjacent citation chips stealing each other’s taps ([plan](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/plans/261021c-minimum-text-and-touch-target-sizes-on-a-phone.md:35), [tap-target.css](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/src/web/styles/tap-target.css:48), [touch.md](/var/tmp/spideryarn-worktrees/fby4yhnp-iphone-minimum-sizes/docs/project/touch.md:508)). Raising the text to 13px does not break that arithmetic because the halo uses `max(100%, …)`, but the target remains far below 40 × 40. **Fix:** state passage-ID chips as an explicit exception in the rule and acceptance criteria; retaining their bounded halo is simpler and consistent with the measured overlap evidence.
