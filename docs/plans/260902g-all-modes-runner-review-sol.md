- **P1 — Interaction rounds are labelled cold/warm by position, not validated, yet the report calculates cache savings from them.**  
  [interactions.ts:459](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/evals/cost/interactions.ts:459) aggregates cache reads across all calls in a round. [interactions.ts:518](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/evals/cost/interactions.ts:518) merely prints an arrow when a warm round reads nothing, while [interactions.ts:693](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/evals/cost/interactions.ts:693) still reports “cache worth X×,” including failed or unpriced rounds. For chat, a later tool-loop call can read cache even when the first call was cold, so aggregate `cacheRead > 0` does not establish a warm turn. Chat may also invoke passage search before the standalone search task, making search round 1 warm while it remains labelled cold. The runner needs per-call earliest-call validation, cold-round rejection when any pre-existing cache is read, and no ratio when either round failed, is unpriced, or contradicted its expected cache state.

- **P1 — The claimed cold coverage excludes the two paths where implicit provider caching is actually possible.**  
  `checkFirstCallCold` exits for every non-mode draw at [report.ts:515](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/evals/cost/report.ts:515). Consequently PDF extraction has no cold-cache gate: it resends the same checked-in PDF bytes and prompt to OpenAI, whose caching is automatic. A rerun within the cache lifetime can therefore report discounted extraction as cold ingest. Dictation similarly reuses an identical committed clip and article vocabulary at [interactions.ts:348](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/evals/cost/interactions.ts:348), but calls Gemini and asserts that no explicit breakpoint means “nothing to warm.” Gemini supports implicit caching by default, so that assertion is false. [Google’s caching documentation](https://ai.google.dev/gemini-api/docs/caching) and [OpenRouter’s provider-specific caching documentation](https://openrouter.ai/docs/guides/best-practices/prompt-caching) both document these implicit paths. Both cold measurements need to reject a cache read rather than assume one cannot occur.

- **P1 — Interaction rows are eval-scoped, but attributed to the wrong owner and consequently lose their article link.**  
  [interactions.ts:739](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/evals/cost/interactions.ts:739) calls `withLedger` outside `runAsOwner`. `withLedger` explicitly sets the collector owner to `environmentOwnerId()` at [cli-ledger.ts:86](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/src/cli-ledger.ts:86), and explicit collector attribution wins over ambient ownership at [ai-spend.ts:1036](/home/greg/code/spideryarn2/.claude/worktrees/cost-all-modes/src/ai-spend.ts:1036). The persisted ledger evidence contradicts the run metadata and will be missed or misattributed by owner/article queries.
