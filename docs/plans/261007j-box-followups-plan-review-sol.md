1. **P1 — Live browser state is missing from the exclusions.** [Plan:37](/var/tmp/spideryarn-worktrees/box-followups-tmp-overseer-pngs/docs/plans/261007j-box-followups-tmp-age-overseer-unit-png-compression.md:37). Provisioning launches both MCP browsers with `--isolated`; the browser process fixture explicitly uses `/tmp/playwright_chromiumdev_profile-*`. Fresh files preserve their ancestors, **not old siblings**: an active profile can lose old preferences or Chromium’s `SingletonLock` symlink. Tmpfiles protects BSD-locked objects and recognized live sockets, not every open file or process-owned directory. Audit the host’s live temporary profiles and locks, then exclude or relocate them before enabling the timer or running the first sweep. The same-name override, mount-boundary checks and non-following of descendant symlinks are correct, but do not resolve this lifetime problem. Scope the manual run with `--prefix=/tmp` and monitor dashboard/heartbeat health during it; `nice` and `ionice` alone do not establish safety. [Tmpfiles implementation](https://raw.githubusercontent.com/systemd/systemd/v255/src/tmpfiles/tmpfiles.c), [Chromium singleton implementation](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/process_singleton_posix.cc).

2. **P1 — The cut-over can inspect the wrong store under sudo.** [overseer-activate.ts:291](/var/tmp/spideryarn-worktrees/box-followups-tmp-overseer-pngs/scripts/overseer-activate.ts:291). The script derives `storeDir` from `$HOME`, while substituting `User=greg` from `SUDO_USER`. Normal sudo policy sets HOME to root’s, so the documented command checks `/root/.overseer`, misses the tmux daemon’s lock, and starts systemd into a lock conflict. Resolve the store from the target user/unit or pass an explicit `OVERSEER_STORE_DIR` through sudo, and test that invocation. Also preview with `--disarm`: the current flagless dry run correctly reports the known missing arming file as a blocker. **`--apply --disarm` does create that missing file before stopping the holder**, once other preflight checks pass. [Sudo’s HOME behavior](https://github.com/sudo-project/sudo/blob/main/docs/TROUBLESHOOTING.md).

5. **P2 — Secret validation happens too late for malformed or empty values.** [Plan:105](/var/tmp/spideryarn-worktrees/box-followups-tmp-overseer-pngs/docs/plans/261007j-box-followups-tmp-age-overseer-unit-png-compression.md:105). 6. **P2 — Backoff does not reset after a healthy run.** [Plan:86](/var/tmp/spideryarn-worktrees/box-followups-tmp-overseer-pngs/docs/plans/261007j-box-followups-tmp-age-overseer-unit-png-compression.md:86). Systemd 255 maintains the restart counter across successful running periods; it resets after a full stop/start or `reset-failed`. After enough isolated failures, even a crash following days of healthy operation waits five minutes. Document and test that consequence. A simpler alternative is `StartLimitIntervalSec=0` with a fixed `RestartSec=30s` or `60s`: indefinite recovery, predictable downtime, and no cumulative backoff behavior. [Systemd 255 counter lifecycle](https://raw.githubusercontent.com/systemd/systemd/v255/src/core/service.c).

7. **P2 — The transient test needs a stable success condition and a startup-failure case.** [Plan:92](/var/tmp/spideryarn-worktrees/box-followups-tmp-overseer-pngs/docs/plans/261007j-box-followups-tmp-age-overseer-unit-png-compression.md:92). A command that writes one block and exits still restarts under `Restart=always`; briefly observing `active` does not prove recovery. 8. **P2 — The `tried` marker can outlive the image it certifies.** [Plan:135](/var/tmp/spideryarn-worktrees/box-followups-tmp-overseer-pngs/docs/plans/261007j-box-followups-tmp-age-overseer-unit-png-compression.md:135). A valid `tEXt` chunk is suitable storage, but editors can retain it while changing pixels, allowing a newly enlarged truecolor image to pass without another attempt. Bind the marker to the image data, or narrow the claim to an advisory convention. Metadata stripping can remove it; that should cause revalidation, not automatic acceptance. Explicitly distinguish pngquant’s expected skips—98 for size and 99 for quality—from genuine errors, which must not receive a marker. [PNG editor rules](https://www.w3.org/TR/png-3/#14Editors), [pngquant exit statuses](https://raw.githubusercontent.com/kornelski/pngquant/2.18.0/pngquant.1).

10. **P2 — A Vitest convention cannot guarantee that uncompressed bytes never enter history.** [Plan:141](/var/tmp/spideryarn-worktrees/box-followups-tmp-overseer-pngs/docs/plans/261007j-box-followups-tmp-age-overseer-unit-png-compression.md:141). Files can be created or changed after testing, and pathspec commits select their current working-tree contents. The temporary-index difficulty applies to **rewriting** hooks; a validation-only hook can inspect the commit index and reject offending PNGs without restaging anything. Either add that validation where hooks are installed, or describe Vitest as an advisory gate rather than a commit guarantee.
